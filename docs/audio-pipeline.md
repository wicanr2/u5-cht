## 1. 已經打通的部分(可重跑)

### 1.1 場景 → 曲號 → 檔名

原版把「播第幾首」寫在程式碼裡(32 個 `sub_3181C(n)` 呼叫點 + `sub_31DC0`
的地點跳表),**不在任何資料表裡** —— `U5_BGM.TBL` 只給檔名與六聲道音量。
完整推導與 32 個呼叫點見 `docs/re/87`。

引擎接了八個換曲點:進場景 7、離場地表 1 / **幽冥界 0x0A**、進地牢 9、
離開地牢 1、月門 1、開戰 3、勝利 0、上船 / 上小艇 2。

```
internal/game/music.go       曲號常數 + playSong + overworldSong
internal/u5data/bgm.go       U5_BGM.TBL + StartupSong(sub_31DC0)
internal/audio/audio.go      曲號 → 檔名 → 後端
```

⚠ 曲號 **0 是勝利那一首**,所以 `State.song` 刻意不匯出(零值陷阱,見 `docs/re/87` §7)。

### 1.2 兩條 CDDA

```bash
tools/cdda2ogg.sh            # 預設輸出 assets/audio/
```

CDDA 是紅皮書規格:44,100 Hz、16-bit、立體聲、LE、**176,400 byte/s**
⇒ 長度可以從位元組數算出來當驗收,不必猜:

| 音軌 | 位元組 | 算出來 | 轉出的 ogg |
|---|---|---|---|
| Track 2 | 31,752,000 | 180 s | ✅ 180 s |
| Track 3 | 65,444,400 | 371 s | ✅ 371 s |

腳本在除不盡 176,400 時會出聲警告(那表示不是純 CDDA 或抽檔抽錯),
並在轉完之後用 `ffprobe` 比長度,差超過 1 秒就失敗。

⬜ **誰在什麼時候播它們還沒追。** 但 `cdr_mtplay` / `cdr_rmtplay` 那組
CD-ROM 音軌 API **確實連進了執行檔**(`docs/re/89` §3a)⇒ 不是裝飾。

### 1.3 `.EUP` 的音序

事件流起點 = `"EUPHONY "` 簽章 + 16,每筆 6 byte:
`[status][step][gate u16][note][vel]`。

★★ **相位是用統計證明的**:一首正常的曲子裡 note-on 與 note-off 的筆數必須
相等(十五首都是 881/882 這種形狀)。相位錯的話 status 欄根本不是 status,
這個關係不可能成立。⚠ `../u1-cht` 的相位掃描判準**對 U5 會停在錯的地方**
(停在 `sig+0x40`)—— 同一個格式、同一個引擎,**相位判準不通用**。

其他確認:note-off 的音高欄一律 0(收「該聲道當前那一個」)、
事件流開頭就是**六個 program change**(對上 `U5_BGM.TBL` 的六欄音量)。

### 1.4 `.FMB` 的佈局

```
0x0000  8       檔頭
0x0008  48×128  +0x00 8 byte 名字(TRUMP1 / Horn / Tuba / FLUTE / OBOE / Piano…)
                +0x08 40 byte 參數 ⬜
```

8 + 128 × 48 = **6,152 = 檔案大小,整除無餘數**;而 `.EUP` 的 program change
值域落在 0..127 ⇒ **兩份獨立資料互相佐證**。

## 2. 為什麼不用自製合成器

`../u1-cht/tools/render_eup_music.py` 是**自製 2-op FM 近似**:它只用音序,
音色是自己寫的。當初那是唯一的路,因為不知道原版音色在哪。

**現在知道 `FM_BANK.FMB` 就在光碟上。** `CLAUDE.md §3.0` 的鐵則是
「素材全部從原版媒體抽取解碼,不自製」—— 明知有原版音色卻用自製的,
就是違反它。⇒ **這條路已排除。**

## 3. ★★ 硬結:那 40 byte 的語意在 `TBIOS.BIN` 裡

### 3.1 為什麼遊戲執行檔裡找不到

`sub_3453B` 把 `"FM_BANK.FMB"` 的 **far pointer**(offset + segment)寫進
`byte_726DC`,然後 `sub_34B1B` 做:

```asm
lgs  edi, fword ptr byte_726DC       ; 檔名指標
mov  ax, 110h ; mov fs, eax          ; 固定 selector 0x110
call large fword ptr fs:loc_1180     ; 遠端呼叫低位線性位址的入口表
```

那一族有 **28 個同形狀的 stub**(`AH` = 0..0x1B)。⇒ **遊戲遞出去的是檔名,
不是解析好的資料**;它從來沒有解釋過那 40 byte,也沒有把 tick 換算成時間。

### 3.2 那是誰?`TBIOS.BIN`

```
CONFIG.SYS:    DEVICE=TBIOS.SYS /TBIOS.BIN
AUTOEXEC.BAT:  CONTROL            (只是選單)
```

**沒有載入任何獨立的音源驅動** ⇒ selector 0x110 那張入口表是 Towns BIOS 裝的。
而遊戲裡那條 `EUPHONY DRIVER FOR TOWNES by Joe Mizuno 1989 Copyright (C)
FUJITSU LIMITED` 是**介面函式庫的 banner**(同時出現在 `WORRIORS.EXP` /
`WORRIORJ.EXP` / `U5OPEN.EXP` 三個檔案),不是驅動本體。

`TBIOS.BIN`(81,920 B,`V31L31`、`90/11/21towns`、Fujitsu 1989)裡:

| 特徵 | 次數 |
|---|---|
| `mov dx, 4D8h`(FM 音源埠) | 18 |
| `mov ah, 3Dh`(DOS 開檔) | 2 |
| 0x4D8 / 0x4DA / 0x4E0 的 LE 序列 | 23 / 8 / 11 |

**同時碰晶片又會開檔** —— 正是「收一個檔名、把 FMB 讀進來寫進 YM2612」該有的形狀。

### 3.3 三條路,由使用者決定

| # | 路線 | 成本 | 風險 |
|---|---|---|---|
| **1** | **逆 `TBIOS.BIN`**:找 `AH=15h/16h` 的分派 → 追到 FMB 解析與 tick 換算 | 16-bit BIOS 映像、**無 MZ 檔頭**(手動建 segment)、**無 Hex-Rays**(全程組語)⇒ 一個新的子專案。錨點是那 18 處 `mov dx, 4D8h`,往上追誰餵它資料 | 中:BIOS 沒符號,但 FM 暫存器寫入是很強的錨點 |
| **2** | 依**外部 EUPHONY / FMB 格式文件**實作,在程式碼與文件標明「佈局來自社群文件,未經一手驗證」 | 低 | ★★ 高:讀錯一個欄位就是音色不對,**而聽起來仍然像 FM 音樂** ⇒ 錯不會自己暴露(同 `docs/re/86` 的「安靜截斷」形狀)。`CLAUDE.md §3.0` 把社群文件排在最低優先序 |
| **3** | 換 oracle:找一份可信的 FM Towns EUP 播放實作或錄音,用「同一首渲染出來要對得上」驗收 | 中 | 需要一個可信對照來源;`rulebook/64` 的手法 |

⚠ **只有音色受影響。** 音序(音高、時長、聲道、選第幾號音色)已經全部解出來了
—— 路線 2 做出來的東西「音對、音色可能不對」,不是「整首錯」。

⚠ 也可以**先做能做的**:路線 2 當佔位、路線 1 慢慢挖,挖通了再換音色參數解讀
——`.EUP` 與 `.FMB` 的解碼層已經分離,換的只有渲染器那一支。
但**佔位不得進入交付**(`CLAUDE.md §3.0`),而且要在 README 誠實揭露。

## 4. 驗收條件(決定性,不是「跑得動」)

| # | 項目 | 驗收 |
|---|---|---|
| A1 | CDDA 轉檔 | ✅ 兩軌長度與位元組數算出來的秒數差 ≤ 1 s(腳本內建) |
| A2 | `.EUP` 音序 | ✅ 十五首 note-on / note-off 差 ≤ 1;program change 全部 < 128 |
| A3 | `.FMB` 佈局 | ✅ 8 + 128 × 48 整除;`TRUMP1` / `FLUTE` / `OBOE` 讀得出來 |
| A4 | 渲染器 | ⬜ 十五首都渲染成 ogg;**每一首的長度要能從 tick 數推算並相符** |
| A5 | 音色正確性 | ⬜ 依 §3.3 選的路線而定;走路線 1 才有一手證據 |
| A6 | 引擎換曲 | ⬜ 進城 / 開戰 / 上船 / 進地牢各切一次,曲號與檔案都對(曲號部分已有單元測試) |
| A7 | 不崩 | ⬜ 熱鍵切主題、快速進出場景不掉音、不卡住(u1-cht 踩過) |

⚠ A4 的「長度要能推算並相符」是刻意的:**不要用「聽起來對」當驗收** ——
tick 換算錯 20% 也還是「聽起來像」。

```bash
# 兩條 CDDA → ogg(需要 org_game/fmtown/ 的光碟壓縮檔)
tools/cdda2ogg.sh

./tools/dev.sh go test ./internal/audio/ -v

# 遊戲(-audio 指向渲染好的 ogg;缺幾首會在啟動時印出來)
./build/u5cht -audio assets/audio
```
