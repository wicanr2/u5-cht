## 一、`IBM.HCS` / `RUNES.HCS` 是 16×12 的字型

各 3,072 B = 128 glyph × 24 B。24 B 有兩種切法都整除,**但只有一種看得出字**:

```
8 × 24  的 glyph 65        16 × 12 的 glyph 65
........                   ................
.....###                   .....########...
#####...                   ....###...###...
....###.                   ...###....###...
..###...                   ...##########...
...###..                   ...###....###...
..###...                   ...###....###...
...#####                   ..###.....###...
#####...                   .###......####..
...(一團斜線)               ................
```

**16×12。** 整張表(0x20..0x7F)畫出來是完整的 ASCII:空白、標點、數字、
大小寫字母,最後幾格是畫框用的圖形字元 —— 與 `IBM.CH`(8×8)同樣**索引 = ASCII 碼**。

幾何上也說得通:Hercules 是 720×348,720 / 16 = 45 欄、348 / 12 = 29 列。
相對於 DOS 的 8×8 @ 320×200,是**橫向 2 倍、縱向 1.5 倍**。

⚠ `RUNES.HCS` 有 14 格是空的:`! # $ % & ( ) < = > ?` 與 **`x y z`** ——
不列顛符文表沒有那幾個。那是資料本身,不是解析錯誤,測試要放行。

## 二、`HER.DRV` 裡的三張表

`HER.DRV` **沒有任何 `int 10h`** —— Hercules 不在 BIOS 支援範圍內。
需要的東西全部在檔案裡,而且都不是猜的:

| 位移 | 長度 | 內容 | 是什麼 |
|---|---:|---|---|
| 0x070C | 12 B | `35 2D 2E 07 5B 02 57 57 02 03 00 00` | **標準 Hercules 圖形模式的 6845 參數表**,一個位元組都不差 |
| 0x071A | | `mov al,1 / mov dx,3BFh / out dx,al` | 設定暫存器:允許圖形模式 |
| 0x0734 | | `mov dx,3B8h / out dx,al` | 模式暫存器 |
| **0x0318** | **4 B** | **`00 55 AA FF`** | ★ 色號 → 位元圖樣 |
| 0x031C | 16 B | `00 03 0C 0F 30 33 3C 3F C0 C3 CC CF F0 F3 FC FF` | 每個 bit 複製成兩個 = **橫向 2 倍** |
| 0x032C | 8 B | `80 40 20 10 08 04 02 01` | 單一位元遮罩 |

0x031C 那張表值得看一眼:`0001`→`00000011`、`0010`→`00001100`、`1111`→`11111111`
—— 就是「四個像素變八個」。與字型 16 寬(而 DOS 是 8)是同一件事的兩個出口。

### ★ 用到圖樣表的地方(0x1296 附近)

```asm
        and     dx, 0303h        ; ★ DL 與 DH 各取**低 2 bit**
        mov     bx, 0318h
        mov     al, dl / xlat    ; al = 圖樣表[dl]
        mov     cs:[130E], al
        mov     al, dh / xlat    ; al = 圖樣表[dh]
        mov     cs:[130F], al
        …
        mov     ax, 0B000h       ; ← Hercules 的顯示記憶體區段
```

`and dx, 0303h` 是關鍵:**索引只有 2 bit**。所以 Hercules 吃的是
**2bpp 的素材(`.4`)**,不是十六色的 `.16` ——
「Hercules 沒有自己的 tileset,那它畫什麼」這個問題到此結案:**它畫 CGA 那一份**。

而 `0xB000` 是 Hercules 的顯示記憶體區段,確認這條路徑通到畫面。

### 四個圖樣的語意

```
色號 0 → 0x00  全暗
色號 1 → 0x55  隔一點亮(50%,相位 A)
色號 2 → 0xAA  隔一點亮(50%,相位 B)
色號 3 → 0xFF  全亮
```

中間兩色都是 50% 灰但**相位相反** —— 所以色號 1 與 2 的區域相鄰時分得出來。
而且**四筆就是全部**:若原版還要依列號交替相位,表就得有八筆。

## 三、落地與誠實的界線

`LoadTileSetFor(dir, DisplayHercules)` 讀 `TILES.4`,每個像素取
「圖樣在該 x 位置的那個 bit」,亮的給色號 15、暗的給 0 —— 算繪層因此不必為單色
另開一條路。畫出來的圖山脈、樹、城堡、桌椅、船、墓碑、十字架都認得出來。

⚠ **還沒追完的**:16×16 的 tile 到 Hercules 畫面上那一格的**完整 blit 迴圈**
(位元加倍表怎麼與圖樣表配合、縱向 1.5 倍怎麼放)。所以現在產出的是 **1× 的
16×16 單色圖**,那正是圖樣表自己說的規則,不多加任何未經證實的縮放假設。

⇒ 這**不是逐像素重現原版的 Hercules 畫面**。`u5cht -display Hercules` 會在啟動時
印一句話說明(`CLAUDE.md` §3.0:缺的部分要明說,不要讓玩家以為是完整的)。
