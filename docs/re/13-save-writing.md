# 存檔寫回

> 輸入檔:`WORRIORS.EXP`(FM Towns)、`SAVED.GAM` / `INIT.GAM` / `SAVED.OOL`
> 日期:2026-08-07

寫入函式 `sub_284CC` 與讀取 `sub_27D24` **逐欄位對稱** —— 同樣的順序、
同樣的大小、同樣的一串全域變數。逐一比對過前十四個欄位:

```
byte_3DDB0(2)  byte_3DDB4(512 名冊)  word_3DFB4  word_3DFB6
byte_3DFC4(4)  byte_3DFD0(48 裝備)   byte_3E000(48)
byte_3E030(8)  byte_3E038(8)  byte_3E040(8)  byte_3E048(8)
byte_3E050(8)  byte_3E058(8)  byte_3E060(8 藥草)  …
```

⇒ **讀得回來就寫得出去,不需要另一套位移表。**

---

## 1. 以讀進來的那份當底稿

引擎目前只解出存檔的一部分欄位(名冊、背包、時間、位置、業報…);
魔法、任務旗標、地牢狀態、`byte_3E000` 那 48 B 都還沒解。

所以 `Encode()` 的作法是**複製讀進來的 4,192 B,只覆蓋已解出來的欄位**。
沒解的區段原樣保留。

這不是偷懶,是必要:把未解欄位清成 0 的存檔,拿回原版 DOS 版會壞掉。
`ExportSave` 因此**拒絕在沒有底稿時存檔**,而不是生一份半殘的檔。

### 驗收:逐位元組相同

`TestSaveRoundTripIsByteIdentical` 讀 `INIT.GAM` 與 `SAVED.GAM`,
`Encode()` 之後與原檔逐位元組比對。只要有任何一個欄位寫錯位置、
或哪個區段被清掉,這裡就會指出第一個不同的位元組在哪。

通過它就代表:**寫出去的檔拿回原版也讀得起來**。

---

## 2. 物件表另存一份

`SAVED.OOL` 是 512 B =「地表 256 + 地下 256」(見 `docs/re/11 §2`)。
玩家買的馬、放下的船都在裡面,所以存檔要兩個檔一起寫。

⚠ 船的耐久與小艇數藏在槽的 +5 / +7,只存在 `Raw` 裡 ——
序列化時要先 `copy(rec, o.Raw[:])` 再蓋結構化欄位,順序反了就會掉。

---

## 3. 存到哪

**[HARD] 絕不寫進 cwd。** 一律 `os.UserConfigDir()/u5cht/`:

- u1-cht 踩過:遊戲裝在唯讀目錄時存不進去。
- 玩家的原版資料目錄不該被引擎污染 —— `gamedata/SAVED.GAM` 是他的東西。

寫入用「先寫 `.tmp` 再 `rename`」:中途失敗不會留下半份壞檔把舊進度蓋掉。

讀檔的優先序:`-save` 指定的 → 設定目錄的進度 → `gamedata/SAVED.GAM` →
`gamedata/INIT.GAM`。存過一次之後就讀自己的進度,原版存檔留著不動。

---

## 4. 按鍵

原版的 `Q` 是「存檔並離開」。這裡拆成兩個,照
`esc-cancel-f10-quit-autosave` 的慣例:

| 鍵 | 行為 |
|---|---|
| `Q` | 存檔,不離開 |
| `F10` / `Ctrl+Q` | **自動存檔**後離開 |
| `ESC` | 永遠是取消(退出對話、離開商店),不是離開遊戲 |

按錯鍵不該丟進度。
