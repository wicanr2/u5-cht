## 1. `sub_0` 不是主迴圈,是三個主迴圈之間的切換器

```asm
loc_DF:                                  ; ← 外層
    edi = 0
    if (byte_3E0A3 == 0) {               ; 地點 0 = 大地圖
        ebx = 1
        call sub_2DD44                   ; ★ 大地圖主迴圈,一路跑到離開大地圖
        edi = ebx                        ; ebx 帶回「要不要結束遊戲」
    }
loc_F9:
    al = byte_3E0A3
    if (al == 0)     goto loc_1BE        ; 還在大地圖 ⇒ 只可能是要結束
    if (al >= 0x21)  goto loc_12D        ; 地牢
    call sub_1678(…)                     ; 1..0x20 = 場景
    call sub_1A54                        ; ★ 場景主迴圈
    goto loc_142
loc_12D:
    call sub_2CB3C(2)
    call sub_5378(edi)                   ; ★ 地牢主迴圈
loc_142:
    重載 BRIT.DAT(必要時再載 UNDER.DAT)  ; 從場景 / 地牢回來
loc_1BE:
    if (edi == 0) goto loc_DF            ; 回外層
    收尾離開
```

**三支都是「一路跑到玩家離開這個模式才回來」的完整迴圈**,不是每回合被叫一次的
處理函式。`sub_0` 只負責在它們之間切換、順便重載地圖。

⇒ **同一個回合絕不可能同時走兩支。**

## 2. 每個模式自己算一回合(表)

| 模式 | 主迴圈 | 一回合幾分鐘 | 地形效果 | 維生開銷 `sub_2A50C` |
|---|---|---|---|---|
| 大地圖 | `sub_2DD44` → `sub_2D9D0` | **2**(`sub_29304(2)`) | `sub_2D9D0` 自己那一串 | `loc_2DCC5` |
| 場景 | `sub_1A54` → `sub_1318` | 1 | `sub_1318` | `sub_1318` 尾巴 |
| 地牢 | `sub_5378` → `sub_5150` | 1(An Tym 停、Rel Tym 隔次) | `sub_5150` | `sub_5150` 尾巴 |
| 睡床 | `sub_16BA0`(H 指令) | 10 | — | 尾段額外一次 |
| 戰鬥 | 另一套(`docs/re/16`) | 每 10 個單位 1 分 | — | **沒有** |

`sub_2A50C` 全檔四個呼叫者(`sub_1318` / `sub_2D9D0` / `sub_5150` / `sub_16BA0`),
**一個模式一個**,外加睡床。⇒ **中毒每回合掉 1 血,沒有雙倍。⬜ 結案。**

⚠ 附帶結論:**戰鬥中不算維生開銷** —— 中毒不會在戰鬥裡持續扣血,
存糧也不會在戰鬥裡消耗。四個呼叫點沒有一個在戰鬥迴圈裡。

## 3. ★★ 因此 `docs/re/74` §1 是錯的

那份寫著:

> ⇒ **踏進沼澤的那一步會被擲兩次**(先移動後的分派,同一回合再地形效果),
> 之後每站一回合擲一次。**「走進去」比「站著」危險一倍。**

**不成立。** 兩支的呼叫者是互斥的兩個迴圈:

| 出處 | 唯一呼叫者 | 骰子 | 何時擲 |
|---|---|---|---|
| `sub_10BDC` | `sub_2D9D0` | random(1, 30) | **大地圖**的每一回合 |
| `sub_1318` 內段 | `sub_1A54` | random(0, 29) | **場景裡**的每一回合 |

⇒ 正確的說法是「**大地圖的沼澤與場景裡的沼澤用不同的骰子**」,
而不是「走進去擲兩次」。**同一回合只擲一次。**

### 為什麼會寫錯

`docs/re/74` 當時查了「誰呼叫 `sub_10BDC`」(答案:`sub_2D9D0`),
也查了「誰呼叫 `sub_1318`」(答案:`sub_1A54`),但**沒有再往上一層問
「`sub_2D9D0` 與 `sub_1A54` 會不會在同一回合都跑」**。
兩個呼叫者不同 ≠ 兩條路都會走到。

⇒ 這是 `rulebook/62` 的溯源要多爬一層:**問到「呼叫者」還不夠,
要問到「兩個呼叫者的共同祖先怎麼分派」。**

### 那個一格之差還是要保留

`docs/re/74` 對「不能統一成一顆骰子」的判斷仍然成立(敏捷 29 在場景裡免疫、
在大地圖有 1/30 會中)。差別只是它區分的是**地點**而不是**時機**。
`CLAUDE.md` §3.0:不自行平衡,兩顆照原樣留著。

## 4. ★ `docs/re/38` §4 的順序也寫錯了

那份寫著:

> 呼叫點在 `moveInWorld`:`tick()` 之後、月門之前 —— 原版 `sub_2D174` 就是這個順序。

`sub_2D174`(移動 + 地形代價)在 `sub_2D9D0` 的 **line 79899** 被呼叫,
而每回合的收尾(`sub_29304(2)` 起)在 **line 80013** 的 `loc_2DBF4`。
指令分派(`sub_2ACF4`)在中間的 `loc_2DBAF`。

⇒ 原版的順序是 **移動 + 地形代價 → 才是每回合的收尾**,
也就是**地形代價在前**。引擎目前是 `tick()` 先、`payTerrainCost()` 後,**反了**。

## 5. 由此浮出來的缺口(未實作,逐條有位址)

⬜ **大地圖每回合 2 分鐘。** `sub_2D9D0` 的 `sub_29304(2)`;引擎的
`MinutesPerTurn` 是 1 且全模式共用 ⇒ 大地圖的時鐘走一半速度。

⬜ **每個大地圖回合都跑一個世界回合。** `loc_2DD2F: call sub_2E24` 是**無條件**的。
引擎的 `extraWorldTurn()` 只從 `payTerrainCost` 呼叫(地形 1/2 級),
所以**在草地上走路,野怪不會動、也不會擲遭遇** —— 而草地是最常見的地形。
地形代價的 1/2 個回合是**額外加**的(`docs/re/38` 的「山裡走一步怪走三步」
= 1 個基本 + 2 個額外)。

⬜ **幽冥界地震**(`sub_2D998`):`byte_3E0A5 != 0` 且 `random(0,255) == 0x69`
→ 印 `EARTHQUAKE!` + `sub_2AC08`(震動畫面)+ `sub_2A4D0`(全隊 random(1,8) 傷)。
每個大地圖回合擲一次。引擎完全沒有。

⬜ **`(0xE9, 0xEB)` 的「Pass, Seeker!」關卡**(`sub_2D9D0` `loc_2DC5F`):
地表大地圖上那一格,`byte_3E0DC`(進行中的聖壇試煉,引擎的 `ShrineQuestActive`)
非 0 → 印 `Pass, Seeker!`;為 0 → 印 `Thou art not upon a Sacred Quest!` +
`Passage denied!` 並 **`inc byte_3E0A7`**(把玩家往南推回一格)。引擎沒有。

⬜ **大地圖沒有「自己醒過來」。** `random(0,15)==15` 把 `'S'` 寫回 `'G'` 的那段
只在 `sub_1318`(場景)裡。**全檔掃過**:寫 `'G'` 進名冊的位置有 22 處、
`random(0,15)` 後比 `0Fh` 的只有 1 處(`sub_1318`)⇒ 睡著的隊員在大地圖上
不會自己醒。引擎的 `terrainEffects()` 在所有模式都跑,所以醒得比原版容易。

⬜ **`tile == 0x8F`(熔岩)在大地圖走 `sub_10BC4`**:印 `Burning!` + `sub_2A4D0`。
與場景的 `sub_1318` 分支同效果,但是另一支函式。

⬜ **空白鍵(Pass)沒有走每回合收尾。** 原版 case 32 回到 `sub_2D9D0` /
`sub_1A54` 的收尾,所以按空白鍵一樣會結算地形、維生開銷、世界回合。
引擎的 `Pass()` 自己 `AdvanceTime` + `extraWorldTurn()`,**跳過了地形與維生開銷**。

⬜ `sub_2B740(n)`(沼澤中毒後呼叫)= `if (byte_3E0B4 != 0) 重畫 n 次`。
純視覺,引擎沒有阻塞動畫層。
