# 58 — 施法與調藥的輸入法:打符文首字母

| | |
|---|---|
| 輸入檔 | `U5_E/WORRIORS.EXP`(FM Towns,SHA-256 見 `docs/re/00-hexrays-p3-verified.md`) |
| | `DATA.OVL`(DOS,48,464 B) |
| 位址 | `sub_1CA0C`(讀符文 → 咒語索引)、`sub_1994C`(施法)、`sub_18704`(調藥) |
| | `sub_18468`(藥草勾選)、`sub_18698`(問份數) |
| | 指標表 `0x40D54` 26 個符文詞 → `0x40DBC` 48 個咒語代碼(相鄰) |
| 資料位移 | `DATA.OVL` `0x0941` 24 個符文詞、`0x09A5` 48 個咒語代碼 |
| 落地 | `internal/u5data/runeinput.go`、`internal/game/magic.go`、`internal/game/picker.go` |

`WORKLIST` 上兩條並排的 ⬜ 其實是同一題:

```
法術代碼表  DATA.OVL 0x09B3:98 項縮寫(AY AS ACX HR IW KX IMX LV FV…)  ⬜ 對應關係待解
施法流程    CAST.OVL 8,560 + CAST2.OVL 4,544                          ⬜
```

## 那 48 個縮寫是什麼

先更正兩處記載錯誤:表的起點是 **`0x09A5` 不是 `0x09B3`**,筆數是 **48 不是 98**。
`0x09B3` 剛好落在第 6 筆(`AY`)上,而「98 項」是把後面接著的地名一起數進去了。

從 `0x09A5` 起 48 筆,接著就是 `MOONGLOW BRITAIN JHELOM…`:

```
IL GP AZ AN M AY AS ACX HR IW KX IMX LV FV FGI GIN GIZ IP AG IS GIS PU DP QW
BIX AEP EIP MV IZ RT IPVY AQW AI AWY AEX BRX LS CX IQX IQW HIN CIQ CIM CKX
CGIV FHI PRV AT
```

每一筆是**咒語名各詞首字母、排序後**的樣子。抽樣看不出來 —— `IL` = `In Lor` 只是巧合般地
同序;要抽到這幾筆才看得出有排序:

| 咒語 | 首字母原序 | 表上 |
|---|---|---|
| `Rel Hur` | R,H | **HR** |
| `Vas Lor` | V,L | **LV** |
| `Vas Flam` | V,F | **FV** |
| `An Xen Cor` | A,X,C | **ACX** |
| `In Vas Por Ylem` | I,V,P,Y | **IPVY** |

48 筆逐一驗過,0 筆例外(`TestSpellCodesAreSortedInitials`)。逐筆比對比抽樣強太多:
抽三筆很可能全抽到同序的那幾個,然後得出「這只是縮寫」的錯結論。

## 所以原版根本不是讓你打咒語名

`sub_1CA0C` 是施法與調藥**共用**的輸入常式(`sub_1994C+5C` 與 `sub_18704+3E` 兩處呼叫):

```
1. 讀一個鍵
   'J' / 'O'              → 默默丟掉,跳回讀鍵        ← 見下一節
   'A'..'Z' 且已收 < 4 個  → 收下,並把**整個符文詞**回顯出來
                             (dword_40C50[字母*4],詞後補一個空白,
                              累計超過 13 欄先換行)
   Backspace              → 退一個字母,把那個詞從畫面擦掉
   Enter(0x0D)/ 空白       → 送出
   ESC(0x1B)              → 字母數歸零後送出(所以它與空輸入同一條路)
2. 氣泡排序把字母排成遞增
3. 逐一比對 48 個代碼;比對時**連續重複的輸入字母只吃掉表上一個字元**
   (排序後重複必相鄰 → 打 AA 等於打 A)
4. 一個字母都沒打 → −1;打了但湊不出來 → −2;湊出來 → 咒語索引
```

打 `I` 畫面上長出 `IN`,再打 `L` 變成 `IN LOR`,按 Enter 才查表。
**引擎原本讓玩家把 `In Lor` 整串打進去 —— 那是我自己設計的輸入法,不是原版的。**
`CastByName` 已移除,免得兩種模型並存。

### J 與 O 被丟掉是因為沒有符文詞以它們開頭

24 個符文詞 `AN BET CORP DES EX FLAM GRAV HUR IN KAL LOR MANI NOX POR QUAS
REL SANCT TYM UUS VAS WIS XEN YLEM ZU` 的首字母正好是 **A–Z 去掉 J 與 O**。
`dword_40C50[字母*4]` 是以 ASCII 碼直接索引的指標表,J / O 那兩格沒有字串 ——
所以原版在收鍵時就先擋掉,而且**不印任何訊息**。

指標表的排列本身是佐證:`0x40D54` 起 26 個 × 4 B 剛好到 `0x40DBB`,
而 48 個咒語代碼的指標表就從 **`0x40DBC`** 開始。兩張表緊貼著,不是巧合。

## 施法的流程(`sub_1994C`)

```
選施法者(sub_E19C)         → 取消就結束
"Spell name:\n:" → sub_1CA0C
  −1 → "None!"      −2 → "No effect!"
圈數 = 索引 / 6 + 1
地點分派:
  地點 == 0        → 測場合位元 8(野外)
  地點 > 0x7F      → 測位元 1(戰鬥)
  地點 == 0x12 且**還沒拿到王冠** → "Absorbed!"      ★
  地點 == 0x1D                    → "Absorbed!"      ★
  地點 < 0x21      → 測位元 4(城鎮)
  否則              → 測位元 2(地牢)
測不過 → "Not here!"
份數 == 0 → "None mixed!"
份數 −1                                ← 之後失敗都不退
魔力 < 圈數 → "M.P. too low!)"
魔力 −= 圈數
等級 < 圈數 → 失敗
跑效果 → "Success!" / "Failed!"
```

★ 那兩個地點就是**王冠與權杖的所在**(`docs/re/57`):`0x12` = 18 = 第二座城堡,
`0x1D` = 29 = `STONEGATE`。城堡在你拿到王冠之前壓制魔法,`STONEGATE` 永遠壓制。
兩個號碼分別由「信物擺在哪一槽」獨立佐證 —— 兩條線索在同一對數字上會合。

⚠ 這一關在場合檢查與「有沒有調配」**之前**,所以在這兩處施法**不扣份數也不扣魔力**。
順序寫錯的話玩家會白白損失藥草。

## 調藥的流程(`sub_18704`)

```
八種藥草加總 == 0 → "No reagents owned!"
"For what spell?\n:" → sub_1CA0C
  ⚠ 只擋 −1(`inc eax; jnz`)—— **−2 照樣往下走**
畫方向鍵提示 + " to move,\nRETURN selects.\nType M to m…"
sub_18468 → 勾選遮罩;−1(ESC)→ 結束
sub_18698(遮罩) → 份數
  "How much? " 讀**兩位數**;0 → 結束
  任一勾選的藥草不足 → "Insufficient reagents!" → **重問份數**(不是取消)
遮罩 == 0 → "\nNothing to mix!"        ← ⚠ 在問完份數**之後**才檢查
"Mixing...\n"
逐位元扣藥草:byte_3E060[i] -= 份數
若 咒語索引 >= 0 且 byte_40EAC[索引] == 遮罩 → "\nDone!\n",份數加上去(上限 99)
否則 → 換行 + 失敗效果
```

三個容易寫錯的地方:

1. **符文湊不出咒語不會中止。** 原版只擋 −1。亂打符文照樣進得了藥草畫面、照樣扣藥草,
   只是永遠調不出東西。引擎原本 `Mix` 開頭就 `if spell < 0 { return false }`,
   那會把藥草還給玩家 —— 已改。
2. **「沒東西可調!」在問完份數之後。** 一味都沒勾就按 M,原版還是先問「要幾份?」。
3. **藥草不足是重問份數,不是取消。** `sub_18698` 裡 `var_4 = 0` 之後跳回 `loc_1869F`
   ——「How much? 」那一行。

### `sub_18468` 的藥草畫面

只列**身上有的**藥草(`byte_3E060[i] != 0`),每列印:游標記號(0xFD)、
兩位數的擁有量、勾記(0x0F)、藥草名(`off_40A6C[i]`)。按鍵:

| 鍵 | 作用 |
|---|---|
| 四個方向鍵(碼 1/3 → 上,2/4 → 下) | 移動游標,**不繞回**(到頂 / 到底就不動) |
| 空白 或 Enter(碼 13) | 勾 / 取消勾游標那一項 |
| `M` | 確定,把遮罩交回去 |
| ESC | 遮罩設成 −1 → 呼叫端結束 |

⚠ 四個方向鍵各走哪一邊(1..4 分別是哪個箭頭)沒有辦法從組語判定 ——
**能確定的是四個都能移動、兩上兩下**。引擎把上 / 左當上、下 / 右當下,
這一條記在這裡以免日後被當成已證實的細節。

## 這次改了什麼

| 之前 | 現在 |
|---|---|
| 施法:打 `In Lor` 整串 | 打 `I` `L` 兩個字母,回顯 `IN LOR` |
| 取消施法印「作罷。」 | 印「無!」(原版 ESC 與空輸入同一條路) |
| 湊不出咒語印「無此咒語!」 | 印「毫無效果!」(與空輸入分成兩句) |
| 調藥:咒語選單 + 照配方自動調 | 符文輸入 → 藥草複選 → 兩位數份數 |
| 「不能在這裡施法」只有場合檢查 | 多了兩個地點的「被吸收了!」 |
| `Mix(spell<0)` 直接 return | 照扣藥草再失敗 |

被拿掉的東西:`CastByName`(錯的輸入模型)、`MixByRecipe` 的選單入口、
`canMixOnce`(只有那張選單用得到)、`MsgPickSpell`。

一條測試也跟著改:`TestMixMenuOnlyListsWhatCanBeMixed` 原本在驗
「選單只列調得出來的咒語」—— 而那張選單是我自己加的,原版沒有。
**它每次都綠,因為它量的是我自己的發明。** 改成釘住原版的第一步是符文輸入。

`realState`(測試用的真資料狀態)之前沒載咒語表,於是所有碰到施法 / 調藥的
測試都靜靜 `t.Skip`。一直跳過的測試等於沒有測試 —— 一併補上。

## 還沒解的

`CAST.OVL`(8,560 B)與 `CAST2.OVL`(4,544 B)是 DOS 版的施法 overlay。
FM Towns 是 flat 32-bit,沒有這兩個檔,所以上面的流程是從 `WORRIORS.EXP` 逆出來的。
兩者的資料檔相同(`docs/re/00`),流程應當一致,但**沒有逐位元組對照過** ——
如果哪天發現 DOS 版行為不同,先懷疑這一點。
