# 一對座標、一個取格函式 —— 為什麼那九個指令不需要「戰場版」

輸入檔:`WORRIORS.EXP`(FM Towns 英文版)
IDA 位址:`sub_DB10`(取格)、`sub_A360` 開頭(座標借用)、`sub_2E364`(存還)、
`sub_16058`(戰鬥中的 Klimb)、`sub_15E20`(離場)
日期:2026-08-08

---

## 0. 上一輪我下錯的判斷

`docs/re/51` §4 寫著:

> ⬜ 可用的 G/J/K/O/P/R/S/U/Z 在引擎裡的實作是**地圖版**的:它們讀世界 /
> 場景座標,不是戰場座標。接上去會作用在錯的地圖上,所以先不接。

「先不接」那個判斷是對的(硬接確實會壞),但**「需要另寫戰場版」是錯的**。
原版沒有戰場版 —— 它用的是同一份程式。

## 1. 原版的形狀:一對座標 + 一個取格函式

### 1.1 `sub_DB10(x, y)` 依地點分派

```asm
cmp  byte_3E0A3, 7Fh
ja   → lea ecx, ds:3F8F4h[y*32 + x]     ; 戰場緩衝(11 列 × 32 B)
       byte_3E0A3 == 0 → 世界地圖的 chunk 計算
       否則             → 場景
```

戰鬥時 `byte_3E0A3 = 0xFF`(`sub_2E364` 設的),所以 `> 0x7F` 那一支就是戰場。
而且回的是**位址**,讀寫共用。

### 1.2 `sub_A360` 進來就把座標借給行動中的單位

```asm
movzx eax, byte_3E0AE                    ; 目前行動的單位
mov   dl, byte ptr dword_3EF54+2[eax*8]
mov   byte_3E0A6, dl                     ; 「隊伍 X」← 該單位在戰場上的 X
mov   dl, byte ptr dword_3EF54+3[eax*8]
mov   byte_3E0A7, dl
```

### 1.3 `sub_2E364` 存還

進戰場前把 `byte_3E0A6/A7/A5` 存進 var_4/var_8/var_C,離場時寫回去。

⇒ **原版只有一對座標。** 平時是隊伍的位置,戰鬥時借給行動者,離場還原。
`Get` / `Jimmy` / `Open` / `Push` / `Search` / `Ready` / `Use` / `Ztats`
讀的一直是這一對 + `sub_DB10` —— 所以它們**一行都不用改**就能在戰場上運作。

## 2. 引擎補的三處

| 原版 | 引擎 |
|---|---|
| `sub_DB10` 的 `> 0x7F` 分支 | `TileAt` / `SetTileAt` 加 `if s.InCombat()` |
| `sub_A360` 開頭借座標 | `focusCombatUnit`(回合開始時 `State.X/Y = 單位座標`) |
| `sub_2E364` 存還 | `Combat.savedX/savedY` + `EndCombat` 還原 |

補完之後那九個指令直接接上鍵盤就對了。先前之所以覺得要另寫,
是因為**我把座標與地圖各拆成了兩套**(`State.X/Y` 與 `u.X/u.Y`、
`TileAt` 與 `CombatTileAt`)—— 拆開之後就必須寫第二份指令,
而原版從一開始就沒有這個問題。

> 這是 deep module 的反例:介面拆得比實作該有的樣子多,
> 呼叫端就得為每一份介面各寫一次。

另外一處:`pickCharacter` 在戰鬥中直接回**行動者**的名冊索引 ——
原版把「目前是哪個角色」記在 `byte_3E08B`,而 `sub_A360` 進來就設好它。
戰鬥中沒有「挑人」這回事。

## 3. K 在戰鬥中是第四支 Klimb(`sub_16058`)

地圖上的 Klimb 有三個入口(地表 `sub_188C4`、場景 `sub_EA0`、地牢 `sub_417C`),
戰鬥是第四支。它做兩件事:

```
tile = 腳下
if (byte_3E0B1 & 2 && tile == 0xC8 && byte_418DE) {
    print "U/D-"                     ; 兩向梯 → 問上下
    3 / 'U' → 上;4 / 'D' → tile = 0xC9(下);其餘 → 放棄
}
tile == 0xC8                        → "Up!"   + sub_15E20(單位, 5)
tile == 0x86 && !(byte_3E0B1 & 0x80) → "Down!" + sub_15E20(單位, 6)
tile == 0xC9                        → "Down!" + sub_15E20(單位, 6)
否則 → 問方向;鄰格 tile 必須是 **0x4C** 且沒人站著,才爬過去;否則 "What?"
```

⚠ `byte_418DE`(這是兩向梯)是**畫戰場時**記下來的 —— `sub_FD54` 對腳下
地牢地形 kind 3 設起來(`docs/re/48` §6 那一段的最後兩行)。
所以「要不要問上下」不是看戰場上那個 tile,而是看**你在地牢裡站在什麼上面**。

## 4. `sub_15E20` 順帶解出一條規則

```asm
byte_3E08C & 0xF8 == 0x20 → "\nStay with ship!\n"      ; 在船上不能自己走掉
隊員:
   byte_3E0B0 == 0            → byte_3E0B0 = 出口      ; 第一個離場的人選定出口
   出口 != byte_3E0B0 且 byte_3E0B1 & 0x80
                              → "\nAll must use the same exit!\n"
```

★ **全隊必須從同一個出口離開。** 第一個離場的人選,之後的人只能跟。

⚠ 但那條有 `byte_3E0B1 & 0x80` 的閘門,而目前四種戰場模式
(0 一般遭遇 / 2 地牢遊蕩 / 4 地表紮營 / 6 地牢紮營)**都不帶 0x80** ——
規則存在但還踩不到。**照抄閘門,不假裝它一定生效**(`Combat.sameExitEnforced`)。

## 5. 一個順帶的疑點

`sub_16058` 的「爬得過去」判的是 **tile 0x4C**。而本專案的
`partyTileFor()` 回的也是 0x4C(隊伍在戰場上的圖)。兩者衝突 ——
0x4C 不太可能同時是「隊伍自己」與「戰場上爬得過去的東西」。

`partyTileFor` 當初是猜的(沒有 `docs/re/` 依據)。⬜ 待查:隊伍在戰場上
實際畫的是哪個 tile(`sub_A360` 附近應該有寫進 `dword_3EF50` 的地方)。
**先不動它** —— 沒有證據就不要為了消除矛盾而改另一邊。
