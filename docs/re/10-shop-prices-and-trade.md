# 商店價目表與交易流程

> 輸入檔:`WORRIORS.EXP`(FM Towns,SHA-256 見 `re_work/fmtowns/SHA256SUMS.txt`)、
> DOS `DATA.OVL`、`SHOPPE.DAT`
> IDA 位址皆為線性位址(Phar Lap flat model,檔案位移 = 線性位址 + 0x200)
> 日期:2026-08-07

八種店在原版是八支獨立函式,由 `sub_1B294` 的跳表 `jpt_1B363` 分派:

| 店種 | 對話碼 | 處理函式 | 家數 | 本輪狀態 |
|---|---|---|---|---|
| 武具店 | 0x81 | `sub_1258C` | 9 | ✅ 買 + 賣 |
| 酒館 | 0x82 | `sub_216C8` | 9 | ⬜ 未逆完 |
| 馬廄 | 0x83 | `sub_118CC` | 4 | ✅ 買馬(地圖物件待補) |
| 造船廠 | 0x84 | `sub_21C40` → `sub_219B0` | 4 | ⬜ 未逆完(價已解) |
| 藥草鋪 | 0x85 | `sub_11864` → `sub_1173C` → `sub_11588` | 5 | ✅ |
| 公會 | 0x86 | `sub_11520` → `sub_11464` → `sub_112F8` | 3 | ✅ |
| 治療所 | 0x87 | `sub_12838` | 7 | ✅ |
| 旅店 | 0x88 | `sub_2274C` → `sub_22280` | 6 | ⬜ 未逆完(價已解) |

## 1. 兩個索引

進店時 `sub_1B294` 先算出兩個數,之後每張表都靠它們取值:

```asm
lea  eax, [edi-81h]          ; edi = NPC 的對話號碼
mov  word_3EF36, ax          ; 店種 = 對話碼 − 0x81
mov  word_3EF34, 0
loop:                        ; 在 byte_4185C[店種][0..15] 裡找當前地點
    mov al, byte_4185C[店種*16 + word_3EF34]
    cmp al, byte_3E0A3       ; byte_3E0A3 = 當前地點編號
    jz  found
    inc word_3EF34
```

- `word_3EF36` = **店種**(0..7)
- `word_3EF34` = **同種店裡的第幾家**

⚠ Hex-Rays 把 `word_3EF34` 整個折掉了:`byte_55384[edi + eax*8]` 被印成
`byte_55384[i]`,看起來像「全遊戲共用一張貨架」。實際上組語清清楚楚是二維的。
這是 CLAUDE.md §4.4 那條規則的又一個實例。

## 2. 價目表在 DOS `DATA.OVL` 裡

FM Towns 的資料段與 DOS 的 `DATA.OVL` 是**整塊照搬**——不只值相同,連相對距離
都一樣。逐位元組比對確認:

| FM Towns 線性 | DOS `DATA.OVL` | 內容 | 形狀 |
|---|---|---|---|
| `0x55274` | `0x3A42` | 藥草底價 | 5 家 × 8 味,byte |
| `0x5529C` | `0x3A6A` | 藥草份數 | 5 × 8,byte |
| `0x552C4` | `0x3A92` | 裝備底價 | 48 × u16 |
| `0x55384` | `0x3AF2` | 武具店貨架 | 9 家 × 8 格,0xFF 結束 |
| `0x553CC` | `0x3B3A` | 問候語位移 | 8 種 × 4 句 × u16 |
| `0x5554C` | `0x3BFA` | 公會底價 | 3 家 × 4 格 × u16(用 3 格) |
| `0x5558C` | `0x3C1A` | 公會說詞位移 | 3 × u16 |
| `0x55598` | `0x3C20` | 藥草說詞位移 | 8 × u16 |
| `0x555D8` | `0x3C40` | 馬價 | 4 × u16 |
| `0x55608` | `0x3C58` | 裝備推銷詞位移 | 48 × u16 |
| `0x556F4` | `0x3CCE` | 收購說詞位移 | 8 × u16 |
| `0x56E44` | `0x4C58` | 酒單價 | 6 × u16 |
| `0x57060` | `0x4D76` | 帆船價 | 4 × u16 |
| `0x57070` | `0x4D7E` | 小艇價 | 4 × u16 |
| `0x57090` | `0x4D8E` | 旅店每人每天 | 6 × byte |

⇒ **價格一律讀玩家自己的 `DATA.OVL`**,不寫死在引擎裡(與店名、店主、詞典一致)。
實作在 `internal/u5data/price.go`。

唯一的例外是 `dword_55714`(裝備的「另一種說法」,`Cloth suit`、`Two-Handed Axe`
之類,14 筆):在 DOS `DATA.OVL` 裡整組位移都對不上,所以是唯一一張從 FM Towns
抄過來寫死的商店字串表。

### 這組位址怎麼確認的

每張表的**列數都等於該店種的家數**——武具 9、藥草 5、公會 3、馬廄 4、造船 4、
旅店 6、酒館 9。家數來自 `byte_4185C` 那三張平行表(見 `docs/re/08-shops.md`),
列數來自這裡的位移,兩邊各自獨立。八種店全部對上,不會是位移湊巧。

更硬的一條:41 件有店在賣的裝備,推銷詞位移全部落在 `SHOPPE.DAT`(10,135 B)
之內;7 件沒人賣的(寶石盾、神秘甲、混沌之劍、玻璃劍、寶石劍、神秘之劍、安卡)
位移全是 0 或垃圾。貨架、價格、說詞是**三個不同位移**讀出來的,能三方對上。

## 3. 議價:買價與賣價是兩條不同的公式

### 買(`sub_11AF0`、`sub_11588`、`sub_112F8`、`sub_118CC`、`sub_219B0` 都一樣)

```asm
mov  ax, word ptr dword_552C4[edi*4]  ; base
mov  word_3EF38, ax
movzx edx, byte_3DDC2[買家*32]         ; INT(角色紀錄 offset 0x0E)
lea  edx, [edx+edx*2]                 ; ×3
mov  ecx, 64h
sub  ecx, edx                         ; 100 − 3×INT
imul eax, ecx
cdq
idiv ecx(=100)
add  word_3EF38, ax
```

```
買價 = base + base × (100 − 3 × INT) / 100
```

智力每點折 3%,**起點是底價的兩倍**:INT 0 付兩倍,INT 33 才約等於底價。
`idiv` 向零捨入,INT 超過 33 商為負、價格會低於底價——原版沒有夾住,照抄。

### 賣(`sub_12060`)

```
賣價 = (3 × INT × base) / 100 + 1
```

方向相反:從零往上加。智力 17 只換得回約半價。兩件事不能賣——

- 箭矢(27)與弩矢(29):`cmp edi, 1Bh` / `cmp edi, 1Dh` → 「不收二手彈藥」
- 底價 0 的東西:「這個我不收」

金幣上限 **9999**(`sub_2BBDC(&gold, price, 0x270F)`)。

## 4. 佔位符(`sub_10FEC`)

商店文字裡的七個佔位符,全出自跳表 `jpt_11093`:

| 字元 | 來源 | 內容 |
|---|---|---|
| `#` 0x23 | `dword_3EF24` | 店名 |
| `$` 0x24 | `dword_3EF28` | 店主 |
| `%` 0x25 | `word_3EF38` | 價格 |
| `&` 0x26 | `dword_3EF2C` | 物品名(收購對白;有別稱就用別稱) |
| `*` 0x2A | `dword_3EF30` | 地名(酒館八卦) |
| `@` 0x40 | `byte_3E08F` | 時段:< 12 morning、< 18 afternoon、其餘 evening |
| `^` 0x5E | `word_3EF3A` | 數量(藥草一次幾份) |

同一趟迴圈還負責展開詞典 token(位元組 ≥ 0x80,前面補一個空格)。

驗收:藥草鋪的人參一句展開成
`This Ginseng variety imparts the highest degree of healing power to thine magic,
and costs 29 gp for 10 roots.` ——`%` 是議過價的 29(底價 20、智力 17),
`^` 是份數表讀出來的 10。

## 5. 各店的細節

### 武具店

先問買(B)還是賣(S),空白鍵走人(`sub_1258C` 只認這三個)。
貨架每家 7 件 + `0xFF` 終止。第 0 家(Iolo's Bows)賣的是
匕首 / 投石索 / 弓 / 箭 / 十字弓 / 弩矢 / 魔法弓——**與店名對得上**,
而店名是從另一張表讀的。

買箭矢與弩矢不是加一,是**直接補滿 99**(`sub_11AF0` 的兩個特例分支)。
這條同時是「裝備編號解對了」的旁證:27 與 29 正好是 Arrows 與 Quarrels。

### 藥草鋪

一價買**一包 N 份**,價與份數各一張表。選單字母只發給有貨的,
按鍵再由 `sub_11588` 掃過 8 味映射回真正的藥草編號,所以缺貨的味不佔位。
跳表只有 5 個 case ⇒ **一家最多列 5 味**,實際資料也沒有超過的。

毒藤與曼陀羅只有 3 家賣,而且貴——原版把這兩味邪門藥草限制在特定地點。

### 公會

固定三樣:鑰匙(一次 3 把)、寶石(4 顆)、火把(5 支)。
還有一個沒列在選單上的 `D` 鍵,印 `SHOPPE.DAT` 位移 0x2215 的一段文字。

### 治療所

三種服務的價**不在表裡**,是程式碼裡的立即數:
解毒 20、療傷 35、復活 200。各有前置判斷(`sub_12838`):

```asm
byte_3DDBF[32*i] != 'P'  → 「汝無需此術」   ; 解毒要中毒
狀態=='D' 或 HP==MaxHP   → 「汝無需此術」   ; 療傷要活著且有傷
byte_3DDBF[32*i] != 'D'  → 「汝無需此術」   ; 復活要死了
```

`sub_12794` 收錢時有一條**與地點綁定的例外**:

```asm
cmp  ax, word_3DFB6      ; 價格 vs 金幣
jle  ok
cmp  ax, 64h             ; 價格 > 100?
jg   refuse
cmp  byte_3E0A3, 7       ; 地點 7?
jz   ok                  ; ← 付不起也照做
refuse: ...
```

⇒ **地點 7 的治療所,100 金以下的服務付不起也照治**;復活 200 金不在此列。

### 馬廄

四家,馬價 100 / 130 / 160 / 190。買了之後原版會在店門口的地圖格放一隻馬 tile
(`sub_118CC` 尾段寫 `dword_3E46C` 的物件槽)——地圖物件層還沒做,
目前只誠實說明。

### 騎馬進店

`sub_1B294` 開頭:`byte_3E08C & 0xFE == 0x12`(騎馬)而店種不是 0x83(馬廄)
→ 「GET THAT HORSE OUT OF HERE!」,連問候語都沒有。

## 6. 背包欄位在存檔裡的位移

跟著 `sub_27D24` 的讀取序列累加得出:

| 存檔位移 | 記憶體 | 內容 |
|---|---|---|
| `0x0204` | `word_3DFB6` | 金幣(u16) |
| `0x0206` | `byte_3DFB8` | 鑰匙 |
| `0x0207` | `byte_3DFB9` | 寶石 |
| `0x0208` | `byte_3DFBA` | 火把 |
| `0x021A` | `byte_3DFD0` | 裝備持有數 48 B,索引 = 裝備編號 |
| `0x02AA` | `byte_3E060` | 藥草持有數 8 B |

⚠ **記憶體位址與檔案位移不是固定差值**。讀取是逐欄位 `fread`/`fgetc`,
而全域變數之間有對齊留下的空隙:`byte_3DFB8` 讀完 10 B 到 `0x3DFC2`,
下一個欄位卻在 `0x3DFC4`。整份存檔累積 **4 B** 的漂移,所以不能拿
「線性位址 − 某個常數」去推位移,一定要跟著讀取序列走。

用 `INIT.GAM` 驗證:金幣 150、鑰匙 2、火把 4、藥草
`[4 6 7 6 0 3 0 0]`、背包是小盾 1 / 布甲 2 / 匕首 6 / 棍 1 / 火油 3
——全部是開場該有的東西,不是「某個看起來像數字的值」。
