## 1. ★ `sub_25F0` 不是移動,是攻擊

名字看起來像「讓這一槽動一步」,實際上它**完全不改座標**。三條路,全部是攻擊:

```
kind = 物件[槽][0]
dx = abs(物件X − 隊伍X);  if (dx > 0x7F) dx = 0x100 − dx      ; ★ 環繞距離
dy = abs(物件Y − 隊伍Y);  if (dy > 0x7F) dy = 0x100 − dy

if ((dx == 1 && dy == 0) || (dx == 0 && dy == 1)) {            ; ── 貼著隊伍
    sub_24DC(槽); return 1
}
if (kind == 0x88 || kind == 0xDC) {                            ; ── 遠程:海蛇 / 龍
    if (dx > 3 || dy > 3) return 0
    if (random(0, 7) != 0) return 0                            ; ★ 1/8 才開火
    音效 sub_2C188(0x514, 0x12C, 5, 0x64)
    命中 = sub_20CB4(dx+5, dy+5, 5, 5, 3)                      ; 投射物飛行
    if (命中) { sub_2B1C8(隊伍X, 隊伍Y); sub_22F0() }          ; ★ 打中 → 船損
    return 1
}
if ((kind & 0xFC) == 0x2C) {                                   ; ── 敵船開砲
    if (!((dx == 0 && dy < 4) || (dy == 0 && dx < 4))) return 0
    印 "* BOOOM! *"
    sub_23FC(槽, dx, dy)
    return 1
}
return 0
```

### ★★ 三個容易寫錯的地方

1. **相鄰只算正交。** 判準是 `(dx==1 && dy==0) || (dx==0 && dy==1)` ——
   **斜對角(1,1)不算相鄰**,所以斜著貼著隊伍的怪不會動手。
   寫成「切比雪夫距離 1」會讓怪物比原版兇一圈。
2. **只有海蛇(0x88)與龍(0xDC)有遠程攻擊**,射程 3(兩軸各自 ≤ 3,
   所以是**方形**範圍不是圓形),而且**每回合只有 1/8 會開火**。
3. **遠程命中打的是船不是人**(`sub_2B1C8` + `sub_22F0` 是船損那一對)。
   在陸地上被龍噴到會發生什麼,取決於 `sub_2B1C8` 對非船載具怎麼處理 ——
   ⬜ 未追。

### ★★ `sub_24DC`(貼身接觸)讀完了 —— 而它解開了 0xEC 是什麼

```
kind = 物件[槽][0]
if ((kind & 0xFC) == 0xEC) {                  ; ── 漩渦
    if (byte_3E08C == 0x1C) → 只損船           ; ★ 步行時碰不到你
    物件[槽][0] = 物件[槽][1] = 0              ; ★ 漩渦自己消失(一次性)
    印 "\nWHIRLPOOL!\n"
    音效(把載具碼暫時設成 0xEC 再還原)
    sub_22F0()                                 ; 船損
    byte_3E0A5 = 0FFh                          ; ★ 幽冥界
    byte_3E0A6 = 22h (34);  byte_3E0A7 = 12h (18)   ; ★ 固定落點
    sub_2CBEC()                                ; 重載地圖
    return
}
if ((kind & 0xFC) == 0xE0) → 只損船             ; 流沙陷阱族
印 "\nAttacked!\n"
if (tile(隊伍腳下) >= 4) → 開戰                 ; ★ 陸地一律開戰
if ((byte_3E08C & 0FEh) == 14h) → 只損船        ; 魔毯
if ((byte_3E08C & 0FCh) != 28h) → 開戰         ; 不是小艇
→ 只損船                                        ; 是小艇
```

## ★★ `0xEC` 是**漩渦**,不是怪物

`docs/re/82` §5 留了一條 ⬜:「深水 1/8 生的 0xEC 在 `DATA.OVL` 名表裡沒有名字」。
答案是**它不是生物,是地理特徵** —— 所以名表本來就不會有它。**三重佐證**:

1. `sub_24DC` 印的字串就是 `"\nWHIRLPOOL!\n"`。
2. 物件種類碼 **+256** 才是 tile(`docs/re/09` 早就記了),而
   `0xEC + 0x100 = 0x1EC = 492` —— `look#492` 的譯文正是「**漩渦**」。
   ⚠ 我先前拿 `look#236`(= 0xEC 當**地圖** tile 的敘述,「不列顛尼亞的光榮戰旗」)
   去對,那是**兩個不同的命名空間**。判斷法:物件種類碼要先 +256 才能查 tile 名。
3. **遊戲內的傳聞早就講過這個機制**,而且譯文早就在庫裡:
   `DWELLING.TLK#2#e8`「俺聽說深海地底有大漩渦、是幽冥界的洞穴崩塌造成的」、
   `DWELLING.TLK#2#e11`「有人說被漩渦吸下去的船、後來擱淺在地底什麼地方」。

⇒ 三條證據獨立命中同一個結論。★ 而 §2 裡 `sub_2D38` 對 `0xEC` 那一段
(隔次 + 1/2 機率 + `sub_2A54`)就是**漩渦的漂移**。

### ★ 在小艇上被貼身不會開戰

水上(腳下 tile < 4)分三條:**魔毯與小艇只損船,其餘開戰**。
寫成「一律開戰」會讓小艇變成活棺材 —— 而在小艇上安全正是 U5 海上的節奏。

### ⬜ 兩支下游還沒讀

| 位址 | 是什麼 |
|---|---|
| `sub_20CB4` | 投射物飛行(引擎已有投射物,要對齊參數語意) |
| `sub_23FC` | 敵船開砲(`"* BOOOM! *"` 之後做什麼) |

⇒ **所以「怪物移動」到現在還沒找到。** `sub_2E24` 對每一槽只做兩件事:
`sub_25F0`(攻擊)與 `sub_2D38`(能不能動)。若移動在 `sub_2D38` 裡面,
那它的名字與 §3 的內容不符;若不在,大地圖的怪就**真的不會移動** ——
那是可以對 DOSBox 實測驗證的(A 階段)。**先不猜。**

## 2. `sub_2D38` 是「這一槽這回合能不能動」的閘門

```
kind = 物件[槽][0]
if ((kind & 0xFC) == 0xEC) {              ; 那個沒名字的 0xEC 族
    物件[槽][5] ^= 1                       ; ★ 持久切換位元 → 隔次
    if (物件[槽][5] == 0) return 不動
    if (random(0, 1) != 0) return 動
    sub_2A54(槽)                           ; ⬜ 未讀
    return 不動
}
if (kind == 0xFC) {                        ; ObjSpecialFC
    if (sub_27F0(槽) == 0) return 動        ; ⬜ 未讀
    舊 = 物件[槽][5]; 物件[槽][5]++
    if (舊 >= 0x14) return 動               ; ★ 20 次之後就一直能動
    return 不動
}
if ((kind & 0xFC) == 0x2C) {               ; ── 敵船
    if (byte_3E0A2 == 0) return 不動         ; ★ 無風 → 敵船不動
    延遲 = dword_4FD50[(kind − 0x2C)*4 + 風向]
    if (延遲 == 4) return 動                 ; ⚠ 見下
    物件[槽][7]++
    if (物件[槽][7] <= 延遲) return 動
    物件[槽][7] = 0
    return 不動
}
return 動
```

⚠ `延遲 == 4` 與「計數器沒到」走的是**同一個出口**,所以那兩條的回傳值相同 ——
要判斷哪個是「動」哪個是「不動」得看呼叫端怎麼用回傳值。⬜ 未定,
所以上面的「動 / 不動」標注只是相對關係,絕對語意待確認。

### ★★ 敵船的風向延遲表與怪物權重表**物理上重疊**

`dword_4FD50` 是一張 4×4 的 dword 表(`[船的朝向][風向]`),而**風向 0 不可能發生**
(`byte_3E0A2 == 0` 在查表之前就 return)⇒ **`[0][0]` 那一格永遠讀不到**。

原作者就把別的資料塞進那四個位元組:

| 位址 | 誰在用 |
|---|---|
| `0x4FD50` +0 | **水域・地表怪物權重的第 5 個**(`docs/re/82` §5 的溢出) |
| `0x4FD50` +1..+3 | **水域・幽冥界的權重表**(`00 80 80`) |
| `0x4FD50` 整個 dword | 敵船延遲表的 `[0][0]` —— **死格** |

⇒ 三個用途共用同四個位元組,而三者都正確,因為第三個永遠讀不到。
**這種重疊不是資料損壞,是 1988 年的空間節省。** 判斷法:先確認那一格真的
不可達,再相信重疊。

表的內容(朝向 0..3 × 風向 1..4):

```
朝向 0:  2  3  4  4
朝向 1:  4  4  2  3
朝向 2:  3  2  4  4
朝向 3:  4  4  3  2
```

每個朝向剛好一個 2、一個 3、兩個 4。

## 3. ★★ 玩家的航行在 `sub_2D2D0`,用**另外兩張表**

`sub_2D38` 全檔**只有一個呼叫者**(`sub_2E24`),而它讀的是**物件槽** ——
玩家的船是 `byte_3E08C`(載具碼),不是物件槽。

⇒ **`sub_2D38` 與玩家的航行無關。** 玩家的自動航行是 `sub_2D2D0`
(由 `sub_2D9D0` 在 line 79860 呼叫,比移動 `sub_2D174` 還早):

```
loop:
  if (byte_3E167 == 0) 收尾                       ; ★ 沒揚帆就不自動走
  key = 有沒有按鍵
  if (key != 0 && key != byte_3E167) 收尾          ; ★ 按別的鍵就停
  帆向 = byte_3E167                                ; 1..4
  if (byte_3E0A2 == 0) 走一步                      ; ★★ 無風 → 照走,不查表
  (dx帆, dy帆) = 帆向的單位向量
  n = 1
  if (byte_601C7[風向] != dx帆) n++
  if (byte_601CB[風向] != dy帆) n++
  if ((n % 3) > byte_3E093) 走一步 else { byte_3E093 = 0; 收尾 }
走一步:
  時鐘 += (byte_3DFC9 > 0x7F ? 1 : 2)
  (條件符合時) sub_2E24()                          ; 世界回合
  sub_2B740(1); byte_3E093++; goto loop
```

`byte_601C7` / `byte_601CB` 是四個風向的單位向量(以 unsigned byte 存,
`0xFF` 就是 −1):

| 風向 | 601C7 | 601CB |
|---|---|---|
| 1 | 0 | +1 |
| 2 | 0 | −1 |
| 3 | −1 | 0 |
| 4 | +1 | 0 |

而 `n = 1 + (兩個分量各自不同的個數)`,所以:

| 帆向 vs 風向 | 不同的分量數 | n | `n % 3` = 這回合走幾步 |
|---|---|---|---|
| **同向** | 0 | 1 | **1** |
| **反向** | 1(只有那一軸) | 2 | **2** |
| **垂直** | 2(兩軸都不同) | 3 | **0** |

## 4. ⇒ 引擎的 `CanSail` 掛在錯的函式上

`internal/game/wind.go` 的註解寫「原版 `sub_2D38` 的邏輯:延遲 4 一律不動;
否則累加一個計數器」,而那是**敵船**的規則。玩家的規則是 §3 的 `n % 3`,
用的是完全不同的兩張表。

`state.go:785` 的「駕船時風向決定走不走得動(原版 `sub_2D38` 的延遲表)」
同樣掛錯。

## 5. ⚠⚠ 沒收斂的一條:走一步的地方沒有改座標

`loc_2D40A`(上面的「走一步」)做了四件事:推時鐘、可能跑一個世界回合、
`sub_2B740(1)` 重畫、計數器 +1。**沒有任何一行寫 `byte_3E0A6`/`byte_3E0A7`。**

⇒ 三種可能,而我還分不出來:

1. 位置更新在 `sub_2D174`(它在 `sub_2D2D0` 之後被呼叫),而 `byte_3E093`
   是傳給它的「還要走幾步」。
2. `sub_2B740` 不只是重畫。
3. 我把「走一步」認錯了,那一段其實是「等待一拍」。

⇒ **在這條收斂之前不動 `CanSail`。** 現在改等於用半個理解換掉一個至少
「玩起來對」的近似,而 `n % 3` 那張表如果我把方向對應搞反了,
就會做出「順風走不動、逆風飛快」的船 —— 而那在遊玩時只覺得怪,
不會有人查得出原因。

⇒ 這一條正好是 A 階段(對 DOSBox 並排實測)最省力的第一個題目:
**在原版揚帆,數順風 / 逆風 / 側風各走幾格**,十分鐘就有答案。
