### 舷側怎麼判

船首方向是載具碼的低兩位(`0x24..0x27` 大船 / `0x20..0x23` 揚帆中各對四個朝向)。
舷側 = 與船首**垂直**,而方向碼北 0 / 東 1 / 南 2 / 西 3 —— 偶數是南北、
奇數是東西,所以 `(方向 ^ 船首) & 1 == 1` 就是垂直。

★ 少了這道限制,玩家可以往船首正前方轟 —— 那是帆船辦不到的事,
也會讓海戰的走位完全失去意義。

## 2. Mix:「藥草不足」是**拒絕**,不是把份數調低

`sub_18698`:

```asm
loc_1869F:
        var_4 = 1
        "How much? "
        ebx = 讀兩位數
        …
        cmp     ebx, eax            ; 要的份數 vs 該藥草存量
        jle     short loc_186F1     ; 夠 → 檢查下一種
        push    offset aInsufficientRe ; "Insufficient reagents!\n\n"
        mov     [ebp+var_4], 0
loc_186F6:
        cmp     [ebp+var_4], 0
        jz      short loc_1869F     ; ← **跳回去重問份數**
```

引擎原本寫成「份數受限於最少的那一味」,而且有一條測試
(`TestMixLimitedByScarcestReagent`)把它釘住了。**那個行為是錯的。**

靜靜調低看起來很體貼,但玩家會以為自己調到了要的份數而實際上少了 ——
那種落差要等到施法時才發現,而那時已經回推不了原因。

已改成拒絕,並把測試改名為 `TestMixRefusesWhenReagentsAreShort`,
在註解裡寫明原本錯在哪裡。

⇒ **測試會把錯的行為釘得跟對的一樣牢。** 綠燈只證明「行為沒變」,
不證明「行為對」——要證明對,得回去讀組語。

## 3. Mix 的其餘規則(既有實作已符合)

- 藥草**先扣再判成敗**(`loc_1881F` 扣完才到 `loc_18836` 比對配方)——
  失敗也扣。寫成「成功才扣」會讓玩家無風險地亂試配方,而浪費藥草
  就是這個系統的全部張力。
- 配方要**恰好相等**,不是「包含」。多放一種就失敗。
- 份數上限 99(`cmp byte_3E000[i], 63h`)。
- 藥草遮罩的**最高位元是第 0 種**(`mov ebx, 80h` + `sar ebx, 1`)。
