## 1. 戰場單位表

`dword_3EF50`,**32 槽 × 8 B**。0..5 是隊員、6..31 是敵人。

| 位移 | 內容 |
|---|---|
| +0 | 目前生命(怪物用;隊員的血在名冊紀錄 0x10) |
| +1 | 敏捷 |
| +2 | 旗標(見下) |
| +3 | 生物索引(怪物)或名冊索引(隊員) |
| +4 | 對應的地圖物件槽 |
| +5 | **行動倒數** |
| +6, +7 | 戰場座標 X / Y |

### 旗標(+2)

| 位元 | 意義 | 依據 |
|---|---|---|
| 0x01 | **陣營反轉** | `sub_29A64` |
| 0x02 | 逃跑中 | `sub_AC40` 反轉方向、`sub_16454` 放行出界 |
| 0x04 | 不能行動,也選不到當目標 | `sub_A108` / `sub_AC40` |
| 0x08 | 睡著 | `sub_A108` 的 1/17 醒來 |
| 0x10 | 看不見,選不到當目標 | `sub_AC40` |
| 0x20 | 死亡 | 全檔 |
| 0x40 | 這一槽是怪物 | `sub_AC40` 的清場迴圈 |
| 0x80 | 這一槽是隊員 | 全檔 |

**0x01 在兩種單位上意義相反**,而 `sub_29A64` 就是靠這一點把兩邊算清楚:

```
死了            → 不算任何一邊
隊員(0x80)    → 回傳 0x01           ; 被魅惑 → 敵方
怪物            → 回傳 !0x01          ; 被馴服 → 我方
```

一個位元表達「站錯邊」,兩種單位各自解讀。少看這個不對稱,寫出來的
陣營判斷會在「魅惑」與「馴服」兩個方向同時錯。

## 2. Saduj:寫死在程式裡的叛徒

`sub_29A64` 對隊員還有一條**先於旗標**的例外:

```asm
mov  eax, ecx
shl  eax, 5              ; 角色索引 × 32
cmp  byte_3DDB8[eax], 6Ah ; 'j'
jnz  short loc_29AA6
mov  eax, 1              ; ← 永遠站在敵方
```

`0x3DDB8 − 0x3DDB4 = 4`,而角色紀錄的 0..8 是名字 —— 所以它比的是
**名字的第 5 個字母是不是 `j`**。全檔只有這一處讀那個位元組。

要認的只有一個人:**Saduj**(S-a-d-u-**j**)。名字倒過來是 **Judas**。
他在地牢裡加入隊伍,進戰鬥就反咬 —— 這是 U5 的既定劇情,不是資料錯誤。
名冊 0 號(聖者本人)不套這條(原版先 `and ecx,ecx; jz` 擋掉),
所以玩家把自己取名 `Xxxxj` 不會變成敵人。

同一類的還有 `sub_A360` 開頭:**握著混沌之劍(裝備 0x23)的隊員**
會被掛上陣營反轉位元,交給 AI 指揮。兩件事共用同一條「玩家控制 ⟺ 站在我方」的判斷。

## 3. 行動順序不是輪流,是敏捷

`sub_A9EC` 是一個 0..31 的無窮掃描:

```asm
dec  byte ptr [ebx+5]
cmp  byte ptr [ebx+5], 0
jnz  loc_AC0C            ; 還沒輪到
mov  al, 24h             ; 36
sub  al, [ebx+1]         ; − 敏捷
mov  [ebx+5], al         ; 重設倒數
```

**倒數 = 36 − 敏捷**。敏捷 30 的蝙蝠每 6 輪動一次、敏捷 6 的史萊姆每 30 輪
—— 差五倍。寫成 round-robin 會讓所有怪物的出手頻率一樣,敏捷那一欄就白放了。

另外兩件排程上的事:

- **每 10 個單位行動 = 遊戲內 1 分鐘**(`byte_3E092` 數到 10 → `sub_29304(1)`)。
- 站在 tile `0x84`/`0x85` 上的單位**整個回合被跳過**(`and eax,0FEh; cmp eax,84h`)。

### 勝負

`sub_15DD4` 每次行動後重數兩邊。⚠ 它用的兩個全域 `word_3E086` / `word_3E088`
**在 `sub_AC40` 裡被當成 (dx, dy) 暫存重用** —— 同名不同義,追值的時候
很容易把兩者搞混。這裡是靠「印 VICTORY 的條件是 `word_3E086 == 0`」
才定出 `3E086` = 敵方數、`3E088` = 我方數。

我方全滅時原版**不會立刻判負**:先叫 `sub_16538` 找一個被魅惑的隊員,
把他解除魅惑(印「X passes out!」)。找不到才印 `BATTLE IS LOST!` ——
不然「隊伍被自己人打光」會判成敗北。

## 4. 一次來幾隻(`sub_2F0EC`)

```
if 地點編號 ∈ 1..32 且 生物 ≠ 衛兵 且 不是「大版本」:
    1 隻                              ← 在城裡動手只打得到眼前那個
else:
    n = 怪物屬性表的 +6(隻數上限)
    if n ∉ {1, 8, 16}: n = random(1, n)
    if n + 6 > 31: n = 26              ← 隊伍佔 6 槽
第 1..n/4 隻各有 1/9 機率換成混編表(DOS 0x16E4)指定的另一種怪物
```

「大版本」是物件槽 +5 的最高位元:成立時原版把生物索引 +256,
繞過城鎮那條規則。

隻數上限這一欄把怪物分得很乾淨:

| 隻數 | 生物 |
|---|---|
| 16 | 蝙蝠、史萊姆 |
| 13 | 小魔怪 |
| 10 | 鯊魚、巨鼠、蟲群、獸人 |
| 8 | **衛兵**、骷髏、無頭者 |
| 1 | 村民、擬態怪、石像鬼、巨蟒陷阱、黑刺、不列顛王、暗影領主 |

衛兵是城鎮規則的唯一例外 —— 在城裡拔劍,來的是**一整隊八個**。

混編表把「小弟 → 頭目」串起來:小魔怪 25 → 擬態怪 26 → 巨人 35。
殺不死的那三位指向自己(不帶小弟)。

## 6. AI 的一回合(`sub_A108`)

```
全域 byte_3E08A == 'T'                  → 整場不動(時間停止 An Tym,10 回合)
全域 byte_3E08A == 'Q' 且 擲 1/2         → 這回合不動
旗標 0x04(凍住)                        → 跳過
旗標 0x08(睡著)                        → 1/17 醒來,這回合不動
旗標 0x02(逃跑)                        → 1/4 機率回 1 點血,然後只走不打
否則                                     → 先試 sub_9F08(攻擊)
                                           打不到才 sub_AE20(移動)
移動之後走出戰場邊緣                     → 印「X escapes!」離場
```

### 6.1 選目標(`sub_AC40`)

由 **31 槽往 0 掃**,取歐氏距離最近的敵對單位。跳過:自己、空槽、死的、
同陣營的、看不見的(0x10)、凍住的(0x04)。

由高往低掃有個看得出來的後果:**距離相同時槽號小的贏** ——
名冊順序在前的隊員比較容易被鎖定。

距離是 `sub_1F9F8`:`sub_1F9CC` 算出 dx²+dy² 之後用「連續減奇數」
求整數平方根 → **floor(√(dx²+dy²))**。所以**斜角相鄰算 1 格**,
與正交相鄰同等 —— 近戰打得到八個方向。

找不到任何目標時,原版把場上**所有**還在的怪物血量設成 1 並掛上逃跑旗標,
方向改成朝戰場正中央 (5,5) 算 —— 實際效果是四散離場。

方向只取正負號(−1 / 0 / +1),逃跑中的取反。

### 6.2 攻擊(`sub_9F08`)

```
dist = 距離
if 怪物射程表[生物] < dist: 不打(回 0,改成移動)
if dist == 1: 近戰 → sub_B484(命中) → sub_B9A8(命中後)
else:         遠程 → sub_9E10
```

**射程表在 DOS `0x15AC`**,把近戰與遠程分得很乾淨:近戰的一律 1,
法師 7、注視者 5、巨龍 9、收割者 9、**衛兵 15**(十字弓)。

緊接著的 `0x15DC` 是**投射物圖號**:`sub_9E10` 一開頭讀它,原封不動
餵給 `sub_1FE54`(投射物飛行)。射程 1 的那一批這一欄全是 0,
有射程的那一批全非 0 —— 兩張表互為佐證。

### 6.3 遠程(`sub_9E10`)——兩個少了就會把法師寫得過強的規則

```asm
cmp  esi, 1Ah              ; 擬態怪例外
jz   short loc_9E4D
push 0FFh / push 0 / call sub_28E14
cmp  eax, 80h
jge  loc_9F00              ; ← random(0,255) >= 128 就整個不射
```

1. **每回合只有 1/2 機率真的射出來**。沒射成就回 0,`sub_A108` 接著去跑移動
   —— 所以法師是「射一次、走一步」,不是每回合都轟。擬態怪(0x1A)是唯一
   的例外,牠不會動所以每回合都出手。
2. **轉化護符**(裝備 `0x2D`,Amulet of Turning)戴在護符欄(紀錄 0x1E)時,
   施法者的這一擊有 1/2 機率直接算失手(`sub_9F08` 先看目標的護符、
   再看攻擊者有沒有 0x8000,兩個都成立才擲那枚硬幣)。

失手的投射物不是消失,而是由 `sub_1FE54` 偏到附近隨機一格,
打到站在那裡的人 —— **可能是自己人**。

> 這一條是這一輪最有價值的發現。我第一版漏了那個 1/2,結果三隻法師
> 對初始隊伍是 8/10 打贏;補上之後變 12/20 —— **「照抄」與「照抄一半」
> 的差別會直接變成遊戲難度,而且不會有任何測試變紅。**

### 6.4 移動(`sub_AE20`)

```
擬態怪(0x1A)/ 收割者(0x1B)  → 直接 return,牠們不動
會瞬移(0x2000)                → 先試瞬移
擲硬幣:
  > 127 → 先試 X 軸;通了就只走 X
  否則或 X 被擋 → 試 Y 軸;通了就只走 Y
兩軸都不行 → 隨機挑四個方向之一,最多試 4 次
還是不行 → 這回合不動
```

**不是最短路徑演算法** —— 這就是原版怪物會在牆角來回繞的原因。

`sub_16454`(能不能走)對**出界**的格子只在逃跑旗標成立時放行:
逃跑就是靠走出邊緣完成的,沒有另外的「逃跑判定」。

## 7. 傷害之後(`sub_B9A8` / `sub_B51C`)

命中之後的優先序:

```
攻擊者是怪物 且 有下毒位元 且 擲 3/4  → 下毒(sub_B8DC)
攻擊者是注視者(0x1C)且 目標沒睡     → 讓目標睡著
否則                                   → sub_B274 算傷害 → sub_B51C 扣血
```

`sub_B8DC`(下毒)對狀態「良好」的隊員 → 狀態改 `'P'`、印「X is poisoned!」;
其餘一律當成 `random(0, 20)` 的傷害。

`sub_B51C` 的傷害套用:

```
無敵(0x0008)          → 傷害歸 0
傷害減半(0x0020)      → 除以 2(除非 byte_3E0A0 成立,那個旗標還沒解)
HP < 傷害 → HP = 0,否則 HP -= 傷害
HP == 0 或 傷害 == 99  → 死亡
沒死 且 有分裂位元      → 找空位複製一份,印「X divides!」
```

⚠ **傷害是負數時怪物會回血**:`mov al, byte ptr [ebp+arg_4]; sub [edi], al`
是位元組減法,減一個負數就是加。防禦擲贏傷害時就會這樣。照抄 ——
這是原版行為,不是我加的平衡。對**隊員**則不同:`sub_B9A8` 在傷害 < 0
且目標是隊員時直接 `byte_3E0B2 = 0x20` 走人,完全擋下。

### 經驗值

```asm
movzx edx, byte_3F055[eax*8]   ; 生命上限
shr   edx, 2
inc   edx                      ; → (上限 / 4) + 1
```

**經驗值只跟這種怪物有多耐打有關,與實際打了幾下無關。** 上限 9999
(`sub_2BBDC` 的第三個參數),寫進角色紀錄 0x14。

## 8. 玩家的戰鬥指令(`jpt_A5C8`)

從跳表的 case 值直接讀出來:

| 鍵 | 指令 | | 鍵 | 指令 |
|---|---|---|---|---|
| 方向鍵 | 移動 | | `R` | Ready |
| `A` | Attack | | `S` | Search |
| `C` | Cast | | `U` | Use item |
| `G` | Get | | `Y` | Yell |
| `J` | Jimmy | | `Z` | Z-stats |
| `K` | Klimb | | **空白** | **Pass** |
| `O` | Open | | `1`–`6` | 指定行動角色 |
| `P` | Push | | `0` | 取消指定 |

**空白鍵 Pass 是必要的** —— 四面被自己人堵住時那是唯一的出路,
少了它排程會停在那個人身上不動。(這是實測跑滿 4000 步跑出來的:
沒有 Pass 的版本在 20 個亂數種子裡有 4 個會卡死。)

## 9. 還沒做的

- **法術**(`sub_A360` 的 `C`)—— 整個魔法系統另案。
- `byte_3E08A` 的其餘值:`'T'`(時間停止,已知)、`'Q'`、`'C'`、`'N'`、`0x1C`。
- `byte_3E0A0`(疑為魔法武器,決定減半位元要不要生效)與
  `byte_3E0AD`(武器附加效果:`'3'` 下毒、`'4'` 催眠)。
- 旗標 0x0080 / 0x0100 / 0x0400 / 0x0800 / 0x4000。
- 怪物屬性 +7(巨龍 30、聖者 25、衛兵 5、海洋生物全 0)—— 像是掉落物或
  金幣,但**沒有讀它的程式碼被找到**,不寫。
- `sub_1FE54` / `sub_20CB4` 的投射物飛行路徑(會不會被地形擋)。
- `sub_1F5A4`:魅惑(0x0040)與另外兩個位元(0x0400 / 0x0800)的遠程特殊行為。
- **屍體與寶箱**:`sub_B51C` 死亡時會依地形放下 tile 1(寶箱)或 0x1F,
  機率與怪物屬性 +7 有關,還沒逆完。
