## 1. Push(`sub_18154`)

### 座標從哪裡來

```asm
movsx   edi, word_3E086      ; dx —— 方向選單回傳的增量
movsx   esi, word_3E088      ; dy
movzx   eax, byte_3E0A6      ; 隊伍 X
lea     ebx, [edi+eax]       ; 目標 X = X + dx
```

⚠ `byte_3E0A6/A7` 是**隊伍座標**,`word_3E086/3E088` 才是方向增量。
兩組名字長得像,搞反的話會去讀地圖上 (1,0) 那一格 —— 而那一格通常是水,
於是「什麼都推不動」,看起來像清單抄錯。Look(`sub_D9C4`)與地形代價
(`sub_2D0BC`)用的是同一組變數,三處交叉對照才確定。

### 流程

```
目標 = 隊伍 + 方向
目標格有物件、或 tile 不在可推清單 → "Won't budge!"

地板 = (tile & 0xFC) == 0xB4 ? 0x45 : 0x44

前一格(目標再往前)沒有物件 且 tile == 地板
    → 推:前一格 ← 家具,目標格 ← 地板
否則 隊伍腳下 == 地板
    → 拉:隊伍腳下 ← 家具,目標格 ← 地板
否則 → "Won't budge"

隊伍往那個方向走一步          ← 推與拉**都會走**
```

★ **「拉」不是另一個指令**,是同一支函式的 else 分支。而且因為最後都會走一步,
拉的結果是**隊伍與家具交換位置**。寫成「推不動就算了」會少掉半個機制 ——
玩家永遠搬不動靠牆的家具。

### 可推的東西(`sub_17F58` 的 switch)

| tile | 東西 | 轉向 |
|---|---|---|
| 0x90–0x93 | 椅子 | ✔ |
| 0xA5 | 書桌 | |
| 0xA6 | 橡木桶 | |
| 0xA8 | 梳妝台 | |
| 0xA9 | 水壺 | |
| 0xAD | 五斗櫃 | |
| 0xAE | 邊桌 | |
| 0xAF | 沉重的置物箱 | |
| 0xB4–0xB7 | 大砲 | ✔ |

名稱取自 `LOOK2.DAT`(`docs/re/37`)—— 又一個「兩份資料互相佐證」的例子:
可推清單只有數字,敘述表給了它們的意思。

### 兩種地板不能互換

`0x44` 與 `0x45` 在 `LOOK2` 都叫 cobble,肉眼分不出來。但大砲**只認 0x45**、
其餘家具**只認 0x44**,而且目的地必須「正好是」那一種。
只有比對數值才看得見這條規則。

### 轉向(`sub_18028`)

```
(0,-1) 北 → +0    (1,0) 東 → +1    (0,1) 南 → +2    (-1,0) 西 → +3
拉的時候:face ^= 2        ← 與 Direction.Opposite 同一個手法
```

只有 `tile & 0xFC` 是 0x90(椅子)或 0xB4(大砲)才轉。少了這一段,
椅子推一推會朝著奇怪的方向 —— 而那看起來只像美術瑕疵,不像 bug。

## 2. 主選單(`sub_60BC`)

```
Journey Onward
Create New Character
Transfer from Ultima IV
Ultima V Introduction
Acknowledgements
Return to the View
```

`sub_6730` 的迴圈用方向鍵移動、Enter 選定(跳表在 `jpt_6D52` / `jpt_6D9E`)。

⚠ **順序照原版不重排。** 老遊戲玩家的肌肉記憶是「第幾項」;
把常用的往上搬會踩到那個記憶,而且對照原版錄影驗收時會對不上。

### 兩項沒做,照實說

- **Transfer from Ultima IV** —— 轉換規則未逆(`DATA.OVL` 0x3115 / 0x3529 有字串)。
- **Acknowledgements** —— 原版畫的是一張製作群畫面,素材還沒對到。

兩項都印「尚未實作」而不是做一個「什麼都不做卻關掉選單」的分支:
玩家會以為角色轉進來了,那比缺這一項更糟(CLAUDE.md §3.0)。

⚠ 也**不要**拿結局那份頒獎狀名單頂替 Acknowledgements —— 那是通關的獎勵,
內容完全不同,混用等於偽造。
