# 結局:兩個,取決於汝有沒有帶那只盒子

> 輸入檔:`org_game/fmtown/…/U5_E/WORRIORS.EXP`
> 位址:`sub_135FC`(整幕)、`sub_134CC`(走位動畫)、`sub_13258`(製作名單)
> 日期:2026-08-07

`ENDMSG.DAT` 的十一筆譯文早就備好了,但那一幕一直沒接。逆完發現它**有兩個結局**,
而分岔點不是玩家的回答 —— 是背包裡有沒有那只檀香木盒。

## 1. 流程

```c
sub_2C740("MISCMAPS.DAT", 地圖, 0xB0, 0x210);      // 王座廳的 11×11
sub_2C740("ENDMSG.DAT",  byte_54700, 0x3E8, 0);    // ★ 從檔頭載入
for (i = 0; i < 隊伍人數; i++)
    if (狀態 == 'D') { 印「<名字> lives!」; 狀態 = 'G'; HP = MaxHP; }   // ★ 無條件復活
…全員走進王座廳(sub_134CC 的逐格動畫)…
puts(#0); puts(聖者名); puts("!\"\n\n");
puts(#1);  讀 Y / N;
if (N) { puts(#2); 讀 Y / N; }                      // ★ 只追問一次
if (答案 == 'Y' && byte_3DFCD != 0) {               // ★ 兩個條件是 and
    puts(#3); puts("\n\nHe says:\n\n");
    puts(#4); puts(#5); puts(#6); puts(#7); puts(#8); puts(#9);
    …全員退場、畫面淡出、sub_13258 跑製作名單…
} else {
    puts("\"I see...\n"); puts(#10);
    for (;;) { sub_13554(1); sub_13554(3); sub_13554(4); sub_13554(5); }  // ★ 無窮迴圈
}
```

三件事值得記下來:

**復活是無條件的。** 它在問話**之前**就做完了 —— 不看回答、也不看盒子。
而且做兩件事:狀態 `'D'` → `'G'`,**以及** `word_3DDC4 = word_3DDC6`(目前 HP = 最大 HP)。
只改狀態的話,人活過來但血是 0。

**答 N 會換個說法再問一次。** 第二問是另一段文字,把盒子講清楚
(「吾寢室密道裡的那只檀香木盒」)。少了它,玩家隨手按到 N 就直接吃到壞結局。

**真結局的條件是 `and`。** `cmp ebx,'Y'; jnz 壞結局` 之後**接著**
`cmp byte_3DFCD,0; jz 壞結局`。少了後者,嘴上說有就真的有了 ——
而那只盒子是整條主線最後一件收集品。

## 2. ★ 十一個「寫死的字串指標」就是 `ENDMSG.DAT` 的十一筆

與黑棘的審問(`docs/re/28` §2.4)完全同一套手法:`byte_54700` 是 BSS 緩衝區,
`sub_135FC` 用 `sub_2C740(…, 0x3E8, 0)` **從檔頭**把整份檔案載進去,
所以 `byte_54700 + n` 就是檔頭起算第 n 個位元組。

| 指標 | 位移 | 記錄 | 內容 |
|---|---|---|---|
| `byte_54700` | 0x000 | 0 | 「不列顛王說道:『幸會了,」+ 聖者名 |
| `byte_54721` | 0x021 | 1 | 「汝可帶來了吾的盒子?」 |
| `byte_54749` | 0x049 | 2 | 「那只檀香木盒……汝可帶來了?」 |
| `byte_547AB` | 0x0AB | 3 | 「不列顛王小心翼翼地打開盒子……」 |
| `byte_547D3` | 0x0D3 | 4 | 星界器物 |
| `dword_54828` | 0x128 | 5 | 「來自汝與吾同稱為故鄉的那個世界」 |
| `byte_54867` | 0x167 | 6 | 「它將帶我們脫出此獄!」 |
| `byte_548C9` | 0x1C9 | 7 | 「比蒙丹之惡更為久遠」 |

十一個位移**全部落在記錄開頭**,一個不差(`TestEndingMessageOffsetsMatchTheOriginal`
拿 `TextRecord.Offset` 逐筆比對)。

## 3. 存檔:那只盒子

`byte_3DFCD` → 存檔位移 **0x0219**。跟著讀取序列:0x0214 起是
`byte_3DFC8`..`byte_3DFCD` 六個單位元組,之後 0x021A 就是既有且已驗過的
`SaveItemsOffset`。兩端都釘住了,中間沒有算錯的空間 ——
`TestSandalwoodBoxSurvivesSaveRoundTrip` 拿裝備表當哨兵。

## 4. 引擎的實作

- `u5data.MsgEnd*` / `EndingFinale` / `SaveSandalwoodBoxOffset`
- `game.Ending` / `BeginEnding` / `AnswerEnding` / `AdvanceEnding`(`PromptEnding`)
- `game.revivePartyForEnding`
- `u5dump` 腳本動作 `Z` 播結局,接著 `y`/`N` 回答、`.` 翻頁

⚠ **壞結局的無窮迴圈沒有照抄。** 原版真的把玩家卡在那裡(那是設計的一部分:
汝沒帶盒子,故事就到這裡)。引擎改成在訊息欄寫明「原版在此停住不動」——
一個沒有出口的迴圈在現代視窗程式裡看起來就是當機。
這是本檔唯一一處**刻意**與原版不同,理由寫在 `EndEnding` 的註解裡。
