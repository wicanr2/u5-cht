## 1. `sub_3FE4` 只有十幾行,但改了三件事

```asm
dword_5FF34 = 0
byte_3E0A6 = byte_410F3[byte_3E0A3]     ; ★ X ← 以**地點編號**索引的入口表
byte_3E0A7 = byte_4111B[byte_3E0A3]     ; ★ Y
印 "\nExit to "
if (byte_3E0A5 != 0) {                  ; ★★ 離開時在第幾層
    byte_3E0A5 = 0FFh                   ;    → 樓層 −1
    印 "Underworld!"                    ;    → **地底世界**
    音樂 10
} else {
    byte_3E0A5 = 0
    印 "Britannia!"
    音樂 1
}
byte_3E0A3 = 0
```

引擎的 `LeaveDungeon()` 原本是:

```go
s.Dungeon = nil
s.Location = 0
s.Log("汝回到了地面。")
```

**兩件事都缺。**

## 2. ★★ 離開時在第幾層,決定出到哪個世界

`byte_3E0A5` 在地牢裡就是**層號**(0..7)。所以規則是:

| 離開時的層 | 出到 |
|---|---|
| 0(第 1 層) | 不列顛尼亞地表 |
| 1..7 | **地底世界** |

而「怎麼會從深層離開」有三個呼叫端,全部指向同一件事:

```asm
sub_4074   cmp al, 7 ; jnb → sub_3FE4          ; 最底層再往下
sub_100F8  cmp byte_3E0A5, 7 ; jz → sub_3FE4   ; case 6(疑為坑洞)
sub_3F34   delta > 0 且樓層 == 7 → 回 1 → 呼叫端 sub_3FE4
           delta < 0 且樓層 == 0 → 回 1 → 呼叫端 sub_3FE4
```

⇒ **八座地牢的底層都通到地底世界。** 引擎原本在最底層往下印
「再下去就沒有路了。」—— **那句話是我自己加的**,而它把 U5 的地理封起來了。

★ 這條與 `EnterDungeon` 的 `fromBelow` 是同一條路的**反向**:
`docs/re/18` 早就記了「從地底世界鑽上來是第 8 層」,而引擎實作了那個方向 ——
**卻沒有實作反向**。一條雙向通道只做了一半,而做的那一半看起來完整。

## 3. ★ 離開時要還原世界座標,否則人被丟到左上角

`byte_410F3[地點]` / `byte_4111B[地點]` 是**以地點編號索引**的入口座標表。
引擎的 `LeaveDungeon` 完全沒碰 `X`/`Y` ⇒ 隊伍帶著地牢的 **8×8 層內座標**
回到 256×256 的世界地圖上。從入口進去、走幾步、爬出來,人就會出現在
世界座標 (3, 4) 附近 —— 也就是地圖左上角的海裡。

引擎已經有那張表:`u5data.DungeonEntrances`(八筆,含中譯名),
只是離開時沒用它。

⚠ **原本沒有任何測試檢查過離開之後人在哪裡。** 這正是 `CLAUDE.md` §6.1
那條「debug hook 會遮住真 bug」的形狀 —— 測試都是「進去、走、爬」,
沒有一條把鏡頭拉到離開之後的世界座標。
`TestLeavingADungeonRestoresTheWorldPosition` 對**八座**逐一驗。

## 4. `sub_3F34` 的兩個細節

```asm
印 "Down!" / "Up!"                      ; ★ 開頭就印,在任何判斷之前
if (delta > 0 && 樓層 == 7) 回 1        ; 交給呼叫端 sub_3FE4
if (delta < 0 && 樓層 == 0) 回 1
sub_3ED0(樓層 + delta, …)               ; 才檢查那一格能不能過
```

⇒ 連「無路可去」那條也會**先看到 `Up!` / `Down!`**。
引擎原本把方向訊息放在成功之後,所以失敗時完全沒有回饋。

⚠ 而 Klimb(`sub_417C`)**確實需要梯子** —— 邊界那條在 `sub_3F34` 裡,
排在梯子檢查**之後**。所以「最底層往下出地底世界」的前提是那一格有下行梯
(或陷阱坑 0x60)。測試第一版沒擺梯子就紅了,訊息是「此處無梯可攀」,
看起來像邊界規則沒生效 —— 又是「失敗訊息指向結果,原因在前置條件」。
