### 那個結尾的 `-` 不是標點,是「等方向」的提示

原版的訊息欄是一條**逐字累加**的紙帶:按 `G` 印 `Get-`,方向鍵再把 `North`
接在**同一行**後面 → `Get-North`。所以:

- `-` 結尾的指令(`Fire` `Get` `Jimmy` `Klimb` `Open` `Search` `Talk` `Hole up`,
  以及**非地牢的** `Look`)就是要問方向的那幾支。
- **少了它,玩家按下 G 之後畫面毫無反應**,而症狀看起來像「按鍵沒吃到」。

最乾淨的佐證是 `L`:它先印 `Look`,然後**依位置**選擇印 `...`(地牢,直接看腳下)
或印一個裸的 `'-'`(其餘,問方向)。同一支函式裡兩條路各接一種結尾 ——
破折號的用途在這裡寫得最清楚。

落地:`commandEcho` 表 + `CommandEcho(key)` 處理依位置變化的那五個;
名字以「——」結尾時 `AskDirection` **不另起一行**,`AnswerDirection` 把方向
`Append` 到同一則(`TestDirectionIsAppendedToTheCommandName`)。

⚠ **版面差異**:原版整條訊息欄是單一紙帶,本引擎是一行一則的 CJK 版面。
只有「指令名 + 方向」這一組合併,其餘各佔一行。這是版面,不是機制。

## 二、選單**沒有**字母捷徑 —— 一條長期誤記

`internal/game/picker.go` 的註解原本寫:

> ⚠ 原版用**字母**選(「Item: 」後面按一個字母)。引擎用方向鍵 + Enter……
> 字母對應哪一項在跳表裡看得出來有,但沒逐一核過,所以先不做。

把原版的清單瀏覽器 `sub_1EFC8` 整支掃過,**它比對過的鍵碼只有**:

| 鍵碼 | 作用 |
|---|---|
| 1, 3 | 游標上移一項 |
| 2, 4 | 游標下移一項 |
| **0xD5 / 0xD6** | 上 / 下移動 **7 項**(`var_8 = 7` 之後跑同一個迴圈) |
| 0xD3 / 0xD4 | 另兩條分支(`loc_1F2E5` / `loc_1F303`,未追) |
| 13(Enter)、0x20(空白) | 選定 |
| 0x1B(ESC) | 放棄 |

**0x41..0x5A 一次都沒出現。** 所以 `Item: ` 是「目前停在哪一項」的標籤,
不是「請按字母」的提示 —— 引擎的方向鍵 + Enter **本來就是照原版**,
那條 ⬜ 的前提從一開始就不成立。

真正漏掉的只有一件:**翻頁一次移 7 項**(不是「一整頁」——清單再長也是 7)。
已補 `PickPage` 與 PgUp / PgDn 鍵。

### 順帶釐清 Ready 的三層結構

```
sub_1F3A4:  sub_1DE10(0)                                → 選人(< 0 取消)
            sub_1E418(-1, 0x30, byte_3DFD0, 人)          → 第一個「這個人用得到」的欄位
              -1 → "Thou art empty-handed!"
            印 "Item: " + 那個人的名字
            sub_1EFC8(起始欄位, 人, 'R')                  → 清單瀏覽器(上面那套鍵)
```

`sub_1E418` 只是「往後找下一個非空且該員用得到的欄位」的掃描器,不是清單本身;
瀏覽器 `sub_1EFC8` 靠它前後移動游標。`'R'` 那個參數決定用哪張名字表
(`R` → `byte_3DFD0` 裝備、否則 `byte_40BA0`),所以 **R 與 U 共用同一支瀏覽器** ——
這與 `docs/re/46` 把五支收成一個選單的做法方向一致。

## 追記:0xD3 / 0xD4 是 Home / End —— 而順帶挖出三件漏掉的事

上面留的「還沒追」只剩兩個鍵碼。追完之後那兩個確實就是 Home / End
(上面猜對了),但**同一段程式碼裡有三件比鍵碼重要的事被漏掉**。

### 一、兩個鍵碼

```c
case 0xD3u:                                    // ★ Home
  a1 = sub_1E418(-1, v17, v4, a2);             // 從頭找第一個候選
  j = 1;
  break;

case 0xD4u:                                    // ★ End
  a1 = sub_1E3D8(v17, v17, v4, a2);            // 從尾巴往前找最後一項
  for ( j = 1; j < 7; ++j ) {                  // 再往前最多 6 步
    v9 = sub_1E3D8(a1, v17, v4, a2);
    if ( v9 == -1 ) break;
    a1 = v9;
  }
  break;
```

兩支掃描器是全篇的關鍵:

```c
sub_1E418(from, limit, table, who)   // 往後找:from+1 .. limit−1
sub_1E3D8(from, limit, table, who)   // 往前找:from−1 .. 0
// 條件都是「該格非空,或 who != 255 且 sub_1E38C(who, i) 說這個人用得到」
// 找不到就回 −1
```

`End` 那個 6 步迴圈一開始看不出用意 —— 直到發現 `a1` **不是游標,是視窗頂端**。
往前 6 步 = 把視窗頂端退到「最後一頁」的起點,而 `j` 停在 7 → 游標正好落在最後一項。

### 二、`a1` 是視窗頂端,`j` 是游標列 —— 引擎少了一個量

畫清單的迴圈把這件事講得很清楚:

```c
sub_277C0(1, 2);                               // 從文字列 2 開始
for ( i = a1; i != -1; i = sub_1E418(i, v17, v4, a2) ) {
    ++v11;                                     // v11 = 這一幀畫了幾列
    if ( j == sub_27BBC() - 1 ) v16 = i;       // ★ 游標列 j 對到的那一項
    …畫這一列…
    if ( sub_27BBC() == 9 ) break;             // ★ 畫到文字列 9 就停 → 7 列
}
```

**視窗只有七列**(列 2..8),而 `v16`(真正選中的東西)是靠 `j` 與當前文字列
對出來的。引擎原本只有一個 `Cursor`,把整份清單一次列完 —— 少的就是 `Top`。

### 三、★ 游標黏在正中間(第 4 列)

上移那段迴圈的形狀是這樣(下移對稱,多一個「清單比視窗短」的條件):

```c
for ( 步數 ) {
    if ( j == 4 || j == 1 ) {
        if ( 上面還有東西 ) { a1 = 前一項; continue; }   // 捲視窗,j 不動
        if ( j != 4 )       { continue; }                // j==1 且到頂 → 空轉
    }
    --j;                                                 // 游標在視窗裡往上
}
```

`j == 4` 那個常數就是規則:**游標走到七列的正中間就停住,改成捲動視窗**;
只有靠近頭尾捲不動了,游標才自己在視窗裡走(所以開頭是 1→4、結尾是 4→7)。
這是「游標置中」的清單瀏覽器,1988 年就寫在裡面了。

### 四、★ 不繞回 —— 又一個「量自己發明」的測試

到頂 / 到底時 `sub_1E3D8` / `sub_1E418` 回 −1,那一步**空轉**,游標留在原地。
引擎原本的 `PickMove` 會繞回,而 `TestPickMoveWraps` 每次都綠 ——
因為它量的是我自己加的行為。已改名 `TestPickMoveDoesNotWrap` 並反向釘住。

(這是本專案第三次踩到同一個形狀:調藥的咒語選單、`W` 指令、現在是選單繞回。
**自己加的行為寫成測試,測試永遠不會告訴你原版沒有這件事。**)

### 五、★ 捲動指示的三個箭頭

畫完清單之後有一段一直沒人看:

```c
v13 = 0;
if ( sub_1E3D8(a1, …) != -1 ) v13 = 2;                    // 上面還有
if ( i != -1 && sub_1E418(i, …) != -1 ) ++v13;            // 下面還有
switch ( v13 ) {
  case 0: sub_28F80();     break;   // 都沒有 → 清掉
  case 1: sub_29008(25);   break;   // ↓
  case 2: sub_29008(24);   break;   // ↑
  case 3: sub_29008(18);   break;   // ↕
}
```

25 / 24 / 18 是 **CP437 的 ↓ / ↑ / ↕**(0x19 / 0x18 / 0x12)——
三個數字一次全部對上一組現成的字元,幾乎不可能是別的意思。
落地成 `PickScrollHint()` 回 `↓ / ↑ / ↕ / 空`,擺在標題列後面
(原版畫在清單旁邊;這裡受 CJK 版面限制換了位置,是版面不是機制)。
