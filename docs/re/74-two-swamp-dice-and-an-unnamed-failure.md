## 1. ★★ 沼澤有兩個中毒判定,而 `docs/re/70` 只找到一個

`docs/re/70` 寫沼澤中毒時讀的是 `sub_1318`(每回合的地形效果)。
`sub_10BDC` 在截斷清單上**獨立列著**,字串是 `Poisoned!` —— 當時沒把兩者聯想到一起。

兩支的條件**完全相同**:

```
腳下 tile == 4(沼澤)、byte_3E08C == 0x1C(步行)
逐個隊員各擲一次;狀態 'D' 或 'P' 跳過
擲贏敏捷 → 狀態 = 'P'、印 "Poisoned!"
```

**只有骰子的範圍差一格:**

| 出處 | 由誰呼叫 | 骰子 |
|---|---|---|
| `sub_10BDC` | `sub_2D9D0`(移動之後) | `sub_28E14(1, 1Eh)` = **random(1, 30)** |
| `sub_1318` 自己那一段 | `sub_1A54`(主迴圈,每回合) | `sub_28E14(0, 1Dh)` = **random(0, 29)** |

⇒ **踏進沼澤的那一步會被擲兩次**(先移動後的分派,同一回合再地形效果),
之後每站一回合擲一次。**「走進去」比「站著」危險一倍。**

### 那一格之差**改變機率**,不能統一

| 敏捷 | 每回合(0..29) | 踏進去(1..30) |
|---|---|---|
| 29 | **永遠免疫**(29 > 29 不成立) | 1/30 會中 |
| 30 | 免疫 | 免疫 |
| 0 | 29/30 | **30/30 必中** |

兩顆骰子的範圍不同幾乎可以確定是原作者的手誤 —— 但 `CLAUDE.md` §3.0
說得很清楚:**不自行平衡**。照原樣兩顆分開實作,
`TestSwampHasTwoSeparatePoisonRolls` 用敏捷 29 把差異釘住
(那個值是**唯一**能區分兩顆骰子的敏捷)。

### 另一個差異:位置閘門

`sub_2D9D0` 開頭有 `cmp byte_3E0A3, 0; jnz → 跳過`,所以**踏進去那顆只在大地圖擲**;
`sub_1318` 沒有這個限制(它讀 `sub_DB10(X, Y)`,場景裡的沼澤照樣毒)。

### ★ 這個形狀值得記

> **同一個機制被兩支函式各做一半,是這個執行檔的常見形狀。**

已知的三例:

| 機制 | 兩處 | 差異 |
|---|---|---|
| 沼澤中毒 | `sub_10BDC` / `sub_1318` | 骰子 1..30 vs 0..29 |
| 戒指消失(`docs/re/72`) | `sub_1EC34` / `sub_2EE84` | 骰值 `== 0` vs `== 11` |
| 擦傷(`docs/re/67`) | `sub_B9A8` / `sub_B51C` | 只對隊員 vs 對任何目標 |

⇒ 找到一處之後要問:**「還有誰做同一件事」**。三例都是「先找到一半、
後來才撞到另一半」,而三次都是靠**全檔掃同一個字串或同一個全域**找到的。

## 2. `sub_1F570` —— 一支函式,兩種落空

```asm
sub_1F570(攻擊者):
    if (byte_3E09F != 0) 印 "Failed!"          ; ★ 不提是誰
    else { sub_1F528(攻擊者); 印 " missed!" }   ; 印名字
```

`byte_3E09F` 是「這一擊是第幾圈的咒語」:`sub_1994C` 施法時設成圈數(1..8),
武器攻擊是 0。而 `sub_B484`(命中骰)也讀它 —— 咒語與武器走**不同的必中清單**:

```
byte_3E09F != 0(咒語):攻擊碼 0x30 / 0x31 / >= 0x33 必中
byte_3E09F == 0(武器):攻擊碼 0x23 / 0x27 / 0x28 必中   ← 引擎的 AlwaysHitWeapons
```

`sub_1F528(unit)` 印名字:隊員(`flags & 0x80`)查名冊,怪物查 `off_3F564[生物]`。

⇒ **咒語落空在原版是一句不具名的「失敗了」。** 引擎原本印
`<目標名>擋下了咒語。` —— 那把因果講成了**目標的功勞**,而原版沒有那個意思。
訊息已改成 `MsgFailed`,並與 `Cast()` 裡原本寫死的「失敗!」統一成同一個常數。

⚠ 咒語的必中清單引擎早就有(`u5data.AttackAlwaysHits`),武器那三個也有 ——
所以這一條**只有訊息的歸屬錯了**,機率沒錯。這種「機制對、敘事錯」的落差
不會有任何測試抓到,只能靠讀原版的字串。

## 3. 還沒讀的

- ⬜ `sub_B484` 的第三個參數:咒語路徑傳 `−圈數`、武器路徑傳武器編號,
  而 `sub_B398(unit, code)` 用 `−1` / `−2` 選「查哪一項數值」。
  引擎的 `attackValueOf` 有鈍器看力量那一條,但 `−1` 與 `−2` 的分野未逐條對照。
- ⬜ `sub_2B740(1)`(`sub_10BDC` 之後緊接著呼叫)在截斷清單上被標成繪圖,未讀。
- ⬜ `sub_10BDC` 走的是 `byte_3E06B`(隊伍人數)而不是 `CombatPartySlots` 的 6 ——
  兩者在滿隊時相同,但隊伍人數上限是否真的能超過 6 未查。
