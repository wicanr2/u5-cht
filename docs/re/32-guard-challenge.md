## 1. 問題問錯了

README 上原本掛著這一條:

> **什麼事會惹毛衛兵還沒接**。逮捕本身完整了,但「偷竊 / 攻擊平民 → 衛兵敵對」
> 那個判定還沒對上原版的哪一支。

去找「偷竊判定」找不到,是因為**原版沒有那種東西**。答案不是一個行為偵測器,
而是**對話號碼**:排程表裡對話號碼是 `0xFF` 的那些 NPC 就是會攔人的衛兵。
走過去跟他說話(或被他攔下),他就開口要東西 —— 給不出來才逮捕。

`sub_1B52C` 的分派把三個特別號碼排在一起,一看就清楚:

| 對話號碼 | 反應 | 原版 |
|---|---|---|
| `0x00` | 「無人回應。」 | 直接印 |
| `0x01`–`0x7F` | 一般對話腳本 | `sub_1C840` |
| `0x80`–`0xFC` | 商店 | `ForDialogue` |
| `0xFD` | 「別傷害我!」 | 直接印 |
| `0xFE` | 「滾開,害蟲!」**說完就跑掉** | `sub_154C` → `sub_B98` |
| `0xFF` | **攔人盤查** | `sub_1B3D0` |

引擎原本把 `0xFE` 與 `0xFF` 一起當成「無人回應」帶過 —— 兩個都錯,
而且錯得看不出來:玩家只覺得這些人特別木訥。

## 2. 三種盤查(`sub_1B3D0`)

三段是 **if / else if / else**,依地點分派,不會疊加:

```
if (地點 == 0x12) {                      // 18 = 黑棘的宮殿
    if (byte_3E08A != 0x1D) return 抓;   //   沒戴徽章,連問都不問
    問「拿出通行密語來,佩徽章者!」
    讀入最多 14 字
    if (!完整相等(輸入, "IMPE")) return 抓;
    印「過去吧,朋友!」
    return 過;
}
if (地點 == 5) {                          // 米諾克
    印「汝須捐出半數家財行善!」
    if (答不) return 抓;
    gold /= 2;
    return 過;
}
貢金 = 0;
for (i = 0; i < 隊伍人數; i++)
    if (角色[i].狀態 != 'D') 貢金 += 10;   // 死人不算
印「衛兵索取 <貢金> gp,說是給黑棘的貢金!」
if (答不)         return 抓;
if (gold < 貢金)  return 抓;              // ⚠ 願意但沒錢,一樣抓
gold -= 貢金;
return 過;
```

三個細節容易漏:

**「我願意但沒錢」不是理由。** 答了「願」還是要過金額那一關
(`cmp eax, esi; jb loc_1B522`),不夠就抓。原版在這裡**不多說一句話**,
玩家只會看到自己突然被逮捕。

**死掉的隊員不用繳。** 迴圈判的是 `byte_3DDBF[i*32] != 'D'` ——
角色紀錄位移 11 的狀態欄,`'D'` 是死亡。抬著屍體走不必為他付人頭稅。

**米諾克要的是比例不是人頭。** 措辭是「捐給慈善」(`to charity!`),
金額卻是**一半家財** —— 隊伍幾個人都一樣。名義上跟別處不同,做的事一樣。

## 3. 密語是 `IMPE`,而且是完整相等

`sub_1B140(needle, typed)` 兩邊都先清最高位元再轉大寫,然後**逐字元比到底**:

```
loc_1B176:  cmp byte ptr [edi], 0
            jnz short loc_1B14C       ; needle 還沒完 → 繼續
            cmp byte ptr [esi], 0
            jnz short loc_1B14C       ; typed 還沒完 → 繼續
            mov eax, 1                ; 兩邊同時結束才算過
```

**兩邊要同時碰到結尾。** 這與對話關鍵字那一套(`sub_27C98`,截到 9 字的
**詞首**比對)是兩套不同的規則 —— 混用的話 `IMPERA` 會被判成通過,
而玩家永遠不知道自己其實打錯了。

字串本身兩版一致,沒有被截短:

| | |
|---|---|
| FM Towns `WORRIORS.EXP` | `aImpe db 'IMPE',0` |
| DOS `DATA.OVL` 0x4AAA | `IMPE` —— 前後都是 NUL,獨立一筆 |

⚠ **[HARD] 密語維持英文**。提示句可以譯,答案不行 —— 譯成中文玩家就打不出來
(同力量之言、真言、`Yes/No`)。

## 4. 徽章與戰鬥模式咒語共用同一個位元組

戴上黑棘徽章時原版做的是:

```
mov byte_3E08A, 1Dh        ; 「戴著徽章」
mov byte_3E09E, 0FFh
```

而 `byte_3E08A` 平常放的是**戰鬥模式咒語**的字母 ——
In Sanct `'P'`、Rel Tym `'Q'`、Quas An Wis `'C'`、In An `'N'`、An Tym `'T'`。

也就是說:**戴著徽章時施那些咒語會把徽章「脫掉」**,反過來也一樣,
而遊戲不會提示。下一次走到黑棘宮殿的衛兵面前,他不會問密語,直接抓人。

這是原版的共用儲存,照抄(同 `docs/re/28` 的末日位元與地點 29 共用)。
`TestTheBadgeSharesItsByteWithCombatModeSpells` 釘住這個行為,
免得日後有人「順手」把徽章拆成獨立欄位。

## 5. 攻擊衛兵也是走逮捕,不是直接開打

`sub_195C` 是「對某個 NPC 動手 / 撞上去」的入口:

```
if (指令 == 'a') {                        // 攻擊
    if (對話號碼 == 0xFE) { sub_154C(); goto 收尾; }
    if (生物編號 == 0x70) goto 逮捕;      // ★ 衛兵
    開打旗標 = 1;
    goto 收尾;
}
if (arg_0 != 0)          goto 逮捕;
if (對話號碼 == 0)       return;
if (!sub_1B52C(npc))     return;          // 對話;回非 0 才逮捕(= 盤查沒過)
逮捕:
    開打旗標 = sub_1884();                 // 回 1 = 玩家拒捕
收尾:
if (開打旗標) {
    if (生物編號 >= 0x40) { 印 "Attacked!"; sub_C74(npc); }
    else sub_268(npc);
}
```

所以**揮刀砍衛兵不會馬上開戰**,而是先聽他說「汝被逮捕了!汝束手就擒否?」——
答「不」才打起來。引擎原本就這樣做了(`npcContact`),這裡只是把證據補齊。

## 6. 「滾開,害蟲!」之後(`sub_154C` → `sub_B98`)

對話號碼 `0xFE` 的人被搭話時,說完那句就跑掉:

```
對話號碼 = 0xFD;                    // 改成「怕你」
行為型別[0..2] = 3;                 // 逃跑
```

⚠ **兩個前提,少了會讓不該跑的東西也跑**:

1. 生物編號要在 `0x40..0x73` —— 是人,不是動物或怪物;
2. **原本就是 `0xFE`、或本來有排程**(`sub_B98` 開頭掃四個時刻)——
   是這座城的居民,不是路過的。

第 2 點的「有排程」判斷與 `docs/re/28` 的暗影君主影響用的是同一個條件,
兩處現在共用 `NPCSchedule.Scheduled()`。

## 7. 還沒接的一段

`sub_195C` 的 `arg_0` 由 `sub_1A54` 傳 `esi - 1`,`arg_0 != 0` 會**跳過對話直接逮捕**。
`esi` 是什麼還沒追(它在 `sub_1A54` 更上面產生)。目前引擎只實作
「說話 → 盤查」與「攻擊衛兵 → 逮捕」兩條路;若 `arg_0` 代表的是某種
「被當場抓包」的情境,那會是第三個入口。

在追出來之前**不猜**——標在這裡,不寫進程式。
