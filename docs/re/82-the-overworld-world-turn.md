## 1. `sub_2E24` 的全貌

```
if (byte_3E08A == 'T') return 0                 ; An Tym → 整個跳過
if (byte_3E08A == 'Q') { byte_4FDD5 ^= 1; if (set) return 0 }   ; Rel Tym 隔次
if ((byte_3E08C & 0FEh) == 12h || == 14h) { byte_4FDD7 ^= 1; if (set) return 0 }  ; 馬/魔毯隔次
                                                 ; ↑ 這三道已實作(`docs/re/81`)
門檻 = sub_1F98()
if (random(1, 30) < 門檻) sub_2218()             ; ★ 生怪
for (i = 0x1F; i > 0; i--)                       ; ★ 倒著掃,槽 0 是隊伍
    if (sub_22B0(物件[i].tile))
        esi += sub_25F0(i)                       ; 讓牠動 / 攻擊
        if (esi == 0) sub_2D38(i)                ; ★ 沒出事才漂流(風 / 水流)
for (i = 0x1F; i > 0; i--)                       ; ★ 第二趟:清場
    if (sub_22B0(物件[i].tile))
        dx = (物件[i].x - byte_3E0AB) & 0FFh
        dy = (物件[i].y - byte_3E0AC) & 0FFh
        if (dx > 0x1F || dy > 0x1F) sub_2B6C8(0,0,0,0,0,0, i)   ; 清掉
return esi
```

★ **`esi` 一旦非零,後面的槽就不再漂流** —— 但**仍然會動**(`sub_25F0` 照呼叫)。
兩件事不同層:出事了就不再算風與水流,而移動照舊。

★ 距離用 `& 0xFF` 算,所以是**環繞感知**的;基準是 `byte_3E0AB`/`byte_3E0AC`
(不是隊伍座標 `byte_3E0A6`/`byte_3E0A7`)—— 那對值是**載入視窗的角**,
所以「離開視窗 0x1F 格」才是清場條件。

## 2. ★★ 遭遇門檻(`sub_1F98`)—— 白天的草地在原版也不會遇敵

```
if (byte_3E0A5 > 7Fh) return 3            ; ★ 幽冥界(樓層為負)→ 固定 3,不加夜間
tile = tile(隊伍腳下)
if (0x20 <= tile <= 0x26)  esi = 0        ; ★ 這一族地形完全不生怪
else if (tile == 4 || 9 <= tile <= 0x0F) esi = 2    ; 沼澤、林 / 丘 / 山
else                        esi = 1
if (byte_3E08F >= 0x20 || byte_3E08F < 5) return esi + 3    ; ★ 凌晨 0–4 點 +3
return esi
```

判定是 `random(1, 30) < 門檻`(`cmp eax, ebx; jge → 跳過`)。所以:

| 地形 | 白天門檻 | 白天機率 | 凌晨門檻 | 凌晨機率 |
|---|---|---|---|---|
| 0x20–0x26 那族 | 0 | **0** | 3 | 2/30 |
| 沼澤 / 林 / 丘 / 山(4, 9–15) | 2 | 1/30 | 5 | 4/30 |
| 其餘(含草地) | 1 | **0** ← 見下 | 4 | 3/30 |
| 幽冥界(任何時刻) | 3 | 2/30 | 3 | 2/30 |

⚠⚠ **門檻 1 等於不會發生。** `random(1, 30)` 的最小值是 1,而條件是**嚴格小於** ——
`1 < 1` 不成立。⇒ **在草地上走路,白天永遠不會有隨機遭遇**;要遇敵得走進
沼澤 / 森林 / 丘陵 / 山區,或者等到凌晨。

這條修正了 `docs/re/81` 的措辭(以及那個 commit 的訊息):引擎缺的不是
「草地上的遭遇」,而是**沼澤 / 林 / 山 / 凌晨 / 幽冥界的遭遇** ——
差別在「該補多少」上很大,而如果照著「草地也要生怪」寫,
就會做出一個比原版兇的世界。

★ `byte_3E08F >= 0x20` 那一條是**死碼**(小時只到 23)。照原樣留著,不要「優化」掉。

## 3. 哪一槽算生物(`sub_22B0`)

參數是**物件記錄的第 0 個位元組**,不是地圖 tile。

```
0x2C..0x2F        → 1
0x30..0x7F        → 0
0x80..0xB3        → 1
0xB4..0xB7        → 0      ★ 四個信物(`docs/re/59` 的 0xB4–0xB7)
0xB8..0xE7        → 1
0xE8..0xEB        → 0
0xEC..            → 1
```

⚠ 引擎的 `MapObject.IsCreature()` 判的是 `Kind >= ObjCreatureBase && Kind != ObjSpecialFC`
—— **與這張表不同**(分歧點是 0x40:那一支算生物,這一張不算)。
所以另開了 `u5data.IsCreatureTile`,兩支並存、各有出處,`TestIsCreatureTileIsNotTheSameAsIsCreature`
把分歧點釘住,免得下一輪有人「順手」合併。

## 4. 生怪(`sub_2218`)

```
for (i = 0; i < 0x80; i++) {              ; ★ 最多試 128 次
    sub_215C()                            ; 挑候選座標 → word_3E086 / word_3E088
    kind = sub_203C(tile(候選), X, Y)     ; 依地形選一種怪;0 = 這裡不行
    if (kind == 0) continue
    if (kind != 0x2C) break
    if ((tile & 0xF0) == 0x60) break      ; ★ 0x2C 只能生在 0x6x 那族水上
}
if (i == 0x80) return                     ; 128 次全敗 → 這回合不生
slot = sub_2B57C()                        ; 找空槽
sub_2B6C8(kind, kind, X, Y, byte_3E0A5, 0, slot)
if (kind == 0x2C) 物件[slot] 的 +5 = 0x64     ; ★ 100
```

★ `+5 = 100` 這一筆自己說明了 `0x2C` 是什麼:`docs/re/11` 記過物件槽的
**+5 是船的耐久**(上下船之間保住的那個欄位)。⇒ **`0x2C` 是船,滿耐久 100**,
而且只生在水上 —— 也就是**海上的敵船**。不是「某種叫 0x2C 的怪」。

✅ **第二個佐證到手了**(§5):`0x2C` 是**水域・地表**那張表的最後一筆,
權重 34/256 = 13.3% —— 它只從水域那條路被選出來。兩條證據獨立命中同一個結論。

## 5. 怪種表(`sub_203C` + `sub_2008`)—— ★★ 四張表的權重都恰好 256

```
if (tile < 4 || 0x60<=tile<=0x6F || 0xD4<=tile<=0xD7 || 0xE4<=tile<=0xE7) {   ; 水路
    if (random(0, 0x40) >= 0x10) return 0        ; ★ 只留 16/65 ≈ 24.6%
    if (地表) {
        if (tile == 1 && random(0, 7) == 7) return 0xEC   ; 深水 1/8
        return byte_4FD30[sub_2008(dword_4FD4C)]
    }
    return byte_4FD35[sub_2008(dword_4FD50+1)]
}
                                                  ; 陸路
if (tile == 7)  return random(0,3) == 0 ? 0xE0 : 0            ; 焦灼荒漠 → Sand Trap 1/4
if (tile == 4 && byte_3E0A5 == 0FFh) return 0xF8             ; 幽冥界沼澤 → Rot Worm
if (tile == 0x0C || tile == 0x0D) return 0                   ; 山 / 高峰不生
if (tile >= 0x10 && (tile & 0xFC) != 0x30) return 0          ; 只有 0x30..0x33 例外
if (地表) return byte_4FD1C[sub_2008(dword_4FD38)]
return byte_4FD28[sub_2008(a88)]
```

`sub_2008(權重表)` 是典型的加權抽樣:`r = random(0,0xFF)`,
`while (表[i] <= r) { r -= 表[i]; i++ }; return i`。**沒有邊界檢查** ——
它靠「權重加起來剛好 256」保證走不出去。

### 四張表(★ 權重和都是 256,這是配對正確的硬佐證)

**陸地・地表**(`byte_4FD1C` + `dword_4FD38`)—— 順序本身就是難度曲線:

| tile | 名字 | 權重 | 機率 |
|---|---|---|---|
| 0xC0 | Orc | 60 | 23.4% |
| 0xC8 | Python | 50 | 19.5% |
| 0x90 | Giant Rat | 40 | 15.6% |
| 0x98 | Giant Spider | 30 | 11.7% |
| 0xBC | Insect Swarm | 20 | 7.8% |
| 0xC4 | Skeleton | 15 | 5.9% |
| 0xD0 | Headless | 15 | 5.9% |
| 0xE4 | Troll | 10 | 3.9% |
| 0xCC | Ettin | 10 | 3.9% |
| 0xD4 | Wisp | 3 | 1.2% |
| 0xDC | **Dragon** | 2 | **0.8%** |
| 0xD8 | **Daemon** | 1 | **0.4%** |

**弱的常見、強的稀有**,最後三筆幾乎見不到。這是設計,不是巧合。

**陸地・幽冥界**(`byte_4FD28` + `a88`):Bat 25% / Giant Rat 21.9% / Giant Spider 21.9% /
Mongbat 12.5% / Corpser 12.5% / Daemon 3.1% / Dragon 3.1%。
⚠ 第八筆是 `0x00` 且權重 **0** ⇒ 選不到。照原樣保留 —— 刪掉它會破壞
「表長度 == 權重表長度」這個一致性佐證。

**水域・地表**(`byte_4FD30` + `dword_4FD4C`):Shark 28.1% / Squid 28.1% /
Sea Serpent 15.6% / Sea Horse 14.8% / **敵船 13.3%**。

⚠⚠ 原版的權重只有**四個位元組**(`48 48 28 26`,和 222)。第五個是
**溢出到下一個變數**取到的:`sub_2008` 沒有邊界檢查,擲到 222 以上時會讀
`dword_4FD50` 的第 0 個位元組 `0x22`(34),而 **222 + 34 = 256**。
這就是為什麼 IDA 把水域幽冥界的表標成 `dword_4FD50+1` —— **+0 屬於上一張表**。

**水域・幽冥界**(`byte_4FD35` + `dword_4FD50+1` = `00 80 80`):
索引 0(Squid)權重 **0** ⇒ 選不到;實際是 50% Sea Serpent / 50% 空手。

⚠ `a88` 被 IDA 命名成字串 `'@88  ',8,8,0` —— 那是**權重表**
(`40 38 38 20 20 08 08 00`)。同 `docs/re/67` 的 `off_48A88`、
`docs/re/77` 的 `aBoxHow`:**`aXxx` 這種自動名字不是資料**,第三次了。

### ⬜ 0xEC 與 0xE8 在 `DATA.OVL` 的名表裡是空的

深水 1/8 那一種是 `0xEC`(名表索引 43),而**索引 42 與 43 兩格都沒有名字**。
`look#236` 給的是「不列顛尼亞的光榮戰旗」——那是**地圖 tile** 236 的敘述,
與物件種類碼 0xEC 不是同一件事,不能拿來當名字。
⇒ 照編號實作、語意留白(`CLAUDE.md §3.0`)。要定案得把 tile 0xEC 切出來看
(需要先抽出 FM Towns 的 `EGA*.TIL`)。

## 6. 落點與槽(`sub_215C` / `sub_2B57C` / `sub_2B518` / `sub_2B6C8`)

**落點**(`sub_215C`):在 32×32 載入視窗裡隨機取,重擲到**兩軸都離隊伍 7 格以上**
(`abs(d) <= 6` 或 `abs(d) >= 0xFA` 都算太近 —— 後者是環繞:−253 其實等於 +3)。
⇒ 怪不會在眼前冒出來。

**找槽**(`sub_2B57C` 十趟串接 → `sub_2B518(lo, hi, 要求遠)`):

| 趟 | 可覆寫的種類碼 | 要求遠 |
|---|---|---|
| 1 | 0x00(空槽) | — |
| 2–5 | 0x01–0x0F 物品 / 0x80–0xFF 生物 / 0x10–0x11 坐騎 / 0x30–0x7F 其他 | ✓ |
| 6–9 | 同上四類 | ✗ |
| 10 | 0x00–0xFF(保證找得到) | ✗ |

★ **先犧牲物品,再犧牲生物**,而前四趟都要求離隊伍 5 格以外
⇒ 玩家眼前的東西不會突然消失。

⚠⚠ 兩個容易漏的:
1. **只掃槽 1..0x17(23)**,而世界回合掃到 0x1F(31)⇒ **高 8 槽是保留區**,
   生怪永遠不會用到,但世界回合照樣處理裡面的東西。**別把兩邊對齊。**
2. **種類碼 0xB5 永不被回收**(`cmp al, 0B5h; jz → 跳過`)。0xB4–0xB7 是四個信物,
   而原版**只保護 0xB5 一個**。看起來像遺漏,但不自行補齊。

**寫槽**(`sub_2B6C8(a0..a5, slot)`):依序寫 +0 tile / +1 tile / +2 X / +3 Y /
+4 樓層 / +5 品質。清場時七個參數全 0,同一支函式當「清掉這一槽」用。

## 7. ★★ 綜合結論:原版的隨機遭遇比印象中稀少得多

門檻(§2)看的是**隊伍腳下**那一格,而判定是嚴格小於:

| 什麼時候 | 會不會遇敵 |
|---|---|
| 白天走在**沼澤 / 林 / 丘 / 山**(4, 9–15) | ✓ 1/30 |
| 白天走在**草地、荒漠、道路**…(門檻 1) | ✗ **完全不會** |
| 白天**航海**(tile 1 或 0x60–0x6F,門檻 1) | ✗ **完全不會** |
| **凌晨 0–4 點**,除了 0x20–0x26 那族 | ✓ 3/30 或 4/30 |
| **幽冥界**任何時刻 | ✓ 2/30 |
| tile 0x20–0x26 那族,白天 | ✗ 門檻 0 |

⇒ **U5 的海上與平原在白天是安全的**,危險集中在崎嶇地形、夜裡與地底。
這解釋了為什麼原版航海感覺平靜 —— 不是遭遇表沒有海怪(有四種加敵船),
是**門檻讓它們白天不會觸發**。

實測(引擎,4000 回合):森林白天 3.4%(門檻 2 → 3.3%)、草地凌晨 9.4%
(門檻 4 → 10%)、幽冥界 6.5%(門檻 3 → 6.7%)、深水白天 **0**。
怪物分佈也逐項對上表(Orc 24.1% vs 23.4%、Daemon 0.7% vs 0.4%)。
