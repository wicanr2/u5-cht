## 1. 三張表

| FM Towns | DOS | 內容 |
|---|---|---|
| `0x46884` | `0x0709` | 48 個咒語名 + `"Frotz"`(NUL 分隔的字串,**不是**指標表) |
| `0x40E7C` | `0x1CA0` | 可施法的場合 48 B |
| `0x40EAC` | `0x1CD0` | 藥草組合 48 B |

DOS 位址是拿 FM Towns 那 48 個位元組去 `DATA.OVL` 裡搜出來的 —— 兩版把整塊
資料原樣搬過去,所以逐位元組相同。

### 圈數

```asm
mov  eax, edi        ; 咒語索引
cdq
mov  ecx, 6
idiv ecx
inc  eax             ; → 圈數
```

**圈數 = 索引 / 6 + 1**,每圈正好 6 個、共 8 圈 = 48。圈數同時是:

- **魔力消耗**(`sub byte_3DDC3[角色*32], 圈數`)
- **最低等級**(`byte_3DDCA[角色*32] < 圈數` → 直接失敗)

一個數字管三件事。所以第 8 圈的 An Tym 要 8 級、扣 8 點魔力。

### 可施法的場合

```
地點 == 0        → 測 0x08   大地圖
地點 > 0x7F      → 測 0x01   戰鬥中(sub_2E364 把 byte_3E0A3 設成 −1)
地點 == 0x12 且 byte_3DFC0 == 0 → 「Absorbed!」
地點 == 0x1D                    → 「Absorbed!」
地點 < 0x21      → 測 0x04   城鎮 / 城堡
其餘             → 測 0x02   地牢
```

值本身就是最好的佐證:

| 咒語 | 場合 | 說得通嗎 |
|---|---|---|
| Rel Hur(改風向) | **只有野外** | 風向只在海上有意義 |
| Uus Por / Des Por(上下樓) | **只有地牢** | |
| Grav Por / Vas Flam / Xen Corp / Kal Xen | **只有戰鬥** | 攻擊與召喚 |
| In Lor(光) | 野外 + 城鎮 + 地牢,**不含戰鬥** | 戰鬥中不需要照明 |
| In Mani Corp(復活)/ Vas Rel Por(大傳送門) | **不含戰鬥** | |
| Mani / An Nox / An Zu / Vas Mani / An Tym | 四處皆可 | |

地點 0x12 與 0x1D 會把咒語「吸收」掉 —— 那是兩個特定場所,是哪裡還沒確認。

### 藥草組合

⚠ **位元順序是反的**。原版 `sub_18704` 用 `mov ebx, 80h` 起頭、每輪 `sar ebx, 1`,
所以**藥草 0(硫磺灰)對應 0x80**,不是 0x01。寫成 `1 << r` 會整個左右顛倒,
而且顛倒之後配方看起來還「有模有樣」——我第一版就是這樣,是拿
「In Lor 只要硫磺灰」去對才發現的。

抽出來的配方與 U5 玩家背了三十年的那份完全一致:

```
In Lor      硫磺灰
Grav Por    硫磺灰 + 黑珍珠
An Zu       人參 + 大蒜
An Nox      人參 + 大蒜
Mani        人參 + 蛛絲
In Wis      顛茄
Kal Xen     蛛絲 + 曼德拉草根
Rel Hur     硫磺灰 + 血苔
In Mani Corp 硫磺灰 + 人參 + 大蒜 + 蛛絲 + 血苔 + 曼德拉草根
```

## 2. 調配(`sub_18704`)

```
玩家挑一個咒語、挑一組藥草、挑份數
★ 先把挑到的藥草各扣掉「份數」               ← 配錯了也不退
if 挑到的遮罩 == 配方遮罩:                    ← 要完全相符
    「Done!」;byte_3E000[咒語] += 份數,上限 99
else:
    什麼都沒有
```

**先扣後判**這個順序是規則的一部分:配錯了藥草就沒了,不能無限試錯。
寫成「判對了才扣」會讓藥草變成沒有成本的資源。

## 3. 施法(`sub_1994C`)

順序不能動,每一關都有自己的訊息:

```
1. 場合對不對                → 「Not here!」      (還沒扣任何東西)
2. byte_3E000[咒語] == 0     → 「None mixed!」    (還沒扣任何東西)
3. ★ byte_3E000[咒語] −−                          ← 從這裡開始都不退
4. 魔力 < 圈數               → 「M.P. too low!)」
5. 魔力 −= 圈數
6. 等級 < 圈數               → 失敗
7. 跑效果(jpt_19B27)
8. 「Success!」/「Failed!」
```

第 3 步在第 4 步**之前** —— 魔力不夠時調配好的那一份已經沒了。第 6 步在
第 5 步之後 —— 等級不足連魔力都扣。兩個順序都不像是失手寫成的,
它們讓「亂試」有代價。

### 干擾(`sub_200BC`)

戰鬥中還有一關,在上面全部之前:

```
byte_3E0B8[施法者] 記著「上一個攻擊我的是誰」
那個人 還活著 且 站在敵方 且 沒被凍住也沒睡著 且 時間沒停 且 距離正好 1
    → 「X interferes!」,咒語發不出去(而且什麼都不扣)
```

只認**上一個打你的那個人** —— 旁邊站著別的敵人不算。所以在戰場上被纏住的
法師要先走開一步或換人擋。

### An Tym 的兩個副作用

1. **敵人整個不動**:`sub_A108` 一開頭 `cmp byte_3E08A, 'T'` 就 return。
2. **火把不會燒**:`sub_29304`(推進時鐘)在時間停止時**整段跳過**光源的
   減法 —— 所以 An Tym 期間點著的火把不耗。這不是小事,U5 玩家在地牢裡
   就是靠這一點省火把。

倒數走在 `sub_16370`,而那是**玩家單位回合結束時**呼叫的 ——
所以 An Tym 是「十個玩家回合」,不是「十分鐘」。

### 光源

`byte_3E0B6`(咒語)與 `byte_3E0B7`(火把)各自是一個分鐘倒數,
`sub_29304(n)` 對兩者做飽和減法。任一非零就看得見,兩個都是 0 → 「darkness」。
點一把火把是 `random(0,15) + 0x70`(`sub_17630`),也就是 112..127 分鐘。

### 還沒追到底的 33 個

其餘的效果函式看得到入口(`sub_18C00`、`sub_18D18`、`sub_18EB0`、`sub_18F2C`、
`sub_1904C`、`sub_19098`、`sub_1D1B8`、`sub_1D31C`、`sub_19264`、`sub_192BC`、
`sub_19440`、`sub_195C0`、`sub_19674`、`sub_196A4`、`sub_19810`、`sub_1986C`、
`sub_1CE70`、`sub_1CE0C`、`sub_1AEB4`…),字串也認得出幾個
(`sub_18D18` 印「Disarmed!」「Chest opened!」= An Sanct 解陷阱、
`sub_1D1B8` 印「Field destroyed!」= An Grav 破除力場、
`sub_1986C` 印「To phase:」= Vas Rel Por 大傳送門),
但**數值與細節還沒逆完,所以沒有實作**。

引擎對這 33 個的處理是:**照原版一樣扣掉藥草與魔力,然後誠實回失敗**,
並在訊息裡寫「此咒語的效果尚未實作」。假裝成功比誠實失敗更糟 ——
那會讓「魔法做完了」變成一句謊。

三個攻擊咒語的傷害也還沒逆到底(`sub_189E4` 只把攻擊碼寫進 `byte_3E0AD`,
實際數值在投射物那一段):**Xen Corp 是必殺**這條確定,
另外兩個目前是按圈數估的,文件與程式碼都標明了是估計值。

## 5. 存檔位置

`byte_3E000`(48 個咒語的調配份數)對應存檔 **`0x024A`**。

推法:同一段記憶體裡 `byte_3DFD0`(裝備)對應存檔 `0x021A`、
`byte_3E060`(藥草)對應 `0x02AA`,兩者的差都是 `0x3DDB6` —— 一致,
所以 `byte_3E000` 對應 `0x3E000 − 0x3DDB6 = 0x024A`。
加進讀寫之後 `SAVED.GAM` 的逐位元組 round-trip 仍然相同,等於再驗一次。

## 6. 玩家輸入

原版問「Spell name:」,玩家把**上古語**打進去(`sub_1CA0C`)。
所以咒語名是玩家要輸入的字串 —— **canonical 值一律維持英文**,
中文只出現在說明裡(`CLAUDE.md` §5.2 的硬規則,u4-cht 踩過)。

引擎的 `C` 鍵開一個輸入列,允許空格(「An Tym」),Enter 送出、ESC 作罷。

## 8. 續:方向選單與最後一批效果(第三輪)

### 方向選單真的接上了

原版每個要方向的咒語都先呼叫 `sub_1CC50`(印「Direction-」讀一個方向鍵)。
引擎先前是「猜一個合理方向」代替 —— 那是介面的近似,現在換成真的選單
(`PromptDirection`)。用得到的:An Ylem、An Sanct、An Grav、In Por、
In Ex Por、An Ex Por、Rel Hur、四種風。

### 召喚:召哪一種是從**通行判定那一行**讀出來的

三支召喚咒語都是「挑空位 → `sub_2EAE4(生物索引, 0, x, y, 樓層)`」,
而生物是什麼寫在它前面那一行的 `sub_9CE8(tile, x, y)` 裡:

| 咒語 | `sub_9CE8` 的參數 | 換算 | 生物 | 隻數 |
|---|---|---|---|---|
| Kal Xen | `0x90` | (144−64)/4 = 20 | 巨鼠 | 1 |
| In Bet Xen | `0xBC` | (188−64)/4 = 31 | 蟲群 | **4** |
| Kal Xen Corp | `0xD8` | (216−64)/4 = 38 | 惡魔 | 1 |

⚠ **同一支函式裡兩個參數用兩套編號**:`sub_9CE8` 吃 tile 碼、
`sub_2EAE4` 吃生物索引。抄錯的話會召出完全不相干的東西。

三支都給新單位 `unit[+2] |= 1` —— 怪物的陣營反轉位元 = **被馴服,站我方**。

### 兩個「嚇跑」其實是同一件事

`sub_18EB0`(An Xen Cor)與 `sub_19810`(In Quas Corp)都是
`or byte ptr [esi+2], 2` —— 那正是 `docs/re/16` 認出來的**逃跑位元**。
兩個咒語效果同一個,差別只在抗性判定與音效。

⇒ 逃跑位元一路串起來了:AI 的「沒有目標就四散」、走出戰場邊緣的撤離、
`sub_16454` 對出界的放行,和這兩個咒語 —— 全是同一個 bit 1。

### Rel Xen Bet(變形)

`sub_195C0`:抗性過了就 `sub_B210(-(目標+1))` 把目標移除,
在同一格 `sub_2EAE4(0x14, …)` 生一個新的。

⚠ `0x14` 那個數字有兩種讀法:當生物索引是 **20 = 巨鼠**(而 `sub_2EAE4`
吃的正是生物索引),當物件種類則是別的東西。兩種都說得通,沒有第三個證據
—— 照數值實作並在程式碼裡標明。

### 這一輪補上的

An Xen Cor、Wis Quas(顯形)、In Bet Xen、In Ex Por(改成問方向)、
Rel Xen Bet、In Quas Corp、Kal Xen Corp。

咒語效果 34 → **41**。

## 9. 續:最後 12 個效果,48/48 收齊(第四輪)

> 輸入檔:`WORRIORS.EXP`(FM Towns,SHA-256 見 `docs/re/00-hexrays-p3-verified.md`)
> 這一輪的方法變了 —— 前三輪是「挑一個咒語去追它的函式」,
> 這一輪先把 **`jpt_19B27` 整張 48 格跳表逐格抄下來**,再逐格對函式。
> 一次看完整張表之後,好幾個原本以為各自獨立的咒語其實共用同一支函式,
> 而漏接的那幾格也一目了然。**先看全表再挑細節,比反過來省事。**

### 9.1 四個 `*Grav` 是同一支函式(`sub_18A08`)

跳表 case 14 / 15 / 16 / 20 全部 `jmp loc_19CBC`,只差事先 push 的種類碼:

| 咒語 | 種類 | 地牢格子 |
|---|---|---|
| In Flam Grav | 0 | `0x82` 烈焰 |
| In Nox Grav | 1 | `0x81` 毒 |
| In Zu Grav | 2 | `0x80` 睡眠 |
| In Sanct Grav | 3 | `0x83` 防護 |

格子編號取自 `byte_55E24`(FM Towns 線性位址 0x55E24,檔案位移 +0x200):

```
byte_55E20:  35 33 34 36 | 82 81 80 83
             └ 戰鬥效果碼 └ 地牢力場格子
```

地牢那條路很短:

```
目標 = 面向的下一格,座標 & 7(8×8 是環繞的)
若 (格子 & 0xF7) != 0 → 失敗       ← 只有純通道放得下,「頭上有洞」那一位元可以留
否則 格子 = (舊值 & 8) | 力場編號
```

**這一段順手推翻了 `docs/re/18` 的一條記載。** 那邊寫「0x80 / 0x89 = 睡眠」,
而 `jpt_52C7`(索引 = 格子 − 0x81,10 格)排出來是:

```
0x80, 0x88 → sub_4DC8  "Sleep spell!"
0x81, 0x89 → sub_4E58  "Poison!"
0x82, 0x8A → "Fire"
0x83..0x87, 0x8B → default,什麼都不做
```

⇒ **0x89 是毒,不是睡眠**;而 In Sanct Grav 放出來的 `0x83` **踩上去毫無效果** ——
它是防護力場,本來就不該傷人。四個力場寫成「都會傷人」是很容易犯的對稱化錯誤,
測試 `TestProtectFieldDoesNothing` 專門擋這個。

錯因值得記:當初是憑「0x80 系列 = 睡眠」的印象往下填,沒把 10 格跳表逐格數完。
**跳表要整張抄,不能抄兩格就推規律。**

順帶修正 `sub_4DC8` / `sub_4E58` 的判定 —— 它們**不是全隊一律中**:

```
每人擲 random(1, 30)
敏捷 > 點數 → 躲掉
狀態已是 'D' 的跳過
```

引擎原本寫成無條件掛狀態,那讓敏捷在這裡完全沒有意義,
而敏捷正是原版在這裡唯一看的東西。

### 9.2 抗性判定(`sub_1F48C`)—— 與命中骰同一套算式,比較方向相反

```asm
cmp edi, 30h ; '0'   ┐
jz  …                │ 攻擊碼 '0'、'1'、>= '3' 一律不擲,直接成立
cmp edi, 31h ; '1'   │
jz  …                │
cmp edi, 33h ; '3'   │
jge …                ┘
call sub_B398        ; esi = 施法者的智力
call sub_B398        ; ebx = 目標的智力
call sub_2B724       ; 1..30
lea  edx, [ebx+1Eh]
sub  edx, esi        ; 門檻 = (目標 + 30 − 施法者) / 2
sar  eax, 1
cmp  eax, [ebp+var_4]
jg   → 回 1(擋下)
```

`sub_B398(單位, −1)` 取的是智力:怪物走 `byte_3F052[生物*8]`
= 生物屬性的第 3 個位元組 = Intel。

**與 `docs/re/16` 的命中公式是同一個形狀**(`(目標 + 30 − 攻方) / 2` 對上 1..30 的骰),
只是命中要「骰 ≥ 門檻」、抗性要「骰 < 門檻」。同一組數字,兩個方向。

配套的是 `sub_189BC`:**編號 14(黑刺)、15(不列顛王)、47(暗影領主)完全免疫**。
六個操控類咒語每一個都是 `!sub_1F48C(…) && !sub_189BC(…)` 這一對。
劇情人物不能被一發二圈咒語處理掉,原版是用寫死的編號擋的,不是靠數值撐。

抗性套用在:An Xen Corp、In Quas Corp、An Xen Ex(魅惑)、Rel Xen Bet(變形)、
In Zu(睡眠風)、In Vas Grav Corp(能量風)。⚠ **火風不擲**(`case 3` 沒有那一句),
毒風走自己的一套(`sub_B398(…, −2)`)。

### 9.3 兩個「嚇跑」不完全是同一件事(修正 §8)

§8 寫「兩個咒語效果同一個,差別只在抗性判定與音效」——**差別不只那樣**:

```
sub_18EB0 (An Xen Corp)  額外要求 word_3F1D0[生物] & 0x20
sub_19810 (In Quas Corp) 沒有這個要求
```

而且**兩支都是 `for i in 0..31` 掃全場的群體法術**。引擎原本寫成「嚇跑最近的一隻」,
那是憑印象補的 —— 組語裡沒有那回事。

0x20 這個位元同時是「傷害減半」(`sub_B51C` 的 `test al, 0x20` → `a2 /= 2`)。
實測全 48 種帶它的是 **幽靈、骷髏、惡魔、暗影領主**。

⚠ 別把它讀成「不死生物」:惡魔不是不死。原版沒有另一張不死表 ——
減傷與可驅離就是同一個位元。程式碼裡叫 `CreatureRepellable`,
按機制命名而不是按傳說命名,就是為了避免下一個人又照字面填。

### 9.4 門與鎖:三支函式、兩套不對稱的規則

| 咒語 | 原版 | 規則 |
|---|---|---|
| An Sanct | `sub_18D18` | `格子 − 1`(0xB9 → 0xB8、0xBB → 0xBA) |
| An Ex Por | `sub_19354` | 0xB8 / 0xB9 → **0x97**;0xBA / 0xBB → **0x98** |
| In Ex Por | `sub_1D15C` | 0x97 → 0xB8;0x98 → 0xBA |

兩個不對稱要記住:

1. **An Sanct 與 In Ex Por 不是同一條規則。** 引擎第一版把兩個都寫成 `格子 − 1`,
   那會讓 In Ex Por 把魔法鎖變成 0x96 —— 一個不存在的格子。
2. **上鎖與解鎖不互逆。** An Ex Por 吃一般門與上鎖門兩種,In Ex Por 只還原成一般門。
   所以「鎖住一扇本來就上鎖的門再解開」會得到一扇沒鎖的門。這是原版行為。

### 9.5 An Ylem(`sub_18C00`)—— 一張 32 格跳表 + 一個特例

```
格子 == 0x5B                    → 消除
格子 − 0x90 落在 32 格跳表裡     → 依表決定
```

跳表命中的是 **0x90–0x93、0x9D、0xA5、0xA6、0xA8、0xA9、0xAD–0xAF**,
其餘走 default(什麼都不做)。命中的一律:

```asm
mov byte ptr [esi], 44h   ; 換成 0x44
push offset aPoof_0       ; "POOF!\n"
```

0x44 是**室內地板**。佐證不是猜的:0x44 在 `TOWNE.DAT` 出現 3,142 次、
`CASTLE.DAT` 3,927 次(兩者都是第二多),而在世界地圖 `BRIT.DAT` **一次都沒有**。
An Ylem 的可施法場合正好只有戰鬥與城鎮 —— 對得上。

### 9.6 In Por(`sub_19098`)—— 戰鬥中是隨機,不是玩家指定

```
戰鬥中 → 最多 7 次隨機落點(sub_B1D8),第一個站得住的就過去
地圖上 → 問方向,往那個方向直線瞬移
```

⚠ 戰鬥中那條**是隨機的**。寫成「傳到想去的地方」會讓它變成一個強太多的咒語。
地圖上的距離是 `byte_3E0AB + 0x20`(上限 0x100),`byte_3E0AB` 還沒追到,
引擎先用固定 32 格並在程式碼裡標明。

### 9.7 In Quas Xen(`sub_196A4`)是複製,不是召喚

`dword_3EF50[空槽] = dword_3EF50[目標]`,連 `dword_3EF54` 一起搬 ——
兩個 dword 整組複製,所以分身的種類、血量、旗標全都一樣。
場上多出來的是**本尊的複製品**,不是新生物。

### 9.8 Wis An Ylem 不是「顯示地圖」

`sub_1CE0C` 做的是 `sub_2E0E8(-1, 0, 0)` —— **把視線遮蔽罩整個填成 0xFF**,
然後重畫 20 幀。也就是「這一瞬間牆壁擋不住視線」,不是永久揭開地圖。

⚠ 引擎目前**還沒有視線遮蔽**(`internal/render` 一律把 11×11 全畫出來),
所以這個旗標現在沒有可見效果。規則記下來了,呈現還沒到 ——
與地牢第一人稱透視同一類的缺口,README 要照實寫。

### 9.9 In Quas Wis(`sub_EDD4`)= 全景

兩層 `for (… < 32; …)` 把周圍 **32×32 格**畫進地圖窗
(`sub_24824(16, 80, 367, 431)` 圈的正是地圖窗),畫完卡在
`while (sub_27034() == 0xFFFF)` 等一個按鍵。是一個**阻塞的畫面**,不是持續狀態。

地牢裡走另一支(`sub_F7C0`):從所在位置向八方泛洪,把整層畫成平面圖。
引擎的地牢畫面本來就是 8×8 俯視全圖,資訊量等同,所以沒有另開模式。

引擎這邊:`PromptPeer` + `drawPeer()`,一格 11 px(352 / 32),
與原版一樣是把 16×16 的 tile 縮進 11 px。

### 9.10 這一輪補上的

## 10. 續:攻擊咒語的傷害在表上,不用估(第五輪)

> 起點是「戰鬥中的力場咒語」這個缺口。追下去卻先修好了另一件事。

### 10.1 那四張裝備表是 **56 筆**,不是 48

`sub_20360` 對隊員取 `byte_3F2F8[效果碼]` 與 `byte_3F330[效果碼]`,
而效果碼是 **0x30..0x36** —— 早就超出「48 種裝備」。

一開始看到這個會以為是自己把索引算錯了。實際上是**表比我以為的長**:
相鄰兩張表的位移差一減就看得出來 ——

```
0x160C 武器傷害  →  0x1644 裝備防禦  差 0x38 = 56,不是 0x30 = 48
0x1644          →  0x1674 武器射程  差 0x38
0x1674          →  0x16AC 裝備類別  差 0x38
```

多出來的 8 筆是**攻擊咒語**:

| 索引 | 咒語 | 傷害 | 射程 |
|---|---|---|---|
| 48 `0x30` | Grav Por | **16** | 15 |
| 49 `0x31` | Vas Flam | **30** | 15 |
| 50 `0x32` | Xen Corp | **99** | 15 |
| 51 `0x33` | In Nox Grav | 18 | 15 |
| 52 `0x34` | In Zu Grav | 0 | 15 |
| 53 `0x35` | In Flam Grav | **21** | 15 |
| 54 `0x36` | In Sanct Grav | 0 | 15 |
| 55 | (空) | 0 | 0 |

⇒ **§4 那句「Grav Por 與 Vas Flam 的傷害是估計值」解決了。** 引擎原本用 10 / 20,
表上是 16 / 30。Xen Corp 的 99 也在表上,與先前「必殺」的結論一致。

> **「這個索引超出表的範圍」不一定是算錯,先量一下相鄰位移。**
> 我把 48 寫死是因為「U5 有 48 種裝備」這個印象,而不是因為量過。

### 10.2 命中判定:只有 Xen Corp 要擲

`sub_B484` 在施法時(`byte_3E09F != 0`)的分支:

```asm
cmp edi, 2Fh ; jle loc_B4AB
cmp edi, 32h ; jl  loc_B4CA   ← 0x30 / 0x31 自動命中
loc_B4AB:
cmp edi, 33h ; jge loc_B4CA   ← >= 0x33 自動命中
             ;                  剩下 0x32 走骰子
```

七個攻擊咒語裡**唯一會失手的就是必殺的那一個**。骰法與抗性判定同一個形狀
(智力對智力、1..30),只是這裡沒有 `sub_189BC` 的免疫名單 ——
**Xen Corp 打得動黑棘與不列顛王**,操控類咒語打不動。兩者不可混用。

### 10.3 戰鬥中的四個 `*Grav` 不是「一片力場」

它們走 `sub_20360` → `sub_20134`,那條路是**射程 15 的指定目標攻擊**,
與弓、弩、火油同一條。命中之後 `sub_B9A8` 有兩個特例:

```asm
cmp byte_3E0AD, 34h ; '4'  → sub_2EDF8(目標)   睡著
cmp byte_3E0AD, 33h ; '3'  → sub_B8DC(目標)    中毒
```

所以:

| 咒語 | 戰鬥中 |
|---|---|
| In Flam Grav | 21 點傷害 |
| In Nox Grav | **中毒**(表上有 18 但走中毒分支,不扣血) |
| In Zu Grav | **睡眠** |
| In Sanct Grav | 追到這裡是 0 傷害、沒有狀態 |

⚠ 只看傷害表會把 In Nox Grav 寫成「打 18 點」—— 那是錯的,
`sub_B9A8` 在扣血**之前**就攔下來了。

In Sanct Grav 那一格沒有下文。若它其實會在戰場上留下力場,那要在
投射物飛行(`sub_1FE54`)裡,還沒讀 —— 引擎照表實作(無效果)並在此標明。
