引擎先前**完全沒有 Get**。後果不只是「少一個按鍵」——

## 2. 兩條路(`sub_15A94`)

```
if (33 <= 地點 <= 40) { 地牢寶箱(§4); return; }    // cmp al,20h/29h
方向 = 問一個方向鍵;取消就結束
目標 = 玩家座標 + 方向增量

// 第一條:那一格上的物件
for (槽 = 1; 槽 < 32; 槽++) {
    座標對不上 → 下一個
    地點 < 0x80 而且樓層對不上 → 下一個
    種類 < 0x10          → 撿
    種類 == 0x19(月石)   → 撿
    種類 == 0x1B(魔毯)   → 撿
    (種類 & 0xFC) == 0xB4 → 撿(碎片 / 王冠 / 權杖 / 寶珠)
    其餘 → **下一個**,不是放棄
}
找到 → sub_154BC(種類, 槽[+5], 槽)

// 第二條:地形
switch (地形) {
  0xB0 / 0xB1  牆上的火把 → 換成磚地、火把時間 = 100、印「借用!」   ← 不扣業報
  0x2D         作物       → 換成 0x2C、糧食 +1、印「作物採收了!」    ← 扣 1 業報
  0x9A/0x9B/0x9C 桌上的食物 → 見 §3                                 ← 扣 1 業報
  其餘         → 「這裡沒有東西可拿。」
}
```

**「其餘 → 下一個」不是「其餘 → 放棄」。** 站在馬旁邊按 Get 不會把馬撿起來,
而是繼續掃後面的槽 —— 同一格疊了兩樣東西時,這決定了撿到哪一個。
寫成 `break` 的話,一隻擋在前面的怪物會讓下面的碎片撿不到。

**物件槽的 +5 是數量 / 品質。** `objects.go` 原本記著
「+5..+7 買馬時清零,但全檔沒有其他讀寫處」——**這條被推翻了**:
`sub_15A94` 就是把 +5 傳給 `sub_154BC` 當數量的,而**是哪一塊碎片
完全由它決定**(`mov eax, edi; and eax, 3`)。四塊 0xB4..0xB7 共用同一段
程式碼,種類碼只分「碎片 / 王冠 / 權杖 / 寶珠」。

## 3. 「偷竊」在原版的定義

三種可拿的地形裡,**只有食物扣業報**:

| 地形 | 訊息 | 業報 |
|---|---|---|
| 0xB0 / 0xB1 牆上的火把 | `Borrowed!` | 不扣 |
| 0x2D 作物 | `Crops picked!` | **−1** |
| 0x9A / 0x9B / 0x9C 桌上的食物 | `Mmmmm...` | **−1** |

所以原版對偷竊的判定不是「有沒有人看到」,而是**拿了誰的東西** ——
牆上的火把是公共設施(而且它特地說「借用」),別人桌上的飯不是。

盤子還有方向規矩(`Can't reach plate!`),而且**只看 Y**:

```
0x9A(北半)  要 dy == 1     目標在玩家南邊
0x9B(南半)  要 dy == -1    目標在玩家北邊
0x9C(整張)  要 dx == 0     東西向搆不著
```

★ **整張桌子被拿走一半之後變成剩下的那一半**,不是直接清空:
從南邊拿 → 剩 0x9B,從北邊拿 → 剩 0x9A。所以同一張桌子可以拿兩次,
業報也扣兩次。

## 4. 地牢寶箱:一樁懸案結掉了

`docs/re/`(與 `chest.go` 的註解)先前記著:

> ⚠ **寶箱的「等級」從哪來還沒逆完。** 這裡先用「深度 × 4」當替代,
> **不是**從程式碼讀出來的。

**答案是:根本沒有那個東西。** 地牢寶箱與地表寶箱是**兩套完全不同的程式碼**:

| | 地表寶箱 | 地牢寶箱 |
|---|---|---|
| 函式 | `sub_15020` | **`sub_15930`** |
| 觸發 | 開箱物件 | **Get(不是 Open)** |
| 等級 | 物件的品質位元組 | **沒有** |
| 骰子 | `random(1,30)` 對門檻 | `random(1, 樓層×4 + 4)` 對門檻 |
| 表 | `ChestThreshold/Max/Kind` | `byte_55DD4/DDC/DE4` |

地牢那三張表(dump 自 0x55DD4 / 0x55DDC / 0x55DE4,各以 0 收尾):

| i | 門檻 | 數量上限 | 種類碼 | 掉什麼 |
|---|---|---|---|---|
| 0 | 2 | 31 | 0x0F | 食物 |
| 1 | 4 | **樓層×8** | 0x02 | 金幣 |
| 2 | 5 | 3 | 0x07 | 鑰匙 |
| 3 | 10 | 3 | 0x08 | 寶石 |
| 4 | 20 | 3 | 0x0D | 火把 |
| 5 | 25 | 7 | 特例 | 藥水(種類 3,數量 `random(0,7)`) |
| 6 | 25 | 7 | 特例 | 卷軸(種類 4,數量 `random(0,7)`) |

⚠ **金幣那一格的表值是 0**,數量另外算(`樓層 × 8`)。照抄查表的話
地牢裡永遠撿不到錢,而且不會有任何錯誤訊息。

★ 因為骰子上限是 `樓層×4 + 4`,**深度直接決定獎品的種類**:
第一層最多擲到 4,只可能有食物(門檻 2)與金幣(門檻 4);
火把要第五層以後,藥水與卷軸要第六層以後。這不是「深層東西比較多」,
是「淺層根本不會出現那些東西」。

### 而且開箱與取物是兩個指令

```
Open(O)  0x4x → (tile & 8) | 0x70    該中的陷阱在這裡中
Get (G)  0x7x → tile & 8             獎品在這裡擲
```

`sub_15930` 對 0x4x 印的正是「得先打開它!」。引擎先前把兩步併成一步 ——
玩家開完箱就自動拿到東西。少了一個指令,而且用的是錯的那張獎品表。

## 5. 順帶對出來的四個存檔位移

`sub_154BC` 各分支寫的全域變數,配上既有的兩個錨點,位移就唯一了:

```
0x0208  byte_3DFBA  火把      ← 已驗
0x0209  byte_3DFBB
0x020A  byte_3DFBC  魔毯      ← Inventory.Carpets 先前記「位移還沒對出來」
0x020B  byte_3DFBD  怪鑰匙    ← §8 解出:品質 ≥ 0x80 的鑰匙走這一欄
0x020C  byte_3DFBE
0x020D  byte_3DFBF  寶珠
0x020E  byte_3DFC0  王冠
0x020F  byte_3DFC1  權杖
0x0210  byte_3DFC4  碎片 4 B  ← 已驗
```

七個位元組對七個變數,**兩端都釘死,沒有排列的餘地**。同法可得
`0x0215 = byte_3DFC9`(圖紙)—— 那一段的兩端是 0x0210 的碎片與
已驗的 0x0219 檀香木盒。

## 6.5 地形碼的目視核對

`sub_15A94` 只給地形**碼**,不給名字。把這幾個碼從 tileset 切出來排成一排,
「拿之前 → 拿之後」的配對自己會說話(`docs/screenshots/18-get-tiles.png`):

| 順序 | 碼 | 畫的是 |
|---|---|---|
| 1 → 2 | 0x2D → 0x2C | 長著作物的田 → **翻過的空田溝** |
| 3 → 4 | 0x9A → 0x95 | 擺著食物的桌子 → **空桌子** |
| 5 → 6 | 0x9C → 0x9B | 整張擺滿的桌子 → **只剩一半** |
| 7, 8 | 0xB0, 0xB1 | 牆上帶火的燭台(兩格一組) |

★ 0xB0 / 0xB1 同時也在**發光地形清單**裡(`docs/re/31` §6)——
兩份獨立得來的表對上同一對碼,而畫出來的確實是火。

⚠ 這一步值得做:第一次用 64px 縮圖目視時我把 0x2C / 0x2D 認成別的東西,
放大到 96px 才看清楚是田。**縮得太小的目視不算核對。**

## 7. 碎片與寶珠擺在哪裡:不在任何資料檔裡

先掃過所有可能的地方,**全部落空**:

| 找過的地方 | 結果 |
|---|---|
| `BRIT.OOL` | 只有槽 0(隊伍自己) |
| `UNDER.OOL` | 五個,種類 0x29 與 0x1E ×4 —— 不是碎片 |
| `DUNGEON.CBT` 的 16 個怪物槽 | 掃 0x0E / 0xB4–0xB7 / 0x19 / 0x1B,零命中 |

答案是它們**不存在於資料裡** —— 進地下世界時由 `sub_10B3C` 當場塞進物件槽:

```
if (樓層 == 0) return;                          // 只在地下世界
if (還沒拿到寶珠)
    槽 28 = 寶珠 @ (105, 225),品質 0xF3
for (i = 0; i < 3; i++) {
    if (byte_3DFC4[i] != 0) continue;           // 已經拿到這一塊
    if (byte_3E0D8[i] >= 0x80) continue;        // ★ 第 i 位暗影君主已被消滅
    槽 29+i = 碎片 @ 表,樓層 0xFF
}
```

座標與品質來自 `byte_55140 + 0x110` 起的三段並列表:

| i | X | Y | 品質 | 碎片 |
|---|---|---|---|---|
| 0 | 192 | 80 | 0xF0 | 虛偽 |
| 1 | 130 | 65 | 0xF1 | 憎恨 |
| 2 | 176 | 184 | 0xF2 | 怯懦 |

★ 品質是 **0xF0 / 0xF1 / 0xF2**,不是 0 / 1 / 2 —— 而 `ShardIndex` 取的正是
低兩位(`and eax, 3`)。兩邊獨立對上,§2 對品質欄的解讀就再確認了一次。

⚠⚠ **第二個條件不能省。** `sub_1A38C` 用碎片消滅暗影君主時,
把碎片**清成 0**(`byte_3DFC4[i] = 0`)同時把 `byte_3E0D8[i]` 設成 0xFF。
擺放條件如果只看「有沒有拿到」,用掉的碎片會在原地重生 ——
玩家可以撿第二次,再去消滅一次已經不存在的暗影君主。

槽號也不是猜的:`dword_3E54C` 與 `3E554h[i*8]` 相對於物件表起點 `dword_3E46C`
是 +0xE0 與 +0xE8,除以 8 得槽 28 與 29..31。

## 8. `sub_154BC` 的完整分支表

先前只實作了「一眼看得懂」的那幾條,其餘回報「汝拿不動那個」。整支讀完之後
補齊,而且有三條與原本的猜測不同:

| 種類碼 | 收到哪裡 | 上限 | 備註 |
|---|---|---|---|
| 0x01 關著的寶箱 | — | — | 「得先打開它!」**而且不清槽** |
| 0x02 金幣 | `word_3DFB6` | 9999 | 數量 = 品質 |
| 0x03 藥水 | `byte_3E038[品質]` | 99 | **品質選顏色**(藍/黃/紅/綠/橙/紫/黑/白) |
| 0x04 卷軸 | `byte_3E030[品質]` | 99 | ⚠ **品質 0xFF 是攻城圖紙,不是卷軸** |
| 0x07 鑰匙 | `byte_3DFB8` 或 `byte_3DFBD` | 99 | ⚠ **品質 ≥ 0x80 走「怪鑰匙」那一欄**,數量取清掉最高位之後的值 |
| 0x08 寶石 | `byte_3DFB9` | 99 | |
| 0x0D 火把 | `byte_3DFBA` | 99 | |
| 0x0E 檀香木盒 | `byte_3DFCD` | — | 另外寫死 `byte_3E3AF |= 0x80`(見 `docs/re/36`) |
| 0x0F 糧食 | `word_3DFB4` | 9999 | |
| 0x19 月石 | `byte_3E050[品質] = 0xFF` | — | 品質是第幾顆 |
| 0x1B 魔毯 | `byte_3DFBC` | 99 | 在地點 17 時 `sub_268(0x16)` —— **沒有** `sub_218` |
| 0xB4..0xB7 | 碎片 / 王冠 / 權杖 / 寶珠 | — | 只有王冠走 `sub_2E0`+`sub_218`+`sub_268` |
| 其餘 ≤ 0x0C | `byte_3DFD0[品質]` | 99 | **品質就是裝備編號**;箭矢(27)與弩矢(29)一次 **+5** |

三條與原本猜測不同的:

1. **圖紙不是自己的種類碼。** 它是種類 4 裡品質 0xFF 的那一筆。當成「種類 4
   一律是圖紙」的話,地牢寶箱掉出來的每一捲卷軸都會變成任務物品。
2. **鑰匙有兩個計數欄。** 沒清最高位的話,一把怪鑰匙會算成 131 把普通鑰匙。
3. **箭矢與弩矢撿一次給五支**,但**買**的時候是直接補滿 99(`sub_11AF0`)。
   兩條路的數量不同,不能共用。

### 順帶對出三個存檔位移

記憶體上 `byte_3E000`(咒語 48 B)到 `byte_3E060`(藥草 8 B)距離 0x60,
而存檔上已驗的 `SaveSpellsOffset = 0x024A` 到 `SaveReagentsOffset = 0x02AA`
也正好 0x60 —— **兩端釘死,中間沒有滑動餘地**:

```
0x024A  byte_3E000  咒語 48 B     ← 已驗
0x027A  byte_3E030  卷軸  8 B     ← 新
0x0282  byte_3E038  藥水  8 B     ← 新
0x028A  byte_3E040       16 B     (未解)
0x029A  byte_3E050  月石 16 B     ← 新
0x02AA  byte_3E060  藥草  8 B     ← 已驗
```

`byte_3DFBD`(怪鑰匙,0x020B)同樣是被 0x0208 火把與 0x020F 權杖夾出來的。
