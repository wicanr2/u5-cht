## 為什麼需要這張表

IDA 只在「有直接參照」的位址上建符號。程式碼寫成

```asm
mov     eax, offset dword_4FFB8
movzx   edx, byte ptr [eax+edi+42B0h]
```

時,被讀的其實是 `0x4FFB8 + 0x42B0 = 0x54268` —— 但 IDA 從頭到尾只看到
`dword_4FFB8`,所以 `byte_54268` **這個名字在反組譯檔裡一次都不會出現**。

筆記裡用 `byte_54268` 稱呼那張表是合理的(位址是唯一不會誤解的名字),
但這樣一來,「筆記提到的 IDA 符號在反組譯檔裡查不到」就同時對應兩種情況:

| 情況 | 意思 |
|---|---|
| 打錯字 / 憑記憶寫的位址 | **斷言壞了**,整條溯源要重做 |
| 從 `base + offset` 算出來的 | 斷言沒問題,只是 IDA 沒取名 |

`tools/check_doc_claims.py` 分不出這兩者。所以第二種**一律登記在本表**,
附上算式;工具把本表當白名單。**沒登記的就是第一種**,要當錯誤處理。

⚠ 反過來也成立:登記在這裡不代表語意判斷正確,只代表**位址算得對**。

## 已登記

### `dword_4FFB8` 為基底的開場動畫並列表(`sub_584B`)

21 頁的開場,每一頁的參數散在九張 0x18 間距的並列表裡。程式先把
`dword_4FFB8` 載進 `eax`,再用固定偏移取用(`docs/re/24`)。

| 算式 | 位址 | 內容 | IDA 有沒有取名 |
|---|---|---|---|
| `0x4FFB8 + 0x4250` | **`byte_54208`** | 文字框(其一) | ✗ 只有本表 |
| `0x4FFB8 + 0x4268` | **`byte_54220`** | 文字框(其二) | ✗ 只有本表 |
| `0x4FFB8 + 0x4280` | `byte_54238` | 文字框(其三) | ✓ 另有直接參照 |
| `0x4FFB8 + 0x4298` | **`byte_54250`** | 文字框(其四) | ✗ 只有本表 |
| `0x4FFB8 + 0x42B0` | **`byte_54268`** | 形狀編號 | ✗ 只有本表 |
| `0x4FFB8 + 0x42E0` | `byte_54298` | 擺放座標 X | ✓ 另有直接參照 |
| `0x4FFB8 + 0x42F8` | `byte_542B0` | 擺放座標 Y | ✓ 另有直接參照 |

八個偏移(`+4250h` `+4268h` `+4280h` `+4298h` `+42B0h` `+42E0h` `+42F8h`)
在全檔各出現 **1 次**,間距一致 —— 這是「同一組並列表」的佐證,
不是我挑出來湊的。
