## 0. 這一輪的性質

而是「做錯了」** —— 我用名字聽起來該有的樣子寫了判定式,而沒有逐 case 讀跳表。

## 1. 紮營解算(`sub_165C8`)

### 1.1 突襲是**每過一個遊戲小時**擲一次

```
主迴圈:每輪 sub_29304(5)(推 5 分鐘)
  小時變了 → random(0, 0x3F) == 0 → 突襲
```

睡九小時 ≈ 9 次 1/64 ≈ 13%。**不是每一步擲一次**,也不是進門就決定。

怪物抽 `byte_3F3C8[random(0,7)]`:

| 索引 | 生物 |
|---|---|
| 41 | Troll 巨魔 |
| 20 | Giant Rat 巨鼠 |
| 21 | Bat 蝙蝠 |
| 24 | Slime 泥怪 |
| 22 | Giant Spider 巨蛛 |
| 25 | Gremlin 小鬼 |
| 36 | Headless 無頭者 |
| 20 | Giant Rat 巨鼠(**再一次**) |

★ 巨鼠出現兩次 → 機率雙倍,不是抄重複了。
這張表與地牢的 `byte_3F3D0` 在執行檔裡緊鄰,而且只差頭尾兩筆
(地牢的收割者與凝視魔換成野外的巨魔與無頭者)。

### 1.2 守夜的意義全在突襲那一刻

```
if (watch >= 0) 全隊 'S' → 'G'      ; 開打前站起來
```

沒人守夜 → 大家還躺著('S')就被打,而睡著的人在戰鬥裡動不了。
**這就是派人守夜的全部理由。**

### 1.3 恢復:三條與旅店完全不同的規則

```
if (byte_3E09C >= 1)   → "No effect..."     ; 休息冷卻
if (時數 <= 5)          → "No effect..."     ; ★ 睡不到 6 小時完全沒用
每個隊員:
    中毒 → 跳過(而且**不會死**)
    死亡 → 跳過
    i == watch → 跳過                        ; ★ 守夜的人什麼都不恢復
    HP += random(1, 63),上限 MaxHP           ; ★ 不是回滿
    MP = (職業 == 'A') ? 智力 : 智力 / 2
random(0,99) < 25 → 老人出現(升級)
byte_3E09C = 0x0E                            ; 冷卻 14
```

我第一版把**旅店**那支(`sub_21D48`:回滿血、中毒者毒發身亡)拿來用,
等於讓野外紮營跟住旅店一樣好,還能連續刷。三條門檻全漏了。

`byte_3E09C` 的遞減在 `sub_29304` 裡 —— **每過一個遊戲小時減 1**
(`sub_2BBFC(&byte_3E09C, 1)`,與火把「每分鐘減」是不同節奏)。而且它在存檔裡。

### 1.4 兩條休息路徑,一條的時刻算法是壞的

```
紮營(sub_165C8): if (小時 + 時數 > 0x17) 減 0x18   ← 24,對
睡床(sub_16BA0): if (小時 + 時數 > 0x17) 減 0x17   ← 23,錯
```

同一個遊戲兩條路,一條對一條錯 ⇒ 那個 off-by-one 是**真的寫錯**,
不是某種刻意設計。兩邊都照抄(CLAUDE.md §3.0),並各有測試釘住。

### 1.5 順帶:睡床什麼都不恢復

`sub_16BA0` 的尾巴只做三件事:全隊 'S' → 'G'、**隊伍 x + 1**(從床上下來往東挪)、
還原音樂。**沒有一行動到 HP 或 MP。**

⇒ 睡床的用途是**讓時間過去**(等 NPC 上班、等商店開門),不是治傷。
憑「睡在床上當然比野地舒服」的直覺去補恢復,就是自創遊戲。

## 2. 地牢搜尋的擲骰(`sub_142EC`)

```
門檻 = (樓層 × 2 + 30 − 敏捷) / 2
擲 random(1,30):**大於**門檻才看得清楚
沒看清楚 → v = random(1,8) 亂猜
看清楚了 → 若地形不是 0x40 → v = **樓層**;否則印 "No trap"
v < 4 → "A simple trap" / v >= 7 → "A complex trap" / 其餘 → "A trap"
```

★ **陷阱的「複雜度」就是樓層數。** 原版查的不是格子裡的什麼欄位 ——
越深的陷阱越複雜。憑「每個箱子有自己的陷阱等級」去實作會多出一個
原版沒有的維度。

⚠ 坑的三種比的是**完整位元組**(`cmp edx, 60h/61h/62h`),不是高四位元。
所以帶「頭上有洞」位元的 0x68 / 0x69 / 0x6A **搜起來什麼都不會說** ——
那三種確實出現在地牢資料裡,八成是原版的漏洞。照抄,並用測試釘住。

力場三句(`jpt_14627`):0x80 睡眠 / 0x81 毒氣 / 0x82 火牆;
**0x83(電擊)刻意沒有訊息** —— 與踩踏分派那條一致(沒人站上去過)。

## 3. ★ 移動模式:四個我寫錯了

逐 case 讀 `jpt_2A6B4` 之後:

| 模式 | 原版判定 | 我第一版寫的 |
|---|---|---|
| 0 一般陸行 | `sub_2A610(移動者, tile)` | 只有位圖 ⚠ |
| 1 只走水 | `sub_2A674(tile)` | ✅ |
| 2 兩棲 | 水 ‖ `sub_2A610` | ✅ |
| 3 坐騎 | `sub_2A610` **&& tile != 4 && tile != 0x8F** | 位圖 && 不是水 ❌ |
| 4 飛行 | **`!sub_2A674`**(非水) | `return true` ❌ |
| 5 小艇 | 水 + **河道流向遮罩** | 只要是水 ❌ |
| 6 大船 | **`tile <= 2`** | `< 3 ‖ 0x6x 那族` ❌ |
| 7 | `tile == 4`(沼澤) | 當兩棲 + TODO ❌ |
| 8 | `tile == 5`(草地) | 同上 ❌ |
| 9 | `tile == 1`(中水) | 同上 ❌ |
| 10 | `tile == 7`(荒漠) | 同上 ❌ |
| default(0xFF) | **擋住** | 當一般陸行 ❌ |

四條的後果都不小:

- **飛行**寫成「什麼都不管」,飛行怪物會直接飛過海洋追殺玩家。
- **大船**放行 0x6x,等於開得進河道 —— 而「大船靠不了岸、得放小艇」
  正是 U5 航海的核心限制。
- **坐騎**多擋的其實是**沼澤**(位圖沒擋它),而馬過不了沼澤會直接改變繞路方式。
- **模式 7–10 是最嚴格的**(只認一種 tile),我當成最寬鬆的(兩棲)。
  對應的移動者是 0xF8 / 0xF4 / 0xEC / 0xE0 那幾組 —— 長在特定地形上的東西
  (沼澤的觸手怪、荒漠的沙陷)。

### 3.1 `sub_2A610` 不只是位圖

```
位圖那一位設起來            → 擋
移動者 & 0xFE == 0x1C(步行) → 過
移動者 & 0xF0 == 0x40        → 過
tile & 0xFC == 0x90          → 擋(只有上面兩種過得去)
```

第三條是本專案早就知道的 `TileNeedsSpecialMover`,但**先前沒接進通行判定**。
少了它,一般怪物會走進那四格「只有特定移動者能過」的地形。

⇒ 新增 `MoverBlocked(移動者, tile)`;`MoverCanEnter` 對模式 0 / 2 / 3 改走它。
`MoveModeAllows(模式, tile)` 保留給只有模式在手的呼叫端,並在註解標明
**對模式 0 / 3 會偏寬鬆**。

### 3.2 tile 0 的怪事

`TileIsWater(0)` 為真(原版 `sub_2A674` 把 0 併進 `< 4`),但**阻擋位圖的第 0 位是 0**。
坐騎判的是位圖 ⇒ **原版的馬踩得上 tile 0**。

我第一版的測試把 0 也列進「馬應該拒絕的水」—— 釘住的是直覺,不是判定式。

### 3.3 小艇:河道是有方向的

```
tile & 0xFC == 0x34          → 查 記憶體[0x5FFA8 + tile] 的方向位元
否則 !水                      → 不行
否則 tile < 0x60              → 直接可以(深水與中水)
否則                          → 查 記憶體[0x5FF6C + tile] 的方向位元
位元 = 8 >> (移動者 & 3)      ← 朝向就是載具碼的低兩位
```

★ 兩個算式**指到同一塊記憶體**:`0x5FFA8 + 0x34 == 0x5FF6C + 0x70`。
所以那是**一張表用兩種偏移讀**,不是兩張表 —— 0x34..0x37 借用了 0x70..0x73 的形狀。

值域是 0x01..0x0E(四個方向位元),tile 0x74..0x7A 為 0(小艇完全進不去)。
⇒ **U5 的河流是有流向的,小艇只能順著走。**

## 4. 戰鬥指令表(`jpt_A5C8`)

戰鬥有自己的分派器 `sub_A360`,與主分派器是兩份程式。

**可用**:A 攻擊 · C 施法 · G 撿 · J 撬鎖 · K 攀爬 · O 開 · P 推 · R 換裝 ·
S 搜尋 · U 用道具 · Y 喊 · Z 數值,加上方向鍵 / ESC / 空白 / '0' / '1'–'6'。

**不可用的每一個都有自己的回應**(`sub_16270(名字, 種類)`):

| 尾綴 | 種類 | 鍵 |
|---|---|---|
| ` what?` | 1 | B 上船、X 下載具 |
| `-Not here` | 2 | E 進入、F 開砲、H 紮營、I 點火把、L 觀察、M 調藥、N 換位、Q 存檔、V 看寶石 |
| `-Funny, no response!` | 3 | T 交談 |
| (只印名字) | 0 | **D**、**W** |
| `What?` | default | 其餘所有鍵 |

★ D 與 W 在這裡也只印 `D-What?` / `W-What?` —— 與主分派器一致,
**兩處獨立佐證它們不是指令**(`docs/re/49` §2)。

⬜ 可用的 G / J / K / O / P / R / S / U / Z 在引擎裡的實作是**地圖版**的:
它們讀世界 / 場景座標,不是戰場座標。接上去會作用在錯的地圖上,
所以目前只接 A / C,其餘列在 `CombatAllowedKeys` 裡等戰場版本。
**硬接會比不接更糟** —— 玩家會看到「有反應但結果莫名其妙」。
