# 指令選單 —— 讓 R / W / N / U / M 按得到

輸入檔:`WORRIORS.EXP`(FM Towns 英文版)
IDA 位址:`sub_1F3A4`(Ready 的「Item: 」)、`sub_1E418`(Use 的「Items:」)、
`sub_18468`(Mix 的「Reagents:」)
日期:2026-08-08

---

## 0. 為什麼這一輪做這個

這五支指令的**規則**早就實作了,但簽章是 `Ready(member, item)` 這種 API ——
鍵盤上按不到。**做完了卻用不到,等於沒做。**

## 1. 五個選單收成一個

原版每支各有自己的畫面,但形狀都一樣:列一排候選、挑一個、可以放棄。
所以引擎收成一個 `Picker`,由呼叫端給標題與候選:

| 鍵 | 流程 |
|---|---|
| R | 挑人 → 挑武器或盾 |
| W | 挑人 → 挑頭盔 / 護甲 / 戒指 / 頸飾 |
| N | 挑第一位 → 挑第二位 |
| U | 挑一件特殊道具 |
| M | 挑一個咒語(照配方各一份) |

### 兩層選單的關鍵:第一層選完**不能關掉**

`beginPick` 的 `then` 回傳 `false` 代表「還有下一步」,由 `then` 自己開下一層。
寫成一律回 `true` 的話,玩家挑完人就沒反應了 —— 而那看起來像選單壞掉。

## 2. 換位的第一層**故意列得出聖者**

原版是讓玩家**選得到**、然後才說「<名字> must lead!」。

⚠ 從清單裡藏起來很容易被當成「更好的介面」,但那會抹掉一條規則:
玩家不會知道「聖者必須帶隊」是設計,只會以為選單漏了人。
**「看不見」與「選了被拒」對玩家是兩種完全不同的訊息。**

## 3. 兩個誠實的取捨

### 字母捷徑沒做

原版用**字母**選(「Item: 」後面按一個字母)。跳表裡看得出來有,
但字母對應哪一項沒逐一核過,所以先只做方向鍵 + Enter
(與主選單、Ztats 一致)。同 `docs/re/45` §5 的原則:沒證據不猜。

### 三件道具無條件列出

望遠鏡 / 六分儀 / 懷錶的「有沒有」旗標存檔位移還沒釘死(`docs/re/44` §4),
所以選單**無條件列出它們**。

列了但沒有,比不列好:效果本身是照原版做的,缺的只是那一格旗標 ——
而藏起來會讓玩家以為這幾樣沒實作。兩種都不對,選看得見的那種。

### 調藥先做「照配方調」

原版讓玩家**自己挑藥草**(`sub_18468`,方向鍵 + RETURN,「Type M to mix」),
挑錯就浪費 —— 那是這個系統的張力。引擎的選單先做「照配方各一份」的捷徑;
亂試配方那條路走 `State.Mix(spell, count, reagents)`,API 還在,規則也還在。
逐味挑選是**介面**工作,不是機制落差。

## 4. 選單只列做得到的

調藥選單只列「至少調得出一份」的咒語。列出調不出來的會讓玩家白挑一次,
而原版的選單也是只列手上有的東西。

## 5. 一條測試自己踩的坑

`TestReadyMenuChainsTwoPicks` 第一版在第二層直接 `PickChoose()`,結果裝上的
不是測試放進背包那把 —— **存檔的背包本來就有武器**,游標停在第一項不見得是它。
要驗「選到的那一件真的裝上了」,得先把游標移到它上面。

第一版的失敗訊息是「武器沒裝上:右手 30 左手 4」,看起來像換裝壞了 ——
實際上換裝是對的,錯的是測試選錯了東西。
