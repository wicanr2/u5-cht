## 0. ★★★ 載入視窗:對齊 16,一次捲半個視窗

引擎此前用「隊伍為中心的 32×32」當近似。真的機制是兩支函式:

### `sub_2CBEC` —— 抵達大地圖時定位一次

```
原點X = 隊伍X & 0F0h
if ((隊伍X & 0Fh) < 8) 原點X = (原點X − 10h) & 0F0h
原點Y = 隊伍Y & 0F0h
if ((隊伍Y & 0Fh) < 8) 原點Y = (原點Y − 10h) & 0F0h
```

第二行是「挑離隊伍最近的那個對齊點」:隊伍落在 16 格區塊的前半就再退一塊。
⇒ **隊伍在視窗裡的位置永遠落在 8..23**(視窗 32 格寬),大致居中。
`TestWindowOriginAlignsToSixteen` 對全部 256 個座標驗這條導出性質。

**呼叫者五個**,都是「抵達大地圖某個座標」:`sub_2DD44`(進大地圖模式)、
`sub_DF84`(月門傳送)、`sub_24DC`(漩渦吸下去)、`sub_19098`(In Por 瞬移)、
`sub_10A1C`(墜落動畫)。

⚠ `sub_1986C`(大傳送門 Vas Rel Por)**自己不呼叫**,但它走 `sub_DF84`,
所以照樣會定位 —— 引擎的 `CastGreatGate` → `TravelByMoongate` 天然對上。

### `sub_2D014` —— 走一步之後只在邊緣才捲

```
在視窗內X = (隊伍X − 原點X) & 1Fh
在視窗內Y = (隊伍Y − 原點Y) & 1Fh
if (5 <= 在視窗內X <= 1Ah && 5 <= 在視窗內Y <= 1Ah) → return      ; 不捲
sub_10878(dx, dy)
原點X = ((dx << 4) + 原點X) & 0F0h        ; ★ 一次捲 16 格
原點Y = ((dy << 4) + 原點Y) & 0F0h
sub_10738(dx, dy) ; sub_2E21C            ; 重載視窗內容 + 重算光照
```

⇒ **一次捲半個視窗,不是跟著走一格。** 這就是原版大地圖走到邊緣時
「畫面整塊跳一下」的來源。`& 0xF0` 對 8 位元運算 ⇒ 原點在地圖邊界自然環繞。

### 這件事為什麼重要(不只是畫面)

生怪落點、月門要不要寫、清場的距離判定**全部以視窗原點為基準**。
近似版與真版的差別是可觀察的:

| | 真視窗 | 「隊伍為中心」近似 |
|---|---|---|
| 走一格 | 原點通常**不動** | 原點跟著走 |
| 生怪的那一圈(離隊伍 ≥ 7 格) | 在同一塊裡落在固定位置 | 永遠貼著隊伍 |
| 怪走遠了 | 視窗沒捲就**不會被清** | 立刻被清 |

### `sub_2DD44` 只在「抵達」時跑,不是每回合

`sub_0` 的主迴圈:

```asm
loc_DF:  mov eax, edi              ; edi = 上一輪的模式旗標
         cmp al, byte_3E0A3
         jnz short loc_F9          ; 地點碼與旗標不符 ⇒ 不重進大地圖
         mov ebx, 1
         call sub_2DD44            ; ★ 只在「剛回到大地圖」跑
loc_F9:  mov edi, ebx
```

`sub_2DD44` 裡呼叫 `sub_2CBEC` **再** `sub_2D9D0`(大地圖迴圈本體),
而 `sub_2D9D0` 自己有迴圈 ⇒ `sub_2CBEC` 一次抵達只跑一遍。
**這一點非驗不可** —— 若 `sub_2CBEC` 每回合都跑,`sub_2D014` 的漸進捲動就毫無意義。

★ 順帶一個發現:`sub_2DD44` 在定位之後會處理 `byte_3EE17` ——
**離開場景時騎著 / 開著的載具要放回大地圖**:找空槽、寫座標、
種類碼取 `byte_3EE17 <= 0x7F ? 0x25 : 0x29`、耐久寫死 **0x63 = 99**。
⬜ 引擎的 `leaveScene` 沒有這一段(現在載具是跟著人一起進出場景的)。

## 1. ★★ 清場:離視窗超過 0x1F 格的**生物**整槽清掉

`sub_2E24` 的第二趟(移動那一趟之後):

```
for (槽 = 1Fh; 槽 > 0; 槽--) {                 ; ⚠ 槽 0 掃不到
    if (!sub_22B0(物件[槽].tile)) continue      ; ★ 只清生物
    if (((物件X − 原點X) & 0FFh) > 1Fh) → 清
    if (((物件Y − 原點Y) & 0FFh) > 1Fh) → 清
    清 = sub_2B6C8(0,0,0,0,0,0, 槽)             ; 六個欄位歸零
}
```

★ 兩個容易做錯的地方:

- **判準是視窗原點,不是隊伍座標。** 視窗不捲的回合,怪走遠了也留著。
- **只清生物。** 少了 `sub_22B0` 這一關,**玩家停在岸邊的船會憑空消失**。

`TestCullingUsesTheWindowNotTheParty` 四個案例:視窗邊界那一格留著
(條件是 `> 0x1F` 不是 `>=`)、再遠一格清掉、船不清、槽 0 不掃。

## 2. ⚠⚠ `sub_2B24` 的第二個參數是死的 —— 影主那條路是**空轉**

`sub_2D38` 的 `0xFC` 分支(`cmp esi, 0FCh`,**精確等於**不是 `& 0xFC`):

```asm
push edi ; call sub_27F0                  ; 11×11 遮罩表
and eax, eax ; jz loc_2E11                ; 遮罩 0 → loc_2E11(push 1)
mov al, 物件[槽].+5 ; inc 物件[槽].+5
cmp al, 14h ; jnb loc_2E11                ; 計數器 >= 0x14 → loc_2E11(push 1)
push 0 ; jmp loc_2E13                     ; 否則 push 0
loc_2E11: push 1
loc_2E13: push edi ; call sub_2B24 ; retn
```

**兩條路都呼叫 `sub_2B24`,只差第一個 push。** 而在 `sub_2B24` 的 253 行裡:

```
讀 arg = 1(只有 mov edi, [ebp+arg_0])
寫 arg = 8(全是 mov [ebp+arg_4], eax)
```

⇒ **`arg_4` 只被寫、從來沒被讀** —— 編譯器把參數槽當暫存變數重用了。
沒有任何 `lea ... ebp`,框架位址也沒外流。

**正對照**:同一支偵測器對 `sub_2870` 找到三個參數讀取(含 `add edx, [ebp+arg_4]`)
⇒ 偵測器有效,`sub_2B24` 的結果不是漏抓(`diagnosis-notes/02`:查詢回空要先做正對照)。

### 結論與代價

- 引擎的 `chaseParty(slot)`(沒有旗標)**是對的**,不必改。
- ⇒ **`sub_27F0` 與那張 11×11 遮罩表不必實作** —— 對行為毫無影響。
- ⚠ 但**有一個副作用**:`inc 物件[槽].+5` 真的執行了。而位移 5 不是計數器,
  是**耐久 / 血量**欄位:`sub_2218` 生怪時寫 0x64 = 100、`sub_16F08` 上船時
  讀它當船體、`sub_17120` 從它扣、`sub_B51C` 用 `or ..., 80h` 放旗標。
  ⇒ **影主待在隊伍附近時,牠的耐久欄位會被慢慢加上去。**
  ⬜ 要不要做,取決於影主的位移 5 拿去做什麼(未追)。先記在這裡。

### ⚠ 更正先前的斷言

`WORKLIST §5.1b` 與 `docs/re/85` 寫「`sub_27F0` 為 0 → 移動;否則 +5 累加到
0x14 之前都不動」—— **錯的**。兩條路都移動,差別只在一個沒人讀的參數。
錯因:看到 `push 0` / `push 1` 分岔就假設「旗標會被用」,沒去確認**有沒有人讀**。

### 遮罩表本身(留檔,不實作)

`byte_4FD98`,索引 `11*|dy| + |dx|`,`|dx|` / `|dy|` 各需 < 6。
⚠ **用 IDC dump 不從 `.asm` 的 `dd`/`align` 手抄** —— 風向表就是那樣抄錯三處的
(`tools/ida_dump_mask.idc`)。

```
      dx: 0  1  2  3  4  5
dy=0:     0  0  1  1  1  0
dy=1:     0  0  0  1  1  0
dy=2:     0  0  1  1  0  0
dy=3:     1  1  1  1  0  0
dy=4:     1  1  0  0  0  0
dy=5:     0  0  0  0  0  0
```

⚠ 它**不對稱**((2,0)=1 但 (0,2)=0)⇒ 不是距離環,語意不明。既然不影響行為,
就不猜。表實體跨過 IDA 另外命名的 `byte_4FDBF` 與 `byte_4FDC7`
(索引 0..60 恰好用到 `byte_4FDD4`)—— 又一次「相鄰表物理重疊」。

## 3. ★★ 敵船開砲

### 條件(`sub_25F0` 尾段)

```asm
kind & 0FCh == 2Ch                  ; 敵船
and esi, esi ; jnz loc_274B         ; esi = |dx|
cmp ebx, 4   ; jl  loc_2754         ; |dx| == 0 且 |dy| < 4 → 開砲
loc_274B: and ebx, ebx ; jnz 出去    ; |dy| != 0 → 不開
          cmp esi, 4  ; jge 出去     ; |dx| >= 4 → 不開
loc_2754: 印 "* BOOOM! *\n\n" ; sub_23FC(槽, |dx|, |dy|) ; return 1
```

⇒ **(|dx| == 0 && |dy| < 4) 或 (|dy| == 0 && |dx| < 4)** —— 正交同線、相隔 1..3。

★★ **沒有機率閘門。** 海蛇與龍的遠程是 1/8(`docs/re/83`),敵船只要對齊就
**每個世界回合都開砲**。這是原版海戰壓迫感的來源;不要「平衡」它。

### 側身(`sub_23FC` 前半)

```
if (|dx| == 0) { 船圖是 2Ch / 2Eh(南北向) → (random(0,3) & 2) + 2Dh }   ; → 東 / 西
if (|dy| == 0) { 船圖是 2Dh / 2Fh(東西向) → (random(0,3) & 2) + 2Ch }   ; → 北 / 南
```

★ **舷側砲垂直於船身** ⇒ 要打正北方的目標,船身得是東西向。這和玩家開砲判舷側
(`isBroadside`)是同一個機制的另一半。左舷右舷是**擲骰**選的。

⚠⚠ **它只寫位移 1(`ObjTile`),不動位移 0(`ObjKind`)。**
對照 `sub_2870`(移動時轉向)**兩個都寫**。後果:

- 風速表查的是 `ObjKind`(`dword_3E46C[槽*8] − 0x2C`)⇒ **側身開砲不影響船速**。
- 下一次移動時 `sub_2870` 會用 `ObjKind` 把 `ObjTile` 蓋回去 ⇒ **不持久**。

⇒ 這個轉向在機制上只影響**那一回合畫面上的船圖**。寫成「連 `ObjKind` 一起改」
會意外改掉船速 —— `TestBroadsideTurnChangesTheTileNotTheKind` 釘住它。

### 傷害

```
命中 = sub_20CB4(視窗內dx, 視窗內dy, 5, 5, 1)      ; 投射物飛行動畫
if (命中) { 重畫; sub_2B1C8(隊伍X, 隊伍Y); sub_22F0() }
```

`sub_2B1C8` + `sub_22F0` 就是引擎的 `DamageShip()`(與海蛇 / 龍的遠程同一對)。

⚠ **唯一的差異**:`sub_20CB4` 是投射物動畫,而它的回傳值代表「有沒有被擋住」。
引擎沒有動畫層 ⇒ **一律命中**。`sub_20CB4` 本身純繪圖(把兩塊 0x100 byte 的
路徑緩衝填 −1,格座標 `<< 4 + 0x10` 換成像素)⇒ ⬜ 不實作。

## 5. 兩個踩到的紅燈

### (a) 「視窗原點」變成真狀態,兩條月門測試就紅了

`TestSteppingOnAMoongateTeleports` 與 `TestMoongateTileIsWrittenAtNightAndErasedByDay`
直接改 `s.X / s.Y` 之後沒有定位視窗 ⇒ `moongateWritesHere` 拿 (0,0) 當原點。
**這不是測試壞了,是測試沒有走真實遊戲的路徑** —— 已補 `resetLoadWindow()`
並在原地寫明為什麼。

⚠ 這也是一個真實的地雷:任何**在大地圖上直接改座標**而不定位 / 捲動的程式碼
都會留下一個過期的視窗。目前六個 `resetLoadWindow` 呼叫點與 `moveInWorld` 的
捲動覆蓋了所有已知路徑;新增傳送類機制時要記得一起接。

### (b) 「兩條路做同一件事」是否定結論,所以做了正對照

見 §2。**否定結論要證明偵測器抓得到肯定案例**,不然「沒找到」與「不存在」分不出來。
