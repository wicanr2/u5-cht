# 終極智慧之寶典,以及聖壇與寶典共用的那間石室

> 輸入檔:`org_game/fmtown/…/U5_E/WORRIORS.EXP`
> 位址:`sub_1DA10`(進場)、`sub_1D850`(寶典)、`sub_1D394`(冥想,見 `docs/re/25`)
> 日期:2026-08-07

`docs/re/25` 把聖壇解完之後留了一句「寶典還沒逆,所以引擎暫時把兩個位元一起設」。
這一份把那個簡化拿掉了 —— 順帶發現聖壇與寶典共用同一支進場函式。

## 1. 兩組位元怎麼銜接

| 位元組 | 誰設 | 意思 |
|---|---|---|
| `byte_3E0DC` | **聖壇**(`sub_1D394`)| 這一德的試煉進行中 |
| `byte_3E0DE` | **寶典**(`sub_1D850`)| 這一德的答案已經在寶典上讀到 |

聖壇的三條路(`sub_1D394` 尾段)判的是 `byte_3E0DE`:

```c
if (!(byte_3E0DE & bit))      → 發試煉(只設 byte_3E0DC)
else if (byte_3E0DC & bit)    → 給獎賞(清 byte_3E0DC)
else                          → 只能捐錢
```

⚠ **所以「去寶典」是拿獎賞前必經的一步。** 少了寶典這一段,第一次拜壇之後
`byte_3E0DE` 永遠是 0,第二次來又被當成「第一次」重新發試煉 —— 獎賞永遠拿不到。
引擎在寶典做出來之前是把兩個位元一起設的,效果反過來變成「拜兩次就領獎」。
兩種錯法方向相反,但都是同一個原因:把兩個旗標當成一個。

## 2. 寶典本身(`sub_1D850`)

```c
key(); puts(#37); key(); puts(#38); key();
for (i = 0; i < 8 && !(byte_3E0DC & (1 << i)); i++) ;   // ★ 由小到大,停在第一個
if (i == 8) { puts(#39 "HOW DID YOU GET HERE?"); return; }
byte_3E0DE |= 1 << i;
putchar('"'); puts(答案[i]); puts("\"\n\n"); key();
if (byte_3E0DE != 0xFF) return;
…畫面變色三次…
puts(#40 "A STRANGE WIND CAUSES THE PAGE TO TURN!"); key();
puts(#41); key(); puts(#42); key(); puts(#43); key(); puts(#44); key();
```

⚠ **找的是索引最小的那一項**,不是最後領的。同時開兩項試煉時,寶典先給編號小的。

⚠ **四段符文沒有防重播的旗標** —— 就只有 `cmp byte_3E0DE, 0FFh`。
「只看得到一次」是**流程逼出來的**:八德都領過之後聖壇不會再發新試煉,
所以再來寶典時 `i == 8`,連那一行都到不了。照抄成「加一個播過旗標」會
在只有改存檔才做得出來的狀態下行為不同。

## 3. ★ 那些「寫死的字串指標」其實是 `MISCMSG.DAT`

`sub_1D850` 取答案的算式是 `byte_54700 + dword_5604C[i]`,而 `byte_54700`
不是靜態字串表 —— 它是 BSS 裡的緩衝區,由進場函式填:

```asm
push 3ABh                       ; 檔案位移
push 7D0h                       ; 讀 2000 B
push offset byte_54700
push offset aMiscmsgDat_0       ; "MISCMSG.DAT"
call sub_2C740
```

0x3AB 正好是 `MISCMSG.DAT` **第 12 筆記錄**的開頭。於是:

| 表 | 值 | 加上 0x3AB 之後 |
|---|---|---|
| `dword_5602C` | 0, 27, 57, 95, 123, 159, 185, 214 | 第 **12..19** 筆(「去寶典學 X」) |
| `dword_5604C` | 256, 334, 393, 468, 555, 639, 704, 784 | 第 **20..27** 筆(八段箴言) |

八個位移全部落在記錄開頭,一個不差 —— 這不是湊的,是兩份獨立資料對上。
`internal/u5data/text.go` 為此在 `TextRecord` 上留了 `Offset` 欄位,
`TestCodexAnswersAreTheEightVirtuePassages` 就是拿它逐筆比對。

同一個緩衝區也解釋了聖壇那邊看似寫死的幾個指標:

| 符號 | 記錄 | 內容 |
|---|---|---|
| `byte_54A6D` | 28 | 「……汝跪倒在聖壇之前。」 |
| `dword_54A98` | 29 | 「汝欲冥想何種美德?」 |
| `byte_54AE1` | 31 | 「聖壇開口,一項試煉就此降下!」 |
| `byte_54BB9` | 36 | 「做得好!」 |
| `byte_54BE5` | 37 | 「書已翻至汝所尋的那一頁!」 |
| `byte_54C15` | 38 | 「汝在那神聖的一頁上讀到:」 |
| `word_54C3E` | 39 | 「汝是怎麼來到這裡的?」 |
| `byte_54C55` | 40 | 「一陣異風翻動了書頁!」 |
| `byte_54C7F`…`dword_54D80` | 41–44 | 四段符文 |
| `word_54DAE` | 45 | 「汝走近那座靜謐的聖壇……」 |
| `byte_54DDB` | 46 | 「終極智慧之寶典就在汝眼前……」 |

四段符文用的是符文字母的 ASCII 代換:`[`=TH、`^`=EA、`]`=NG、`_`=ST、
`@`=空白、`o`=句號。內容正是主線提示 —— **要用 `VERAMOCOR` 打開末日之門**。

## 4. 進場函式 `sub_1DA10`:聖壇與寶典是同一間石室

```c
var_4 = 腳下的地形;                    // 0x11 = 法典聖壇,0x19 = 八德聖壇
sub_3181C(4);                          // 換 4 號曲
byte_55FE9 = byte_3E0A3;               // 記住原本的地點
byte_3E0A3 = 0xFF;                     // 進「石室」
備份 32 個地圖物件並清空;
sub_2C740("MISCMAPS.DAT", 地圖, 0xB0, var_4 == 0x11 ? 0x160 : 0xB0);
sub_2C740("MISCMSG.DAT", byte_54700, 0x7D0, 0x3AB);
…把 11×11 搬進 32 格寬的緩衝、走進去的動畫…
puts(var_4 == 0x11 ? #46 : #45);
var_4 == 0x11 ? sub_1D850() : sub_1D394();
…走出來的動畫、還原物件與地點…
sub_29304(0x10);                       // ★ 走掉 16 分鐘
sub_3181C(1);                          // 換回原本的曲子
```

三件事值得記下來:

**分派看的是地形,不是座標。** `sub_2D72C` 依腳下 tile 決定進哪裡
(17 = 法典聖壇、25 = 八德聖壇),所以引擎的 `Enter()` 也改成判地形。
⚠ 這樣改之後**幽冥界的靈性聖壇才會動** —— 它的座標不在 `u5data.Shrines` 表上,
那一筆的 (0,0) 是 `ShrineAt` 的 fallback、不是位置。用座標判就永遠踩不到它。

**進出要花 16 分鐘**(`sub_29304(0x10)`)。聖壇與寶典共用同一支,所以兩邊一樣。
少了它,拜壇與讀寶典都是免費的,而 NPC 排程、月相、光源全都吃這個時鐘。

**石室的地圖在 `MISCMAPS.DAT`** —— 11×11,聖壇用位移 0xB0、寶典用 0x160。
引擎目前**沒有畫這間石室**(直接在原地跑對話流程),這是一處已知的簡化;
規則對了,呈現還沒到。要補的話素材與位移都在這裡。

## 5. 「urn」那一段(尚未實作)

`sub_1DA10` 進場前會數名冊 1..15 裡 `byte_3DDD3[i*32] == 0x7F` 的人
(角色紀錄位移 31),數量 > 0 時呼叫 `sub_1D340(n)`;在寶典那一側還會印
「Thou dost see an urn marked: <名字>」。`sub_1D340` 與位移 31 的語意還沒追,
先原樣留著不動 —— 存檔那一格由 `Character.Raw` 保留。

## 6. 引擎的實作

- `u5data.CodexAnswerRecord(v) = 20 + v`;`MsgCodex*` 一組記錄序號
- `u5data.TileCodex = 0x11`、`ShrineChamberMinutes = 16`
- `game.Codex` / `ReadCodex` / `AdvanceCodex` / `EndCodex`(`PromptCodex`,一頁一鍵)
- `game.State.Enter()` 改為**依地形**分派聖壇與寶典
- `shrineResolve` **不再**設 `ShrineQuestGiven` —— 那是寶典的事
- `u5dump` 腳本動作 `R` 讀寶典,`.` 翻頁(與開場動畫共用)
