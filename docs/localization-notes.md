# 中文化技術筆記

> 決策與量測記錄。規則在 `CLAUDE.md §5`,格式事實在 `docs/formats/`。

## 1. 字形來源:倚天中文系統(ETEN 3.53)

使用者指定 2026-08-07:字形用倚天,不用 TTF rasterize。理由是 1990s DOS 中文遊戲的中文
就長這樣 —— 倚天的 16×15 / 24×24 是為該尺寸手工調的點陣,TTF 縮到這個大小會糊、
筆劃比例也不對。

### 1.1 字庫來源與缺件

`/home/anr2/cht/etan_font/` 有 `stdfont.15`(392,820 B = 13,094 字)與 `ascfont.15`,
**但沒有 `spcfont.15`** —— 那是全形標點(408 字)。缺它的後果是畫面上「字是倚天、
標點是另一套字型」,很突兀。

解法:同目錄的 `ET353S.iso`(倚天 3.53 光碟)裡有完整字庫,
`tools/build_eten_font.py` 會用 `7z e -r` 自動抽:

| 檔案 | ISO 內位置 | 內容 |
|---|---|---|
| `SPCFONT.15` | `DISKS/DISK1/` | 全形符號 408 字 |
| `SPCFSUPP.15` | `DISKS/DISK1/` | 符號補充 365 字 |
| `STDFONT.15` | `DISKS/DISK2/` | 漢字 13,094 字 |
| `STD.24M/K/L/R/B/S` | `DISKS/DISK4–6/` | 24 點六種字體(ETUNPACK 壓縮) |

⚠ `-r` 是必要的(字庫在 `DISKS/DISK*/` 子目錄,不加就匹配不到)。
⚠ 缺 `SPCFONT` 時工具**直接報錯不繼續**,不是印警告 —— 這種錯要在烘字階段擋掉,
不能等到畫面上看到怪標點才發現。

### 1.2 Big5 分區索引的驗證 oracle

倚天的索引不是線性的(符號區 / 常用字 / 次常用字三段)。**oracle 已於 2026-08-07 通過**,
改動索引邏輯後要重跑(`tools/dev.sh font 15` 會自動驗):

| 檢查 | 結果 |
|---|---|
| `STDFONT` 第 0 個字 = 「一」(單橫線) | ✅ |
| 「中」`A4A4` → std idx 66 | ✅ |
| 「猴」`B555` → std idx 2690 | ✅ |
| 「。」`A143` → **spc** idx 3 | ✅ 同時驗證分區公式與 SPCFONT 確實載入 |

### 1.3 烘出的 atlas

`tools/dev.sh font 15` → `assets/fonts/eten-15.{png,json}`:
**13,461 字**、2048×1590 單色 PNG(300 KB)、128 字/列。
`codepoints[i]` 就是第 i 格的 Unicode 碼點。

半角 `,` `!` `?` 不在 atlas 裡 —— 那是**正確的**:ASCII 走原版 `IBM.CH` 的 8×8 字型,
只有 ≥ 0x80 才查倚天(見 §2)。

**atlas 衍生自 1993 年的商業字庫,不入 git**;開發者各自從自備字庫重跑。

## 2. 混排:ASCII 8×8 + CJK 16×15

| 類別 | 字型 | 寬度 | 來源 |
|---|---|---|---|
| ASCII(< 0x80) | 原版 `IBM.CH` | 8 px | 遊戲原本的字 |
| CJK(≥ 0x80) | 倚天 `STDFONT.15` + `SPCFONT.15` | 16 px | 外加(原版沒有 CJK) |

CJK 寬度剛好是 ASCII 的兩倍 —— 混排時欄位對得齊,「幾格寬」的算術也保持整數。
行高 16 px;15 px 高的字模在行內垂直居中(offset 0 或 1),8 px 的 ASCII 也居中。

### 2.1 [HARD] 量測與繪製同一個 gate

度量與斷行抽成 **`internal/textlayout`**(純邏輯、不依賴 ebiten),
`internal/render` 只 re-export、**不自己另算**。

為什麼要這樣分:
1. 量測與繪製若不同步,`Wrap` 算出的斷行與實際畫出來的不同 → 文字溢出訊息框,
   **而症狀看起來完全像「譯文太長」**,會往錯的方向修(這個坑 kb 記過)。
2. ebiten 的 `init` 需要顯示環境,綁在一起的話這些純邏輯就沒辦法在無 GL 環境測試。

property test 固定住核心性質:**對任意樣本與任意上限,`Wrap` 出來的每一行 `Width` 都 ≤ 上限**
(樣本含純中文、純英文、中英混排、100 個重複字、空字串)。

### 2.2 缺字處理

`cjk.Font.Glyph` 找不到字時回 `false`,繪製層畫**紅色空框**而不是靜默跳過 ——
畫面上看得見才會有人去修。`MissingRunes()` 可批次檢查譯文,且**不把 ASCII 算成缺字**。

缺字數量是品質指標:Big5 沒有的字(簡體、罕用字)才該落到 fallback。
若一大批字掉進來,先懷疑索引公式或漏帶 `SPCFONT`,不要無腦補字型。

## 3. 畫布與字級

邏輯畫布 **640×400**(原版 320×200 的乾淨 2×),底圖 tile 用 **2× nearest** 放大成 32 px。
地圖視窗 11×11 tile = 352×352 px,佔畫面比例與原版一致,而中文有空間用正常字級 ——
這就是 `rulebook/81`「拉畫布別縮字」。

### 3.1 16×15 還是 24×24:目前選 16×15

`CLAUDE.md §5.1` 原本預設 24×24(與原版視覺同大但細節 2×),實作時改用 **16×15**,理由:

- 640 px 寬下,16 px 的中文 = 40 字/行;24 px = 26 字/行。
- U5 的訊息欄與右側狀態欄都窄(狀態欄寬 640 − 8 − 352 − 8 = 272 px),
  24×24 只放得下 11 個中文字,狀態列標籤(如「座標 123,456」)會排不進去。
- 16×15 是倚天原生手工點陣,銳利;而 24 點要先解 ETUNPACK 壓縮才有。

⬜ **待做**:烘 24×24 版本(需先解 `STD.24M`),做成執行期可切,讓玩家自己選。
`STD.24L`(隸書)在 ISO 上資料本身是壞的,實務用 `STD.24M`(明體)。
