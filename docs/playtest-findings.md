# 並排驗收:第一輪的發現(2026-08-09)

> 對照點定義在 `docs/playtest-checkpoints.md`;原版由 `tools/dosbox_play.sh` 驅動,
> 重製版由 `u5dump scene --script` 驅動(**不用任何除錯旗標**)。
> 兩邊讀同一份 `SAVED.GAM`(139 年 4 月 5 日 08:35、尤洛小屋 15,15、隊伍 3 人)。

這是本專案第一次真的把原版跑起來並排比。`CLAUDE.md §6.1` 的驗收門檻
(「對 reference 實測」)在此之前**從來沒跑過** —— 所以下面幾條全部是
「靜態讀碼與測試都綠、但畫面不對」的東西。

## 0. 一句話總結

七個對照點裡,**A1–A3 兩邊逐格對過、A5 兩邊都走通了**;
過程中抓到 **六條差異**,其中**四條已修**、一條是決策問題(HUD 欄位)、
一條是 GUI 受阻。最有價值的一條是調色盤:**靜態推導對了「載入什麼」,卻錯在「生效什麼」。**

## 1. ★★ 色號 6:表寫暗黃,畫面是棕 —— 每一張畫面都偏色

| | 值 | 來源 |
|---|---|---|
| `DATA.OVL` 0x52EE 表的第 7 個值 | `0x06` → **#AAAA00 暗黃** | 靜態:驅動程式算 `BX+0x24` 餵給 `int 10h` AH=10h/AL=02h |
| 原版畫面實測 | **#AA5500 棕** | 小屋內部 4,184 px、大地圖森林 420 px |

**控制組**:換成 `machine=vgaonly` 再跑一次(不同的顯示卡模擬路徑)仍是 #AA5500
⇒ 不是模擬器的 EGA 怪癖。

十六格裡**只有第 7 格**與 EGA 預設不同,而那一格顯示的正好是預設值
⇒ **那張表沒有活到遊戲畫面**。最可能的機制:之後又設了一次顯示模式,
而 `int 10h` 設模式會把調色盤暫存器重設回預設。
⬜ 具體是哪一次 mode set 沒追(要逆 16-bit 的 DOS `.OVL`)。

色號 6 佔 tileset 的 **7.70%**(木地板、門、桌椅、箱子、泥土)⇒ 每一張畫面都偏色。

**已修**:`EGAPalette[6]` 改成棕;`ParseEGAPaletteTable` 照舊解表(資料事實);
測試把兩者都釘住並寫明為什麼不同。

> ⇒ 教訓寫成規則:**靜態追到「驅動程式載了什麼」就停,是把「載入」當成「生效」。**
> 中間還有一段執行期,而那一段只有 reference 看得到。

## 2. ★★ 每走一步都要印方向名

原版走三步的訊息欄:

```
>South          >South          >South          >Open-South     Opened!
```

引擎走三步 **一句話都不印**,只有撞牆才印「去路受阻!」。

⇒ 全檔掃描方向字串的引用點,九支函式引用 `North/South/East/West`,其中三支是移動時印:

| 函式 | 位置 | 條件 |
|---|---|---|
| `sub_86C` | 場景移動(由 `sub_1A54` 呼叫)| **無條件** |
| `sub_2D174` | 大地圖移動(由 `sub_2D9D0` 呼叫)| `byte_3E167 == 0` —— 那是**帆船的航向** |
| `sub_15F18` | 戰鬥移動(由 `sub_A360` 呼叫)| 無條件 |

**已修**(`internal/game/moveecho.go`):三條路都印,揚帆的船不印(船印的是轉向)。
⚠ 印在**移動判定之前** —— 撞牆時讀起來是「西」→「去路受阻!」。

## 3. ★★ 隊伍在地圖中央畫的是白框,不是聖者

原版中央是聖者的小人,站在城鎮 tile 上時**小人蓋住那格地形**。
引擎原本畫一個白色空心框(程式碼裡標著 `TODO(P3):索引要從反編譯碼確認,不猜`)。

⇒ 索引公式其實早就在手上:**載具欄位 `byte_3E08C` 本身就是 tile 碼**
(步行 0x1C、騎馬 0x12/0x13、揚帆 0x20..0x23、收帆 0x24..0x27),
而生物 / 載具那一頁是 `NPCTileBase + 碼` —— 地牢那條路一直都這樣畫。
「隊伍長什麼樣」與「在什麼上面移動」在原版是同一個位元組。

**已修**:中央畫 `NPCTileBase + Transport`,白框刪掉。
並排取色後兩邊的森林與小人像素一致。

## 4. 「無風風」—— 風向印了兩個「風」

`WindNameZH` 是「無風 / 北風 / 南風 / 東風 / 西風」,而顯示層又接了一個「風」。
**已修**,並補了不變式測試(`風名自己就帶「風」字`)。

⚠ 順帶記錄:**原版的風向欄位不是決定性的** —— 同一份存檔、同樣的按鍵,
重跑觀察到 `West / North / South / East / Calm Winds` 都出現過(疑似用開機時鐘當種子)。
⇒ **這一格不能逐位元組對照**,兩邊風向不同不算 finding。

## 5. 兩邊都走不出尤洛小屋 —— 其實是**驅動腳本少一個鍵**

第一輪兩個 tester 都卡在小屋裡(原版試了 `x` / `e` / `k` 與四面牆;
重製版在 (15,19) 得到「去路受阻!」)。

答案是 **`O)pen`**:小屋南牆只有一扇門,門要先開。原版按 `o` + 下 →
`Open-South / Opened!`,然後就走得出去。**引擎的 `openToward` 一直都在**,
缺的是 `u5dump scene --script` 沒有這個鍵。

**已修**:腳本加 `O<方向>`。之後重製版走
`sss` `O` + `s`×16 + `y` → **大地圖 (45,62)**,與地點表寫的世界座標一致;
原版同一條路走完印 `Dost thou wish to leave? Yes` / `Exit to Britannia!`,
重製版印「汝欲離去否?(Y/N)」/「前往不列顛尼亞!」。⇒ **這一段兩邊一致。**

> ⇒ 教訓:**兩邊同時卡住,先懷疑對照點的設計,不是引擎。**
> 「兩個獨立的 tester 得到同一個結論」聽起來像強證據,但它們共用同一份
> 對照點清單 —— 清單漏一個鍵,兩邊就一起漏。

## 6. ⬜ 決策問題:HUD 欄位比原版多,而且少了狀態字母

| 欄位 | 原版 | 重製版 |
|---|---|---|
| 隊伍列 | `Elwood 60G`(HP + **狀態字母**)| `Elwood 聖者 60/60`(職業 + HP/上限)|
| 糧 / 金 | `F:63  G:150` | `糧:63  G:150` |
| 日期 | `4-5-139` | `139 年 4 月 5 日` |
| 時間 | **畫面上沒有** | `08:35` |
| 風向 | 地圖窗下緣 `West Winds` | 面板,接在日期後面 |
| 座標 / 地形碼 / 居民數 / 業報 | **都沒有** | **都有** |

⇒ **這不是 bug,是要決定的事**:多出來的四個欄位在開發期很好用,
但它們不是原版的畫面。狀態字母(`G` 良好 / `P` 中毒 / `S` 睡著 / `D` 死亡)
反而是原版有、重製版沒有的 —— 那是**玩家真的要看的資訊**。
時間欄位原版靠 `Ztats` 之外的地方看不到。

**未動**,等使用者決定要不要收斂成原版版面。

## 7. ⬜ 受阻:GUI 沒驗起來

`build/u5cht` 在 xvfb + 軟體 GL 下跑 90 秒逾時被 KILL,期間零輸出 ——
與 `CLAUDE.md §3.1` 記的已知死鎖一致。**只試一次就停手**(那條規則是用五小時換的)。

⇒ 所以本輪驗到的是**繪製層與規則層**(它們與 GUI 共用同一條 CPU 繪製路徑),
**沒有**驗到 ebiten 的紋理上傳、視窗縮放、鍵盤事件。那一層仍然是未知。

## 8. harness 的兩條實測事實(已寫進 `tools/dosbox_play.sh` 檔頭)

1. **`xdotool` 不能帶 `--window`** —— 帶了走 `XSendEvent`,SDL 檢查 `send_event`
   旗標**直接丟掉**。症狀是「腳本跑完、每張截圖都一樣」,看起來像遊戲卡住。
2. **主選單選 Journey Onward 的鍵是 `KP_Enter`**(`Return`/`space`/`j` 都沒反應
   而且毫無回饋)。⚠ 開場動畫結束的時機不穩定,實務上在 `KP_Enter` 之前
   多按一次 `space` 比較穩(DOS 側 tester 實測)。
